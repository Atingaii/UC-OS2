# 入门与接手指南

## 这个项目为什么存在

根据交接说明，前人曾对旧版 uC/OS-II 的部分功能开展形式化验证。这个项目希望复用通用框架，在 Coq 8.18 中完成固定配置的新版本源码级验证，而不是只升级工具或修改版本号。

当前工程处于基础重建阶段。后期工作提示词与实物不一致，先核对是否存在更新的配套工程，再决定从哪里续做。

## 接手者的工作

交付目标是可复现的验证成果，包括：准确源码与配置、修复及反例证据、完整函数清单、逐函数证明、初始化和程序级连接、最终假设审计。

你不必先读完全部论文，但必须能区分：

- C 测试：运行具体场景，观察结果。
- 模型证明：证明 Coq 中定义的操作满足某个性质。
- 源码级证明：证明形式化操作对应真实 C 函数，并满足规格。
- 整体证明：各函数、共享状态、初始化和边界连接到同一个程序。

前三者中的局部成果，不能自动代替后续层次。

## 学习顺序

1. C 基础：指针、结构体、链表、位运算、条件编译。
2. 内核基础：任务、TCB、优先级、调度、就绪、等待、挂起、互斥锁、中断。
3. Coq 基础：类型、定义、命题、定理与证明。
4. 函数规格：前置条件规定允许的起点，后置条件规定结束后的结果；不变量约束可达状态。
5. 小模型：从 `certiucos/v293/model/V293PendModel.v` 开始。
6. 一个真实函数的纵向切片：源码定位、程序表示、规格、局部证明和上层连接。

接着阅读 [第一阶段教学](阶段/01-Coq818与基础检查.md)，按实际命令认识环境、编译与检查，不需要先读完全部框架。

## 第一个例子：任务状态

`V293PendState` 是简化状态，不是完整内核 TCB：

| 字段 | 含义 |
| --- | --- |
| `v293_waiting` | 是否仍等待事件 |
| `v293_suspended` | 是否被显式挂起 |
| `v293_ready` | 是否具备运行资格，不等于正在运行 |
| `v293_pend_result` | 等待结果：成功、超时或中止 |

等待与挂起是两回事。一个同时等待且挂起的任务，经历超时和恢复时，在当前模型中的变化为：

| 阶段 | waiting | suspended | ready | 等待结果 |
| --- | --- | --- | --- | --- |
| 正在等待，同时挂起 | true | true | false | 此处不指定初值 |
| 发生超时 | false | true | false | Timeout |
| 解除挂起 | false | false | true | Timeout |

模型中的超时操作清除等待，但不解除挂起；恢复操作解除挂起，但不替代事件到达或超时，也不抹掉等待结果。

## 第一个证明

文件中的定理 `V293_timeout_clears_waiting` 陈述：对任意模型状态，超时后的 `waiting` 为 `false`。

```coq
forall s, v293_waiting (V293_tick_timeout s) = false
```

读法：先对 `s` 执行超时，再取出新状态的等待字段。由于超时定义直接把这个字段设为 `false`，展开计算后就是 `false = false`。

`intros` 引入任意输入；`reflexivity` 检查定义计算后的相等；`Qed` 结束并检查证明。这里证明的是定义的性质，不是实际 C 内核已经满足该性质。

## 工程推进顺序

按照 `ROADMAP.md` 完成各阶段：确认交接版本 → 准备目标环境 → 校验源码与配置 → 生成函数清单 → 集成并冻结修复 → 建立不变量 → 逐函数证明 → 程序级连接 → 最终审计。
