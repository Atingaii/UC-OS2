# 开发中：让真实调度前缀接上递增与切换

这是 stage25 之后的局部开发记录，不是完整函数或整核验收报告。此前数组借还与关闭入口的基础见[前缀记录](调度前缀共享数组连接.md)。旧正式函数证据和覆盖计数不改写。

## 先理解本轮解决的问题

原来分别有“前缀能执行”和“尾部能切换”的证明，但两者持有的内存布局不同。**两个局部定理分别成立，不等于能顺序执行**。

这次固定同一个物理单元列表，贯穿下面整个片段：

```c
OS_SchedNew();
OSTCBHighRdy = OSTCBPrioTbl[OSPrioHighRdy];
OSCtxSwCtr++;
/* 接框架 ordinary switch target 规则；不是已证明 OSCtxSw 的源码对应 */
```

这里没有优先级 `if`。它只证明无条件执行上述片段时的资源交接；不能把它冒充真正函数的所有分支。

## 三段如何接起来

实现：

- `certiucos/v293/proofs/V293OSSchedStorageConnect.v`
- 主接口：`V293_OSSched_storage_prefix_increment_switch`

同一个 `prefix_cells` 包含 256 项未映射查表、2 项就绪行、组字节、最高就绪字节、完整优先级指针表、**完整 UINT32 计数器单元**及参数化额外存储。

| 阶段 | 资源及值的要求 | 交给下一段什么 |
| --- | --- | --- |
| 关闭前缀入口 | 不变量与同状态精确观察同时成立；绑定可供实际表达式读取 | 借出完整数组，拆成读权限并保留另一半 |
| 真实调用／赋值 | 用旧调用规则执行，重新合并读权限 | 已选最高就绪任务，完整数组和目标指针已归还 |
| 打开本次 snapshot | 保持同一全局状态，不复制独占内存 | 抽象任务表、真实完整数组和某个实际计数器值 `c` |
| 实际递增 | 唯一可写计数器，使用真实赋值 AST | 中间后置明确为 `Int.add c Int.one`，包括模溢出语义 |
| 普通切换 | 用当前任务存在性和最高就绪关系建立 `SWPRE_NDEAD`；全部物理存储归还 | 消耗 `sched`，恢复后只保留共享不变量、当前任务半权限、栈和局部绑定／frame |

恢复后的后置**不保留切换前的数组、目标、任务表或计数器的精确值**。其他任务运行后这些共享状态可能改变。跨切换保留的是不变量，不是旧值。

`V293_storage_observation_flags` 只把不变量已保证的中断标志重建为空内存观察；它不复制共享任务表或物理数组。snapshot 使用同一状态上的普通合取，而非分离合取来重复拥有内存。

### 一个有意保留的边界

前缀旧接口对参数化额外单元只记住“存在一个类型正确的值”，没有记住最初值。因而这里打开计数器时得到的是当前真实的某个 `c`，再精确证明从它到 `c+1`；没有错误地声称最初任意指定值自动一直保留。

这也是下一步接优先级比较要解决的问题：不能从普通有类型存储凭空恢复指定的 `OSPrioCur` 值，必须保留准确观察或建立相应不变量关系。

后续已通过可保留的准确剩余资源接上物理比较求值，见[准确优先级与比较](共享优先级准确值与比较.md)。那项推进仍未把优先级、计数器及所有条件分支合并成一个完整入口；本节无条件片段的历史范围不变。

## 新入口见证：真的有这样的状态

实现：`V293OSSchedStorageConnectWitness.v`。

`V293_storage_connected_entry_witness` 在同一个状态中实际构造：

- 前缀已有的全部物理数组、current／target 指针及唯一抽象槽位；
- 新的独立块 `12`，以 UINT32 编码保存任意 `c`，变量 `108` 绑定到该块；
- 计数器属于同一个共享存储列表，不混进私有 frame；
- 任意事件表、时间、`sched;;aop`，两种当前任务模式；
- 同状态另一项观察独立确认计数器确实保存 `c`，不是随便满足“存在某个值”。

两种模式仍是：当前任务就绪且最高，以及当前任务优先级 4、时间等待、另一优先级 12 任务就绪。夹具名字 `idle_tid` 不表示真实空闲任务可阻塞。这个无条件片段的见证不表示真实优先级条件在两种模式下都走切换分支。

为复用真实数组构造，只把旧前缀物理辅助引理泛化到任意全局环境，仍显式要求 current 和 target 的两条准确查找。旧关闭前缀见证的接口不变；它的原局部门禁另外重跑。

见证的私有 frame 和栈为空，额外单元只加入独立计数器。它证明这个明确布局的**空间入口非空**，不证明任意重叠布局可满足，也不构造完整 `Spec` 函数环境、启动可达轨迹或物理 TCB／ECB 关系。

## 复核时重点排除的误判

- **弱最终后置掩盖丢失递增？** 因为切换恢复后本就不冻结计数器，单检查主根不足；额外固定精确递增根并对其运行省略递增控制。
- **从关闭不变量凭空拿准确数组？** 打开接口使用明确的同状态 snapshot；物理投影负控保留抽象关系而忘掉物理观察。没有声称任意裸不变量都可打开为指定数组。
- **把共享数组藏在私有 frame 跨切换？** 独立后置和 locals 布局固定：locals 只有环境绑定及外部 `px`，本轮数组和计数器全部归还同一 `cells`。
- **前置不可满足？** 新见证构造真实编码字节、内存不相交和抽象槽位，但不据此声称完整函数环境或初始化可达。
- **缓存或旧报告当成全量验收？** 新局部门禁明确使用预构建依赖及 `coqchk`，不是全部活动文件的隔离干净重建；正式身份门保持拒绝。
