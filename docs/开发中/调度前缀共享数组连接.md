本页记录 stage25 之后的局部开发。它不是新的全工程验收报告，也不替代 `audit/function-evidence-stage25.json`。后者是旧提交的证据，不覆盖增加了本页所述 Coq 文件的当前工作树。

后续已把此前缀接上同布局的计数器递增和普通切换，另补含计数器的入口见证，见[最新连接记录](调度前缀到切换的物理连接.md)。下文保留此前缀检查点的范围和当时验收记录，不把历史运行改记为新树验收。

## 这一步解决什么问题

可以把内存权限理解为“操作这块内存的凭证”：

- 完整权限允许写；
- 完整权限可以拆成两半只读权限，供不同证明片段分别使用；
- 想把内存归还要求完整权限的共享不变量，必须把两半都拿回来。

原调度前缀只要求一半只读权限，读取 `OSUnMapTbl`、`OSRdyTbl`、`OSRdyGrp` 和优先级指针表。上一阶段的 `V293_storage_inv` 要求完整权限。因此，不能简单地把两个定理的名字接起来：另一半权限必须真实存在、保留并重新合并，不能凭空生成。

## 新代码做了什么

代码：`certiucos/v293/proofs/V293OSSchedStoragePrefix.v`。

1. 给连续内存数组定义带显式权限的断言，证明完整权限拆为两半、两半合为完整权限。
2. 将原来的字节读取和指针读取断言接到这个表示，不改变旧定义。
3. 在同一个 `V293_storage_inv` 作为外层不变量的规则环境下，真正应用原有调用规则与赋值规则：
   ```c
   OS_SchedNew();
   OSTCBHighRdy = OSTCBPrioTbl[OSPrioHighRdy];
   ```
4. 读取期间保留另一半；返回后合并两半，将完整输入数组、最高就绪优先级单元和额外物理存储归还共享核心。目标指针同样归还。
5. 通过同状态的合取 snapshot 观察本次结果，不把同一块独占内存复制成两份。

原已打开入口定理是 `V293_OSSched_storage_prefix`；新增关闭前缀入口定理为 `V293_OSSched_storage_closed_prefix`。后者先用 `V293_storage_prefix_lend` 借出资源，再执行相同程序。两者都没有“假设后半段正确”的参数，没有修改冻结的 C、配置、框架或策略。

### 本轮新增：关闭入口不是空洞前提

入口同时要求两件事成立：

1. `SWINV (V293_storage_inv ...)` 已关闭；
2. **同一状态**中，数组的内容、当前任务、抽象任务表和目标单元满足精确观察。

两者通过普通逻辑合取组合，不是分别占有两份完整内存。执行证明实际投影第二项借出资源；没有声称从任意裸 `SWINV` 就能推出指定数组内容。

`V293OSSchedStoragePrefixWitness.v` 显式构造每个单元的编码字节并证明内存不相交，随后构造全部抽象槽位。主根 `V293_storage_closed_prefix_entry_witness` 证明这些资源、环境绑定和入口观察可在**同一个状态**中成立：

| 项目 | 本轮见证 |
| --- | --- |
| 未映射查表 | 256 项、完整权限 |
| 就绪位图 | `[0;16]`，组值为 2，选择优先级 12 |
| 优先级指针表 | 完整权限；每项显式类型正确 |
| 当前模式一 | 当前任务就绪，也是最高就绪任务 |
| 当前模式二 | 当前任务优先级 4、处于时间等待；另一优先级 12 任务就绪 |
| 物理 current 与抽象 current | 都是 `V293_idle_tid`，完整指针拆成两半供入口使用 |
| 初始目标 | 有类型的 `Vptr V293_idle_tid`，不是不满足共享目标要求的空指针 |
| 初始输出字节 | 0；执行后由真实查表覆盖 |
| 事件表、时间、continuation | 任意参数，不固定成空表／零值 |
| 额外物理单元、私有 frame、栈 | 分别实例化为 `nil`、`Aemp`、空栈 |

这里的名字 `idle_tid` 只是沿用夹具标识，模式二不是对真实空闲任务阻塞行为的可达性声明。任意事件表参数也不意味着已经建立物理 ECB 与事件关系。

见证只证明明确实例下的入口非空；参数化主定理允许其他资源布局，不代表所有重叠地址实例都可满足。它还没有构造整个函数环境、从启动过程到达的轨迹或完整函数入口。

## 哪些条件仍然开放

- **新增入口只是前缀的关闭入口**，额外带精确同状态观察；不是完整 `OS_Sched` 入口或初始化可达性证明。
- 两种明确实例已具备完整前缀入口见证，但额外单元列表与栈为空；不推广为任意布局可满足。
- 显式要求指针数组的每一项类型正确。旧的“任务属于优先级表”关系只约束已登记任务，不能保证其他数组项的类型。
- snapshot 只在这段尚未切换的代码结束处观察值，不能据此冻结其他线程运行后的共享值。
- 新前缀尚未与比较、计数器递增、真正切换、两层 guard 和临界区连接为完整函数。
- 物理 TCB／ECB 与抽象任务表的关系、`OSCtxSw`／`OSPrioCur` 对应、完整函数环境及初始化仍开放。

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p test_storage_prefix_local.py -v
```

独立接口：`audit/probes/V293StoragePrefixProbe.v`。其中重新写出入口、物理布局、返回 snapshot 和实际两条语句，不用打印候选定理来生成预期类型。

局部门禁设置四个单因素控制：去掉保留的另一半权限、去掉目标赋值、中和输入数组借出、只把见证中的物理 current 换成另一指针而不改抽象 current／目标。要求拒绝发生在各自指定声明内。每项只改一个因素，未执行的下游义务不计作验证。负控只说明当前证明／接口对变更敏感，不证明所有同类错误都不可能通过，也不证明变更后的规格绝对不可证。
