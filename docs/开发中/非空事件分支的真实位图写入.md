# 下一课：任务仍在等待，只迁移它在事件等待表中的优先级

## 1. 这一步接着什么做

此前已证明：两次优先级表写入 → 读取 TCB 旧坐标 → 根据真实条件决定是否更新 ready 表 → 读取事件指针；事件指针为空的连续路径也已接通。

这次补上事件指针**非空**时的真实字段更新，并将“读事件指针、判非空、更新事件表”接为同一次执行。前面表写／ready 前缀到这个非空片段的整体连接仍未完成。两段分别通过，不等于整段已经通过。

对应冻结 `OSTaskChangePrio` 的第 135–143 行；Multi-Pend 在固定配置中关闭，不把原文件的条件编译分支算作本轮已证明代码。

## 2. 先区分两张表

| 结构 | 回答的问题 | 改等待任务优先级时 |
| --- | --- | --- |
| `OSRdyTbl`／`OSRdyGrp` | 哪些优先级的任务可以运行？ | 原本不 ready，就跳过 ready 更新 |
| `pevent->OSEventTbl`／`OSEventGrp` | 哪些优先级的任务在等这个事件？ | 将等待记录从旧优先级迁移到新优先级 |
| `OSTCBPrioTbl` | 某个优先级对应哪个 TCB？ | 改为新槽指向同一个 TCB |

**改优先级不是收到消息。** 等待消息的任务仍然等待；本段不会因为把等待记录移到新位置就把它唤醒。

两处判断是独立的 `if`，不是 `if ... else ...`：即使 ready 条件为假，后面的事件读取和非空判断仍然执行。

## 3. 按四步读真实代码

```c
pevent = ptcb->OSTCBEventPtr;
if (pevent != (OS_EVENT *)0) {
    pevent->OSEventTbl[y_old] &= (OS_PRIO)~bitx_old;
    if (pevent->OSEventTbl[y_old] == 0u) {
        pevent->OSEventGrp &= (OS_PRIO)~bity_old;
    }
    pevent->OSEventGrp |= bity_new;
    pevent->OSEventTbl[y_new] |= bitx_new;
}
```

1. 清掉旧行中的旧优先级位。
2. **读取刚写出的旧行**；只有整行变为零，才清旧组位。
3. 置新行对应的组位。
4. 置新行中的新优先级位。

同行迁移也必须按这个顺序：先清旧位，最后读修改后的同一行并置新位，不能用入口行覆盖中间结果。

## 4. 填好的执行表

行号为 `prio / 8`，行内位置为 `prio % 8`；本固定片段只涉及两行。下表按十进制写字节。

| 用例 | 旧→新优先级 | 入口低行／高行／Grp | 清旧位后的旧行 | 要清旧组位吗 | 出口低行／高行／Grp |
| --- | --- | --- | --- | --- | --- |
| 跨行 | 8→6 | 0／1／2 | 0 | 是 | 64／0／1 |
| 同行 | 8→10 | 0／1／2 | 0 | 是，随后重新置该组位 | 0／4／2 |
| 旧行还有其他等待者 | 2→6 | 20／0／1 | 16 | 否 | 80／0／1 |
| 保留未操作的高位 | 8→6 | 0／129／2 | 128 | 否 | 64／128／3 |

这些是不同边界用例，不声称每两行都是只改变一个物理字节的消融。每个入口的组位都随行的一致性构造。

四个用例的 ready 低行／高行／Grp **始终保持 16／0／1**。这不是“事件等待表改了，所以 ready 也跟着改”。

## 5. Coq 这次具体检查了什么

- `V293_event_row_eval`：通过真实 `pevent` 解引用／字段／数组索引算地址，不将事件表偷换成全局 ready 表。
- `V293_task_prio_event_then_execution`：从入口行／组读取、三个实际字节的写权限和六局部操作数，构造顺序小步执行及出口读回；并证明只改事件基址加 10..12 范围内的字节。
- `V293_task_prio_event_nonnull_execution`：真实 TCB 事件字段读取 → 四字节目的赋值 → 实际非空判断 → THEN。第二段资源从同一中间内存推出，不让调用者假设后半段已经执行成功。
- `V293_event_body_fixture_entry` 与 `V293_event_nonnull_execution_witness`：在同一入口放齐指针、事件字节、六局部和权限，实际执行后同时观察事件结果、正确的 pevent 指针和保持不变的 ready 表。

实例中事件指针为块 72、基址 5；所以 Grp 位于偏移 15，两行位于 16／17，而不是 0／1。pevent 目的变量的初始值故意指向另一块 71、偏移 3，因此不能靠“目的变量本来就正确”省略真实读取／赋值。
