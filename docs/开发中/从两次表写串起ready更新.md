## 一、先看项目为什么要做这一步

## 二、你现在需要认识的四样东西

| 名称 | 直观理解 | 本片段做什么 |
|---|---|---|
| TCB | 保存一个任务信息的结构体 | 读取旧行号和两个掩码；本步尚不更新其优先级字段 |
| `OSTCBPrioTbl` | “优先级 → TCB 指针”的索引表 | 清旧槽，把同一指针放入新槽 |
| `OSRdyTbl` | 每一位表示某优先级是否就绪 | 任务原来 ready 才搬移其 ready 位 |
| `OSRdyGrp` | 表示哪些 ready 行非空的摘要 | 跟随行变化清旧组位、置新组位 |

“改优先级”不等于“把等待任务变为就绪”。如果原 ready 位为 0，本段不设置新的 ready 位；后面还要按独立事件条件处理等待表。

## 三、按照源码顺序读

冻结配置后函数的第 119–130 行，对应以下顺序：

```c
OSTCBPrioTbl[oldprio] = (OS_TCB *)0;
OSTCBPrioTbl[newprio] = ptcb;
y_old    = ptcb->OSTCBY;
bity_old = ptcb->OSTCBBitY;
bitx_old = ptcb->OSTCBBitX;
if ((OSRdyTbl[y_old] & bitx_old) != 0u) {
    OSRdyTbl[y_old] &= (OS_PRIO)~bitx_old;
    if (OSRdyTbl[y_old] == 0u) {
        OSRdyGrp &= (OS_PRIO)~bity_old;
    }
    OSRdyGrp        |= bity_new;
    OSRdyTbl[y_new] |= bitx_new;
}
```

这里新行号和新掩码由入口提供，旧值则必须真正从 TCB 读取。后面的 `pevent = ptcb->OSTCBEventPtr` 和事件 `if` 不属于这个 ready `if` 的 else。

## 四、把具体执行表直接补好

使用 `8 → 6`：旧优先级在高行第 0 位，新优先级在低行第 6 位。另一个任务位于优先级 4，其 ready 位是低行中的 16。

| 观察项 | 原任务 ready | 原任务时间等待 |
|---|---|---|
| 入口表槽 8 | 目标 TCB 指针 | 同一目标 TCB 指针 |
| 入口表槽 6 | 空指针 | 空指针 |
| 入口低行／高行 | 16 / 1 | 16 / 0 |
| 入口组摘要 | 3（两行非空） | 1（仅低行非空） |
| 两次表写后的槽 8／槽 6 | 空／目标指针 | 空／目标指针 |
| 三次读取得到 `y_old / bity_old / bitx_old` | 1 / 2 / 1 | 1 / 2 / 1 |
| ready 条件 | 真 | 假 |
| 最终低行／高行 | 80 / 0 | 16 / 0 |
| 最终组摘要 | 1 | 1 |
| 最终槽 8／槽 6 | 空／目标指针 | 空／目标指针 |
| 其他 11 个表槽 | 保持 | 保持 |

`80 = 16 + 64`，其中 64 就是优先级 6 的 ready 位。假支也执行了前面的表写和三次读取，只跳过 ready 位图更新，不是整个 API 返回。

两列不是“只动一个字节”的消融：ready 位、由它导出的组摘要、抽象任务状态一起变化。它们是两条一致入口上的路径见证。门禁另外进行四项单头部负控。

## 五、证明里的内存名字是什么意思

```text
入口 M
  → 第一次表写 M1
  → 第二次表写 M2
  → 三次局部赋值 Mr
  → ready 真分支或跳过 Mf
```

稳定接口 `V293_task_prio_prefix_execution` 位于 `certiucos/v293/proofs/V293TaskPrioRekey.v`：

1. 由入口槽位写权限构造两次成功存储，不要求调用者提供成功执行。
2. 证明表块与指针、TCB 字段、局部目的块、位图块分离，故表写不会损坏后续读取。
3. 在同一个 `M2` 执行三次读取和 ready 分支；不能为后半段另找一份有利的内存。
4. 再证明后半段不破坏表块，推出最终 `Mf` 中**全部 13 槽**的读回，不能只检查表写后的 `M2`。

`V293_prefix_combined_witness` 还把完整 13 槽物理读取、两个抽象任务、表／任务对应、位图／ready 对应和真实连续执行放进同一个具体入口。这比先前只有两个表槽的稀疏实例更完整。

但这个入口仍只构造所需 TCB 字段与资源，不是完整 TCB 分配、初始化可达性或整个共享不变量。出口真实 TCB 优先级字段尚未更新，所以也不能声称整个任务不变量已经恢复。
