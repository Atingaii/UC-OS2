# 下一步：区分保留标记与真实任务指针

## 1. 为什么还要判断一次？

上一课从 `OSTCBPrioTbl[oldprio]` 真正读取指针，再排除 `NULL`。但“不是空”不等于“这里有真实任务”：某些优先级被互斥锁预留，表槽里放的是 `OS_TCB_RESERVED`，不是能访问字段的 TCB。

| 表槽内容 | 含义 | 本段决定 |
| --- | --- | --- |
| `NULL` | 没有任务 | 前一判断选中退出临界区、返回错误41的语句 |
| `OS_TCB_RESERVED` | 优先级被预留 | 本次判断选中退出临界区、返回错误67的语句 |
| 真实 TCB 指针 | 找到目标任务 | 继续后面的优先级迁移 |

这里的“选中语句”与“完成退出调用和整个函数返回”不同；后者还没证明。

冻结配置后源码的105–107行是：

```c
if (ptcb == OS_TCB_RESERVED) {
    OS_EXIT_CRITICAL();
    return (OS_ERR_TASK_PRIO);
}
```

错误常量的配置后值为67。固定 C 没有改动。

## 2. 当前工具怎样表达这个特殊指针？

C 中的宏是整数1转为 TCB 指针；现有证明语言不能直接给这个表达式定型，旧边界探针仍保留这一事实。我们没有删除判断，也没有把标记换成 `NULL`。

本次以静态符号的地址表示不可解引用的保留标记：

```coq
ecast (eaddrof (evar reserved)) (Tptr V293_tcb_type)
```

直观理解：给“保留标记”一个独特标签，只用于判断相同／不同。取符号地址不读取内存，不需要预先把期望答案写到某个内存位置。

这仍是手工源码表示边界，不是已验证的 C 翻译器，不声称该符号就是机器地址1。上层必须建立：全局符号绑定一致、局部不遮蔽、真实任务指针不等于标记。所有 API 和初始化也要统一采用这个约定。细节见 [ADR-0004](../adr/0004-保留指针采用显式符号地址.md)。

## 3. 本次证明了什么？

- 对任意内存，静态符号表达式得到同一保留指针。
- `NULL`、保留标记、与标记不同的真实指针，三类的相等比较结果分别正确。
- 实际执行保留条件：相等则进入真实错误语句，不等则跳过该错误分支。
- 从前一课原始入口资源开始，连续执行93–107行的成功路径：新槽空检查 → SELF解析 → 读旧槽并写局部 `ptcb` → 排除空指针 → 排除保留标记。
- 入口不要求局部 `ptcb` 已经正确；出口指针来自真正的表读取。SELF／非SELF两种物理入口均有直接实例，原局部 `ptcb` 都是 `NULL`。

上层使用的稳定接口是 `V293_task_prio_entry_reserved_execution`。它不仅说“能继续”，还保留实际参数、两个表槽、写权限和未写块的内存内容。

## 4. 怎样知道不是把结果偷偷写进前提？

入口只给真实表槽和可写局部资源，不给中间执行结果、成功store或预先正确的局部指针。证明先执行原查表段，再把它实际产生的指针交给新的条件判断。

验收另用六个手写字面接口检查类型；并预先指定四项单因素负控：去掉全局绑定、去掉非冲突条件、把实际程序谎称为 `skip`、把出口指针谎称为 `NULL`。负控保留原证明全文，必须进入指定证明之后才拒绝；拒绝只说明这份原证明对该改动敏感，不说明变更命题在数学上都不可证明。

若中和“真实指针不与标记冲突”，实际比较就会把同值指针判成保留标记。这个值级证据解释了为什么上层必须建立非冲突，而不是证明整个共享状态已合法。

实际验收结果以 `audit/logs/stage26-task-prio-reserved/` 中的当前身份记录和根目录 `VERIFICATION_STATUS.md` 为准。

## 5. 接下来怎么做？

1. 将这段成功入口的出口资源运输到已有坐标计算／表迁移／ready与事件位图／TCB字段写回段，形成同一次连续执行；不能假设后半段已经正确，也不能跳过实际源码语句。
2. 补临界区进入／退出、全部错误调用、`OSRunning` 判断、调度及函数返回。
3. 用同一个共享不变量证明 ISR／各 API 的保持性，建立函数环境和初始化。
4. 最后连接源码级 `GOOD_OS` 和同程序 K1–K4；阶段一真正完成后，再按老师要求启动 uC/OS-III。
