# 把坐标计算接成通用优先级迁移

## 1. 这一步解决什么

上一步已经有两种不同的结果：

- 四条坐标赋值的定理可以接收任意满足范围的 `newprio`。
- 把赋值与后续表、位图、TCB 操作连续执行的见证，仍固定为 `8→6`。

不能因为第一项通用，就把第二项也称为通用。本步新增：

```text
V293_task_prio_coordinates_update_execution
```

它对 `old`、`new`、入口内存及相关地址全称量化，从同一个入口连续执行配置后源码 110–166 行的非空事件路径。不是把若干独立运行的结果拼在一起。

范围是 `old<13`、`new<13`、`old<>new` 以及声明中列明的读取、写权限和充分分离条件。这里的 13 是固定表容量；完整 API 要求的新优先级 `<12` 尚须由真实 guard 建立。

## 2. 为什么不能提前假设坐标正确

真实源码先计算：

| 局部变量 | 计算 | `newprio=6` |
| --- | --- | --- |
| `y_new` | `newprio >> 3` | 0 |
| `x_new` | `newprio & 7` | 6 |
| `bity_new` | `1 << y_new` | 1 |
| `bitx_new` | `1 << x_new` | 64 |

若入口已经要求这四个值正确，就没有证明“计算确实产生了它们”。新接口只要求四个局部绑定、目的字节写权限及必要的隔离，不读取它们的旧值作为正确性前提。

输入的真实 `newprio` 值、旧 TCB 坐标、表内容和位图内容仍必须有相应读取资源；这不是凭空执行任意内存。

## 3. 中间内存如何连接

证明顺序是：

```text
原入口 M
  → 四次实际赋值
中间内存 Mc
  → 两表写、旧字段读取、ready 分支、非空事件迁移、五字段写回
最终内存 Mh
```

关键不是新增一个“假设 Mc 满足后缀”的条件，而是证明它：

1. 四次赋值实际产生 Y／X／BitY／BitX。
2. 四地址外的 byte 和 permission 保持。
3. 根据块隔离，把原入口的表、TCB、ready、事件读取和写权限运输到 `Mc`。
4. 在 `Mc` 构造旧后缀需要的新坐标资源。
5. 调用已证明的通用后缀，并连接实际小步执行。

`CF` 处理原始内存字节／权限，`LF` 处理由这些字节得到的类型化读取。两者都是证明内的结论，不是调用方提供的 oracle。

## 4. 同一个出口检查什么

最终同一个 `Mh` 同时满足：

- 13 槽表更新，旧槽为空、新槽保留原 TCB 指针；
- ready 分支的准确行／组结果；
- 非空事件的准确行／组结果；
- TCB 的 Prio／Y／X／BitY／BitX 五字段；
- `ptcb`、`pevent` 及 TCB 内部 EventPtr；
- TCB 偏移 50–54 之外的字节保持。

全局外部 frame 还必须排除四个新坐标局部块，因为它们本轮确实被写了。该外部 frame 是充分的块级条件，不宣称最细粒度或分离条件最弱。

等待用例仍不会因为修改优先级收到消息：原 ready 假分支保持原 ready 行／组。这里还没有建立完整的等待队列／ready 抽象共享关系，不能把物理位图观察提升为整核不变量。

## 5. 如何排除入口根本不可能满足

新增 `V293_generic_coordinate_update_witness`，直接调用本轮的通用接口，复用上一步四目的字节均为 `255` 的真实物理入口。

它不借用旧连续见证的出口，也不假设“坐标恢复到正确后缀入口”。由新通用接口本身完成计算和迁移。见证仍固定 `8→6`，用来说明通用契约可满足；通用性来自上面的全称定理，不来自增加几个例子。它不证明完整合法共享状态或初始化可达。
