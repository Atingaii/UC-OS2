# 开发中：同一共享布局里的真实调度条件分支

这是 stage25 后的局部推进记录，不是完整 `OS_Sched` 或最终 `GOOD_OS` 验收。此前的[准确优先级与比较](共享优先级准确值与比较.md)只连接了准确字节保留和比较求值；本次把计数器与该字节放进同一个入口，再连接真实条件分支。冻结 C、配置、两项授权补丁、框架和旧正式函数证据不变。

## 初学者先看这一张表

调度器先计算最高就绪优先级，并取出目标任务指针，再判断当前任务是否就是应当继续运行的任务：

| 实际比较 | 具体程序动作 | 证明还必须完成什么 |
| --- | --- | --- |
| 最高就绪优先级不等于当前优先级 | UINT32 计数器模加一，然后普通 `switch` | 数组、优先级字节和计数器归还同一共享不变量；按切换规则恢复 |
| 两者相等 | 不执行上述递增／切换语句 | 根据同一任务表证明当前任务最高就绪，完成抽象自调度，并归还同一份物理存储 |

第二行不是“什么都不证明”。具体机器可以不切换任务，但规格中的 `sched;;aop` 仍需要推进到 `aop`。否则两条分支无法交付同一个后置条件。

计数器的模加一包括最大值回绕。这不表示本入口冻结了计数器初值，更不表示切换出去后其他任务不能修改共享值。

## 代码实际连接到了哪里

修改集中在既有的 `V293OSSchedStorageConnect.v` 和 `V293OSSchedStorageConnectWitness.v`，没有增加新的证明文件。

同一共享单元列表为原前缀数组／高优先级存储，加上：

```text
counter : Tint32 :: current_priority : Tint8 :: rest
```

其中 `counter` 在共享资源里存在量化，`current_priority` 在前缀和比较之前保留准确字节；两者都不作为私有 `px` 资源重复占有。普通合取 `//\\` 只是同一状态的准确观察，不复制独占权限。

| 接口 | 本次用途 |
| --- | --- |
| `V293_storage_priority_reads` | 提取实际字节比较的唯一求值证明体；原比较接口继续复用 |
| `V293_conditional_comparison` | 在包含计数器的同一入口后置上证明字面比较的值与类型 |
| `V293_storage_connected_self_finish` | 不执行具体切换，归还同一份存储并消费抽象自调度 |
| `V293_conditional_equal_finish` | 用当前任务／优先级表关系证明相等分支确实可以自调度 |
| `V293_conditional_change` | 通过真正的 `ift_rule` 证明实际 `if` 语句及递增／切换分支 |
| `V293_OSSched_storage_conditional` | 顺序组合真实调用／目标赋值前缀、实际 `if` 和两分支的统一恢复后置 |

准确字节只保留到最后一次必要的物理比较；之后允许忘成同地址、同类型的共享存储。恢复后置不承诺切换前的优先级或计数器值依然不变。相等分支与不同分支使用同一共享不变量，不切换到另一个更弱布局来完成证明。

这里的普通 `switch` 是框架原语，**不是 `OSCtxSw` 端口源码的实现对应证明**。根定理也不包含两层 guard、临界区包装或完整函数环境。

## 排除“前置永远不成立”的组合入口

`V293_storage_conditional_entry_witness` 构造一个同时包含两个标量块的真实状态：

- 块 `12` 按 UINT8 编码当前优先级，变量 `108` 绑定它；
- 块 `13` 按 UINT32 编码任意计数器 `c`，变量 `109` 绑定它；
- 数组、当前／目标指针、唯一的任务／事件／时间抽象槽位和 `sched;;aop` 都在同一状态里；
- 两种模式分别为当前优先级 12 且就绪，以及当前优先级 4 且时间等待；最高就绪优先级均为 12，分别对应相等／不等分支。

这不是把两个分别存在的状态硬拼成一个状态。计数器的精确值另用同状态观察展示，入口本身仍只要求它是有类型存储；准确优先级则真正保留在入口 snapshot 中。夹具沿用的 `idle_tid` 是标识名字，不表示真实 idle task 可以等待。

见证不是初始化可达性或完整函数环境证明，也没有覆盖所有任务／堆形态。

## 前瞻消融与独立检查

协议先写入 `audit/logs/stage26-conditional/PROTOCOL.txt`。独立探针 `audit/probes/V293StorageConnectProbe.v` 显式写出物理单元、共享布局、前后置和字面 AST，不从候选定理自动生成。现在共检查 12 个根，新增组合比较、自调度、最终组合及组合入口见证。

除保留原五项连接负控外，本次新增四项：

| 单因素变化 | 保持不变 | 指定拒绝声明 |
| --- | --- | --- |
| 只把实际条件分支中的递增改成 `skip` | 比较、普通切换、布局、证明与后置 | `V293_conditional_change` |
| 只把闭合快照的准确 `kept` 忘成有类型存储 | 入口、单元列表、比较与预期结果 | `V293_conditional_comparison` |
| 只中和抽象自调度推演 | 物理归还、其余抽象步骤、前后置 | `V293_storage_connected_self_finish` |
| 只把组合夹具中编码的当前优先级改成 0 | 计数器、断言、任务关系和其他物理资源 | `V293_storage_conditional_entry_witness` |

旧物理字节负控与新组合字节负控限定在各自夹具定义中，避免在旧见证处提前失败。数组归还负控同样限定原声明，不误改新自调度证明中的另一处归还步骤。必须在指定声明内拒绝，不能把任意早期报错算作通过；拒绝之后的机制不获得验证信用。

局部 Python 测试检查变异的范围与单因素性；真正的拒绝结果必须由 Coq 重编检查，不能由字符串测试代替。

### 对这些负控应作多强的解释

这些负控是在固定其余证明脚本和接口时重放，说明当前检查能发现指定步骤／资源被中和；**不等于证明变异后的定理在任何证明方法下都不可证**。尤其统一恢复后置有意忘记共享计数器的旧值，单靠它不能区分“曾经递增后被其他任务改变”和“没有递增”。实际递增由字面 AST 及已有的准确中间值定理 `V293_storage_connected_increment` 证明；组合负控只检查该具体步骤与现有证明链的一致性，不额外宣称它是最终抽象后置的必要条件。

相等／不等两模式见证排除了本夹具下单侧不可满足，但不是一般初始化可达性基线。`coqchk` 检查对象与依赖闭包，不检验 C 到本片段的完整翻译，也不能补足尚未建立的完整物理不变量。
