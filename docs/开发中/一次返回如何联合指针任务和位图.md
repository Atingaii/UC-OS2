# 下一步：一次返回，归还一份联合资源

## 1. 我们在解决什么

老师要求先用固定配置的 uC/OS-II V2.93.01 练熟复杂系统验证流程，再验证 uCOS3。最终目标不是“某个文件编译通过”，而是把真实源码、共享状态、初始化、全部纳入的 API 和中断边界接到源码级 `GOOD_OS`，并闭合相同程序的 K1–K4 回归证明。

目前仍在第一阶段。当前小步处理 `OSTaskChangePrio` 的一个成功更新／返回路径；调度器因 ISR 条件受阻，不包含正常无锁任务切换。

上一轮分别得到了：

- 当前任务指针与所有任务的选定字段联合归还；
- ready/event 六个位图字节联合归还。

但两条定理分别写着 `exists Mf`，不能擅自认定它们的 `Mf` 相同。即使都针对同一个内存，`P ** Atrue` 和 `Q ** Atrue` 也不能直接拼成 `(P ** Q) ** Atrue`：可能重复计算了同一个资源。

## 2. 本次怎么连接

新根 `V293_critical_wait_joint_owned_execution` 的入口条件与旧的当前指针／全部任务根逐字相同，没有把待证的最终所有权加到前提里。

证明只调用一次 `V293_critical_event_return_bitmap_owned`，取得实际执行返回的 `Mf`。随后：

1. 用五次字段写入的模型描述任务记录应如何变化；这不是第二次 API 执行。
2. 用实际返回的字节及权限 frame，把当前指针和全部任务的选定字段搬到这个 `Mf`。
3. 从 `Mf` 中真正分离出“当前指针＋任务字段”的联合片段。
4. 利用已有块支持条件，证明六个位图地址不在这个片段中。因此它们的完整字节权限确实还在剩余内存中。
5. 从剩余内存构造六字节所有权，再连接不占物理内存的抽象 `shared_fields`。

最终归还的是同一内存上的：

```text
(((CurTid current ** all_selected_task_fields) ** six_bitmap_bytes)
 ** updated_shared_fields) ** Atrue
```

`**` 是分离连接，包含实际资源分割；不是普通的逻辑“并且”。`CurTid` 保持框架原有的只读半份额，不因此获得写指针权限。

## 3. 已填好的具体例子

| 对象 | 入口 | 同一次成功返回后 | 是否说明任务 ready |
|---|---|---|---|
| 当前任务指针 | `(60,0)` | 仍为 `(60,0)`，只读半份额保持 | 不是仅靠指针判断 |
| 目标任务 `(41,8)` | 优先级 8，等待 SEM `(72,5)` | 优先级 6，仍等待同一 SEM | **否** |
| 另一任务 `(60,0)` | 优先级 4，ready | 优先级 4，仍 ready，字段所有权保持 | 是 |
| ready 两行／group | `16 / 0 / 1` | `16 / 0 / 1` | 只包含已有 ready 任务 |
| 该 event 两行／group | `0 / 1 / 2` | `64 / 0 / 1` | 是等待队列位图，不是 ready 位图 |
| priority table 旧槽 8 | 指向目标任务 | `NULL` | 不直接决定 ready |
| priority table 新槽 6 | `NULL` | 指向目标任务 | 不直接决定 ready |
| 函数 locals | 已分配 | 返回时释放 | 释放后不能继续写入 |

你的原先理解仍然正确：**修改优先级并没有收到等待的消息／信号，所以目标任务不会立即变成 ready。**

## 4. 如何看验证结果

新 probe `audit/probes/V293JointReturnProbe.v` 从实际入口资源重新开始，不调用旧的完整返回 trace 来替代执行。

它检查同次返回的联合后置条件，并从这份资源读当前指针、分别写两个任务字段、写六个位图中的任意一个字节。额外的 `UnifiedBitmapStorePreservesJoint` 证明：一次位图字节写入后，更新后的空间资源与当前指针、全部任务选定字段、抽象字段仍然联合持有。

这里“仍然持有空间资源”不等于“任意写入后内核逻辑仍正确”。例如随便改 ready 位，可能破坏任务状态与位图一致性。该消费者只证明权限和空间 frame，不证明任意写入保持完整 `Inv`，也不证明各个独立 store 存在量词能随意串成一条执行。

运行本步独立检查：

```bash
COQBIN=/data/home/lucentzhou/.opam/default/bin/ \
PYTHONDONTWRITEBYTECODE=1 python3 -B scripts/check-v293-joint-return.py \
  --output-dir audit/logs/stage26-joint-return/自选的新目录名
```

脚本保留正负控、编译日志、假设检查和独立 `coqchk` 的结果；输出目录必须尚不存在。历史检查绑定旧源码身份，不能改写旧报告来制造当前全绿。
