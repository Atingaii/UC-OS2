# 从原始入口一直执行到返回零

## 先理解这次补的缺口

`OSTaskChangePrio` 的成功路径不是“改完优先级”就结束：它还要退出临界区、根据 `OSRunning` 决定是否调用 `OS_Sched()`，最后返回 `0` 并释放函数的局部变量。

上一检查点分开证明了两件事：原始入口能执行到调度调用结束；如果**另外给出更新后所有局部变量可写**，尾部能够返回。它们不能直接拼接，因为“读到了正确的值”不等于“拥有释放这块内存所需的完整权限”。

本次把权限从入口一路传过去，不再把中间内存可释放作为公共前提。

## 第一步：区分值和权限

模型中的一个字节形如 `(permission, value)`。`load` 能读取的字节，不一定能被 `free` 释放。

新增 `V293_success_load_free_permission_ablation` 固定地址和字节值 `7`，只改变一个布尔权限位：

| 权限位 | `load` | `free Tint8` |
|---|---|---|
| `true` | 读到 `7` | 成功，删除该字节 |
| `false` | 仍读到 `7` | 返回 `None` |

这是机器检查的单因素对照，不是口头解释。

## 第二步：跟踪每一次实际写入

新权限保持关系只表示：入口已有的完整写权限，在更新后仍存在；**不表示字节值不变**。

证明逐项经过：SELF 的选择器赋值、`ptcb` 指针赋值、坐标赋值、任务表的两次 store、旧坐标读取后的局部赋值、ready 位图更新、事件指针赋值、非空事件位图更新，以及 TCB 字段更新。

不能推广为“任意执行都保持权限”：函数返回时恰恰会释放局部变量。这里仅对实际 store 和有限的显式字节更新证明保持性。

## 第三步：真正完成函数片段的返回

两个主接口位于 `certiucos/v293/proofs/V293CriticalReturn.v`：

- `V293_critical_null_success_return_execution`：TCB 的事件指针为 `NULL`。
- `V293_critical_event_success_return_execution`：TCB 关联一个事件。

两者从**同一个原始内存 `M`**出发，执行参数 guard、临界区、SELF/lookup、全部更新、退出临界区、条件调度调用及 `return 0`，最后：

1. 删除当前函数 `getaddr le` 中全部局部变量的字节；
2. 恢复原调用者的局部环境 `caller` 和 continuation；
3. 保持原中断使能值、相关栈与中断记录；
4. 在最终内存 `Mf` 中保留任务表、TCB、ready 位图和非空事件位图的更新结果。

第 4 项要求这些内核对象不是当前函数待释放的局部块。这是入口的资源分离条件；不应该等到函数返回后才假设它们还在。完整局部写权限和局部块不重复，也均要求在原始入口成立。当前分离条件只保护后置中明确观察的内核对象，并未证明任意全局块都与给定 `le` 分离；完整函数入口分配与共享不变量仍要补齐。

## 证明到哪里、没有证明到哪里

| 项目 | 本检查点边界 |
|---|---|
| 原始入口到返回值、释放 locals、恢复 caller | 两条成功片段已连接 |
| 条件调用真实函数定义、分配/释放调度器 locals | 承接上一检查点，实际执行 |
| `OSRunning != 1` | 不调用调度器；函数绑定前提有条件提供 |
| 运行中但 ISR 嵌套非零或调度锁非零 | 调度器真实调用完成，但不执行 unlocked 分支 |
| 无锁且不在 ISR 的实际任务切换 | 未接入这两个返回根 |
| 临界区与原始 port 字节/机器指令对应 | 仍为显式宏抽象，不是硬件证明 |
| 完整函数调用入口的 locals 分配 | 未证明；本根从给定 callee 环境开始 |
| 两根新增全部入口前提的统一物理实例 | 尚无新通过见证；不要把旧更新见证或单字节消融冒充它 |
| 完整共享不变量、初始化、`GOOD_OS`、同程序 K1–K4 | 未完成 |

统一见证的一次探索曾使用无界 `vm_compute`，因资源消耗过高主动中止；日志保留，不计验证成功或负控。接下来应使用有界地址/偏移枚举和既有资源引理，而不是继续扩大计算。

## 下一步如何阅读和继续

1. 先读上述单字节消融定理，理解 `load` 与 `free` 的区别。
2. 读 `V293_storebytes_preserves_writable` 和 `V293_store_writable`：注意覆盖字节的值变了，但完整权限仍在。
3. 在任一个新返回根中找到 `InitialWritable`、`UpdateWritable`、`FinalWritable`，它们就是从入口到释放的证明链。
4. 找到 `HeapApart`、`FreeFrame`、`FinalLoad`，理解为什么返回后全局对象仍可读。
5. 下一轮先给两根所有前提构造同状态完整见证，再接无锁调度分支与同一物理共享不变量；不能仅凭局部路径把正式函数覆盖升为完成。
