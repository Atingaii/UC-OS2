# 从指针读数到共享核心的权限保持

## 这一步在解决什么

上一轮已经把“物理当前任务指针、抽象 current、ready 成员”对应到同一次完整返回。但后续分离逻辑证明还要消费内存资源：仅列出读数，并没有把原来持有的空间断言接回去。

这轮沿用现有 `CurTid` 和 `V293_shared_core`，不另造一个不变量。

| 概念 | 含义 | 本轮处理 |
| --- | --- | --- |
| `load ... = Some (Vptr current)` | 从整体内存观察到一个指针值 | 保留上一轮结论，但不把它当作入口空间所有权 |
| `CurTid current` | `OSTCBCur` 指针单元的读取半份额，包含全局绑定和完整指针编码 | 从入口实际持有的空间片段运输到同一出口 |
| `V293_shared_fields` | 抽象 current、任务表、事件表、时钟四项资源 | 使用既有执行证明产出的更新后资源 |
| `V293_shared_core` | 存在某组 current/tasks/events/now，且持有 `CurTid ** shared_fields` | 用上述两部分重建，不凭空复制资源 |
| 完整内核不变量 | 还需要物理 TCB、ready 位图、优先级表、ECB、资源链等全局对应及保持 | 未完成，不能由共享核心代替 |
| 最终 `GOOD_OS` | 同一固定源码、规格、初始化和 API/ISR 的整体闭合 | 未完成；同程序 K1–K4 也未闭合 |

## 推导顺序

1. **入口确实持有权限**：新执行接口要求 `(CurTid current ** shared_fields ...) ** R`。这比上一轮只要求共享字段更强，不能说两轮的入口完全相同。
2. **只保留该指针片段**：指针的所有编码单元均位于一个块。若执行前后该块每个地址的权限和值都相同，该片段仍是最终内存的子资源。
3. **排除写入和释放**：该块既不在函数的写集合，也不在离开函数时释放的 locals 集合。这是显式前提，不能省略。
4. **沿同一次执行走到返回**：新根只调用一次既有完整执行根；没有重新挑选另一份 `Mf` 或 `OO'`。
5. **合并正交资源**：`CurTid` 不占抽象资源，共享字段不占物理内存，所以可把两者的真实片段组合起来；并不是任意两个空间断言都能这样合并。
6. **封装共享核心**：完整字面例子的最终状态满足现有 `V293_shared_core ** Atrue`。

通用根没有把“current 必须 ready”内置进共享核心；它保留上一轮关于 ready 成员的条件结论。下面的字面例子有该 ready 成员，但并未建立其物理 TCB 与全局链表的完整合法性。

**没有承诺任意 `R` 的物理内容都保持。** 函数会写内存和释放局部变量，不能把整个原物理 frame 原样带到出口。

## 同一个例子的数值

| 观察项 | 入口 | 同一次完整返回 |
| --- | --- | --- |
| 普通选择器 | 8，不是 SELF=255 | 被改任务从优先级 8 到 6 |
| 被改任务 | TCB `(41,8)`，等待 SEM | 仍等待，不变成 ready |
| 当前任务 | 抽象成员 `(60,0)`，优先级 4，ready | 指针、抽象成员、读取权限均保留 |
| 当前指针存储块 | 80，绑定标准符号 `OSTCBCur` | 块不被写或释放；不是“TCB 编号 80” |
| ready 位图 | 16 / 0 | 16 / 0 |
| 等待事件位图 | 0 / 1 | 64 / 0 |
| SEM 头数据 | 类型 3、计数 0、NULL | 保持 |
| 运行／ISR／锁计数 | 1 / 1 / 0 | 调度调用受 ISR 条件阻挡，不是正常无锁切换证明 |
| 函数退出 | 有局部变量 | 返回 0、恢复 caller、释放 locals |

入口的读取半份额由实际编码的四字节内存构造，未使用“已完成的旧 trace”充当新的入口证明。另有语义定理排除最终持有“当前任务等于等待任务 41”的 `CurTid`，以及在空内存上持有 `CurTid`。
