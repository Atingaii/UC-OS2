# 读取事件指针并跳过空事件分支

## 1. 接着上一课往下看

上一课已经执行：清旧优先级槽 → 写新槽 → 读取三个旧坐标 → 按原ready位决定是否搬移ready位。本课继续固定配置的第135–143行。项目仍以整个源码级 `GOOD_OS` 和同程序 K1–K4为目标，局部片段不是整核完成；之后才进入老师要求的uC/OS-III。

```c
pevent = ptcb->OSTCBEventPtr;
if (pevent != (OS_EVENT *)0) {
    pevent->OSEventTbl[y_old] &= (OS_PRIO)~bitx_old;
    if (pevent->OSEventTbl[y_old] == 0u) {
        pevent->OSEventGrp &= (OS_PRIO)~bity_old;
    }
    pevent->OSEventGrp |= bity_new;
    pevent->OSEventTbl[y_new] |= bitx_new;
}
```

这是独立的 `if`，不是ready判断的else。ready位为0并不代表函数结束，也不意味着收到消息或自动就绪。

## 2. 三个指针各是什么

| 名称 | 含义 | 本课中的实际读取位置 |
|---|---|---|
| `ptcb` | 指向目标任务TCB | 局部40中的4字节指针，指向块41、基址8 |
| `ptcb->OSTCBEventPtr` | 任务关联的单个等待事件；没有则为空 | TCB偏移28，因此实例地址为块41、偏移36 |
| `pevent` | 本函数保存刚读出的事件指针的局部变量 | 局部70，写入4字节；初值故意为另一非空指针 |

固定分析配置的event结构：Type在0，EventPtr在4，Cnt在8，Grp在10，两个表字节从11开始，总长16。模型显式包含填充，但本课不证明ABI或编译器。

## 3. 空指针路径也有实际写入

`OSTCBEventPtr == NULL`时，仍然会把NULL写到局部`pevent`，随后计算条件为假，跳过整个事件THEN。不能把这段都说成“内存完全不变”。准确说法是：目的4字节改变，其他块保持；之前ready与优先级表的结果不被这次局部赋值破坏。

连续状态链：

```text
M --两次表写--> M2 --旧坐标读取--> Mr --ready判断/更新--> Mf
  --本行接着执行，非另一份入口-->
Mf --真实事件指针赋值--> Me --条件为假，跳过真实事件体--> Me
```

稳定接口：`V293_task_prio_prefix_event_null_execution`。

接口从入口读权限、写权限、绑定和块隔离推导真实执行，不要求调用者先给成功store或后半段执行。Me中再次确认完整13槽、ready位图和pevent。六个坐标局部只在Mf观察：本片段尚未假设pevent与所有局部隔离，不能随意把局部保持推广到Me。

## 4. 本轮已补好的路径表

| 入口路径 | ready后的低/高行与组 | 事件读取后的pevent | 实际执行范围 |
|---|---|---|---|
| 任务原ready，8→6；事件为空 | 80 / 0 / 1 | NULL | 两次表写一直到事件if跳过 |
| 任务原不ready，8→6；事件为空 | 16 / 0 / 1 | NULL | 同上，ready假支只跳过ready更新 |
| 固定同一ready入口；事件非空 | 本课read控制不执行ready片段 | 块72、偏移5；条件为真 | 真实读取与条件；不含非空body |

前两入口还改变ready高行及组，不当作单因素消融。第三行与同一live的空指针read控制只改变事件字段值，局部目的初值相同。非空指针不需要在这次条件中解引用，因而不表示已经拥有可用事件结构资源。
