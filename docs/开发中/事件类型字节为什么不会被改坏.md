# 事件类型字节为什么不会被改坏

## 1. 这一步解决什么

上一轮已经把抽象 ECB 的等待列表与最终事件位图相连。但那不能说明真实内存里的 `OSEventType` 也正确。

本轮先解决一个必要的局部问题：**真实非空事件更新子语句执行时，只修改事件块偏移10～12，不修改偏移0的类型字节。** 这里的“执行”仍是项目框架中的源码级 `cstepstar`，不是机器码执行。

还没有把这个新结论接过优先级修改前缀、坐标计算、完整返回和局部变量释放。因此不能说上一轮完整返回定理已经包含事件类型保持，更不能说全局不变量成立。

## 2. 先分清两套数字

| 对象 | 信号量 | 邮箱 | 队列 | 互斥锁 |
| --- | ---: | ---: | ---: | ---: |
| ECB 的 `OSEventType` | 3 | 1 | 2 | 4 |
| TCB 的等待状态位 | 1 | 2 | 4 | 16 |

例如，任务正在等待信号量，TCB 的等待状态可以是1，而它指向的 ECB 类型应该是3。它们并不矛盾，也不能混用。

类型值来自锁定 V2.93.01 的 `Source/ucos_ii.h`，本轮重新只读校验源码并记录行号、文件哈希；没有拿别的发行版替代。

## 3. 把写入位置列出来

| 相对事件块起点的偏移 | 字段 | 此事件更新子语句是否写入 | 本轮结论 |
| --- | --- | --- | --- |
| 0 | `OSEventType` | 否 | 原字节保持；入口若绑定正确，出口仍绑定同一类型 |
| 4～7 | `OSEventPtr` | 否 | 字节保持；尚未建立它与抽象数据内容的对应 |
| 8～9 | `OSEventCnt` | 否 | 字节保持；尚未建立完整计数语义 |
| 10 | `OSEventGrp` | 是 | 由真实位图更新结果描述，不能套“不变”结论 |
| 11～12 | `OSEventTbl` 两行 | 是 | 等待位从旧优先级移到新优先级 |
| 其他位置 | 其余字节 | 否 | 细粒度 frame 覆盖；不等于任意共享断言都保持 |

读取事件指针时还会写局部变量 `pevent` 所在块。入口要求这个局部块与真实 ECB 块不同，否则不能用“局部写入”推出“事件块不受影响”。

## 4. 证明为什么不是绕圈

新接口 `V293_event_nonnull_type_execution`：

1. 接收原非空事件更新接口的全部物理入口条件，以及原内存中正确的类型绑定；不接收“执行已经完成”或出口读取结果。
2. **只调用一次**原真实执行接口，取得它返回的指针存储结果 `Me` 和实际事件更新结果 `Mf`。
3. 从这次指针 `store` 的结果和事件更新的真实写入地址，推导事件块偏移10～12之外的字节保持。
4. 由偏移0的字节保持，导出同一 `Mf` 上的类型绑定；同时保留原位图、局部值、事件指针、可写性及块外 frame 结果。

没有另外跑一次执行再把两个出口当成相同，也没有假设出口类型恰好正确。

## 5. 一个填好的例子

同一原始内存中的信号量 ECB 位于块72、偏移5；事件等待位由优先级8迁到6。

| 观察 | 入口 | 出口 | 验证方式 |
| --- | --- | --- | --- |
| 类型字节，绝对偏移5 | 3 | 3 | 实际调用新一般执行接口，使用其同一出口 |
| 等待位图低行，绝对偏移16 | 0 | 64 | 一般接口的真实位图结果 |
| 等待位图高行，绝对偏移17 | 1 | 0 | 一般接口的真实位图结果 |
| 事件组字节，绝对偏移15 | 2 | 1 | 一般接口的真实位图结果 |
| 局部 `pevent` | 原夹具中的旧值 | 指向块72、偏移5 | 保留真实指针读取与存储结果 |

所有入口条件都在同一字面内存中构造；不是把一个既有固定执行定理当作出口 oracle。

另外两条独立语义检查说明：

- 这个入口不可能同时绑定为邮箱类型1；
- 绝对偏移17的原值确实是1，真实写入表达式的结果是0，因此原始单元不同。不能把 frame 错扩到这一字节。这个反例本身是写入表达式的语义结论，不冒充整个返回路径的反例。

## 6. 如何复查

在工程根目录执行，输出目录必须尚不存在：

```bash
COQBIN=/data/home/lucentzhou/.opam/default/bin/ \
PYTHONDONTWRITEBYTECODE=1 python3 -B scripts/check-v293-event-type.py \
  --output-dir /tmp/event-type-recheck

PYTHONDONTWRITEBYTECODE=1 python3 -B -m unittest discover \
  -s tests -p test_event_type_local.py
```

门禁实际编译生产文件、旧接口 probe 和新 probe；另外在只导入冻结旧前缀的隔离模块编译整个新增后缀。`coqchk` 检查生产、新 probe 和隔离正控。单因素负控只把出口类型改为邮箱，保留完整 Proof；其拒绝只说明固定证明对后置敏感，不证明修改 C 后的行为，更不证明其他机制有效。

## 7. 下一步不需要猜，按这条链连接

`事件子语句细粒度 frame` → `任务表／ready／坐标及 TCB 更新后的同一内存` → `真实返回与局部释放后的同一内存` → `同一抽象 ECB 查询和等待列表`。

每跨一层都要保留同一次执行的内存身份，并明确其他写入块与 ECB 不别名。到完整返回层实际通过后，才能把“类型保持”加入上一轮队列接口。初始化、API／ISR 保持、正常无锁调度、当前任务一致性、K1–K4 和 `GOOD_OS` 仍要继续证明；阶段一没有完成，uC/OS-III 尚未启动。
