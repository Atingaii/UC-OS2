# 下一步：让 ready 位图真的在内存里改变

## 1. 这一步接在哪里

目标仍然是固定配置的 uC/OS-II V2.93.01 源码级 `GOOD_OS` 和同程序 K1–K4，完成后再开始 uC/OS-III。这一页只讲 `OSTaskChangePrio` 的一小段，不是整核完成报告。

前两步分别做了：

1. 两次优先级表赋值确实执行，旧槽清空、新槽填入任务指针。
2. 用数学关系证明：清除旧 ready 位、设置新 ready 位后，位图、任务优先级和优先级表仍对应。

第二步还没有执行物理位图写入。这一步补上 **ready 条件为真后的 THEN 分支**：从真实入口内存和写权限，构造实际存储与 `cstepstar`，再读取最终内存验证结果。不能直接把前一步表写和本步接成连续执行：中间的三次 TCB 字段读取和外层 ready 判断尚未连接。

## 2. 四次可能的写入

冻结源码 `Source/os_task.c` 的这段顺序如下；trace 宏在固定配置为空：

| 顺序 | 操作 | 为什么不能交换或省略 |
| --- | --- | --- |
| 1 | 清除旧行中的旧优先级位 | 旧优先级不应继续 ready |
| 2 | 读取刚写过的旧行；若为零，清除对应 group 位 | 不能使用修改前的旧行值 |
| 3 | 设置新行对应的 group 位 | 新行即将含 ready 任务 |
| 4 | 设置新行中的新优先级位 | 同一行时必须从清位后的内存重读 |

代码模型为 `V293_task_prio_ready_then`。这里的行号和掩码是局部变量的真实读数，不是纯数学参数替代读取；但它们如何由 TCB 字段和查表计算而来，仍是后续义务。补码、整数提升和最终字节窄化沿用已证明的 RHS，不以无限宽自然数操作替代 C 运算。

## 3. 稳定接口究竟保证什么

`V293_task_prio_ready_then_execution` 的入口给出：

- 两行和 group 的实际字节读取，group 等于两行非零情况的摘要；
- 三个可写字节、两块全局变量的实际绑定且不被局部变量遮蔽；
- 六个局部操作数的实际绑定和读取，局部块不与位图块混叠；
- 优先级在数组容量 13 内，两行均是合法字节。

它**不要求**调用方先提供成功存储、RHS 计算结果或出口内存读取，而是推导：

- 原 THEN 语句序列的实际 `cstepstar`；
- 最终两行及 group 的实际读回与数学更新一致；
- 写权限、局部操作数仍可用，位图两块以外的逐字节内容保持。

`V293_ready_fragment_entry_witness` 在同一状态同时构造全部位图入口读取、写权限和六个局部操作数。`V293_ready_fragment_execution_witness` 进一步消去这些入口条件，得到任意合法两行、优先级的具体执行实例；它不是从 `OSInit` 到达该状态的证明。

## 4. 不用作答，直接看四个结果

位图 `(lo, hi)` 分别表示优先级 0–7、8–12；group 的位表示相应行非零。

| 入口两行 | 改优先级 | 出口两行 | 出口 group | 检验点 |
| --- | --- | --- | --- | --- |
| `(0, 1)` | `8 → 6` | `(64, 0)` | `1` | 跨行、旧行变空 |
| `(0, 1)` | `8 → 10` | `(0, 4)` | `2` | 同一高行，旧位必须清除 |
| `(20, 0)` | `2 → 6` | `(80, 0)` | `1` | 同一低行，保留优先级 4 |
| `(0, 129)` | `8 → 6` | `(64, 128)` | `3` | 未使用的高位保留，不凭空清零 |

这些是实际最终内存的 `load` 结论，由通用执行见证实例化，不只是计算自然数。片段执行定理本身允许 `old = new`；完整 API 在此前检查并拒绝相等情况，13 的数组容量也不替代新优先级 `<12` 的 API guard。

另有真实内存混叠控制：把一个掩码局部变量放到即将清位的同一字节，写入就会改变该变量后续读数。这说明不混叠条件有实质作用，但不是完整 API 合法入口的反例。

## 5. 如何接回任务表

`V293_task_prio_ready_then_correspondence` 接收入口任务／位图／表关系，以及**已经完成重索引的物理优先级表**读取视图。实际位图执行后，它推导新任务关系、新表关系、最终物理表读取和最高就绪任务选择。

必须分清：

- 位图真的写了；这里不是只给出口对应作为前提。
- 任务表是数学抽象任务表，不是物理 TCB 五字段已经写完。
- 这个较大的连接接口没有新增“完整 13 槽表＋任务对应＋全部位图资源”同状态入口实例；上面的位图片段见证不能替它自动获得非空入口信用。
