# ADR-0005：显式临界宏映射不等于端口执行

- 状态：已接受，仅限延续 ADR-0001 的手工源码映射边界；不是接受新的 C 修复或已验证翻译结论。
- 日期：2026-10-29。

分析端口只有 `V293_EnterCritical`／`V293_ExitCritical` 的声明，原框架的函数执行需要函数体，且语言没有读取当前 IE 到 C 变量的语句。选择保留原始调用模型及“无定义无下一步”事实，另显式归一化同一 `&cpu_sr` 的宏标记到已有 `encrit`／`excrit`，在该抽象程序上完成纵向路径；不改 C、配置、端口或框架规则。

## 备选及取舍

- 给原始 `sfexec` 添加执行假设／直接冒充原语：失去真实函数调用边界，拒绝。
- 编造端口函数体或新增隐藏影子状态读取 IE：改变既有语言或引入额外语义，且不能由现有声明支持，拒绝。
- 导入真实硬件端口：超出当前源码级范围，且不是当前局部问题所必需。
- 继续只增加互不连接的保存值／退出／返回引理：不能验证单条连续执行，弃用。

## 信用边界

归一化检查标记标识不同、实参恰为同一保存变量的单个取地址表达式，并保持原 guard、SELF、查表和 return 次序；不支持的运行时语句被拒绝。但它不是通用的语义保持定理，也不检查任意程序的 token 别名／泄漏。当前新鲜配置后 C 的五个 cpu_sr 引用均仅为端口地址参数，初始化为0，只提供该函数手工映射的回归证据。

归一化**擦除 CPU_SR 字节存取**，框架保存栈负责原中断状态。物理见证故意将局部保存字节固定为23，仍可对两种初始 IE 实例化归一化执行；这说明不能把该执行当作原始内存 token 与栈相等的证明。真实端口调用到原语的仿真、真实局部分配／初始化与共享关系、完整函数和最终 GOOD_OS 仍开放。

有界验证只覆盖新槽已占用返回40路径：真实参数检查→已有 encrit→原占用判断→已有 excrit→实际 return／free／caller 恢复。其他错误分支虽保留在语法中，本轮不授其连续执行信用。四个前瞻负控使用独立正控投影，避免归一化早拒绝掩盖后续栈恢复；协议见 `audit/logs/stage26-critical-elaboration/`。
