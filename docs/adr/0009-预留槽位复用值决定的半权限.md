# ADR-0009：预留槽位复用值决定的半权限

- 状态：已接受（局部组件）；生产全局不变量、初始化及整函数集成未完成。
- 日期：2026-10-31。
- 范围：固定 V2.93.01 的任务创建预留、Hook frame 和失败回滚资源契约。

## 背景

`OSTaskCreateExt` 写入 RESERVED 后开启中断，再调用栈 Hook 和 `OS_TCBInit`。失败路径必须只清除此创建者预留的槽位。第111步的存在物理池虽然允许重新借出当前槽位，但不证明槽位所有权，可能接纳别的任务指针；不能以该池授予生产 safety 信用。

现有 `HalfPermMap` 已支持只读半权限和两半重组为写权限，不需要新增 ghost 状态、抽象标识符或公理。共享不变量还必须满足框架 `precise`：同一环境中不能任选半份或整份同值字节。

## 决策

共享槽位的权限由值唯一决定：值等于 RESERVED 时只有半权限，其他类型正确指针（包括 NULL）为全权限。创建者持另一半 RESERVED 权限，跨开启中断阶段作为调用者 frame 保留。

真实 RESERVED 写入后拆分；回滚进入临界区后借出共享池，从两个兼容物理读取推导当前值仍等于 RESERVED，再重组完整权限，进行真实 NULL 写入，最后把 NULL 全权限归还共享池。创建者的半权限随回滚消费，不复制给返回者。

## 理由与已取得证据

- `V293_reservation_pool_precise`、`pool_good`、`pool_isr` 经 Coq 检查；值决定权限避免同一环境存在两种不同子图。
- `V293_reservation_reacquire` 从兼容物理字节推导等值，没有“干扰没有修改槽位”的外部假设。
- `V293_OSTaskCreateExt_owned_stack_fragment` 将实际预留写入、退出临界区和原栈 Hook 调用连续连接；半权限留在调用者 frame，不要求 Hook 改变中断状态。
- 同一独立字面不变量接纳 NULL、RESERVED 和其他任务指针；`ROOwnedWholeLiteral` 证明带 owner 的调用者与共享池实际可分离共存。
- `ROOwnerRemovedAdmitsWrong` 给出删除 owner 后的具体兼容反例；`ROArbitraryPermissionNotPrecise` 证明任意选择权限的候选不满足 precision。

前瞻协议、编译快照、单因素对照及最终实测见 `audit/logs/stage112-reservation-ownership/`。编译失败若发生在共同输入证明之前，只算技术失败，不算消融结论。

## 备选方案

- 只用存在槽位值的全权限池：简单但无法推出归本创建者所有，拒绝作为生产所有权方案。
- 无条件允许任意半／全权限：具体反例违反 precision，拒绝。
- 新增 ghost 预留表／身份：现有物理半权限足以完成当前局部决定，未实施该替代方案，不声称其性能或表达能力较差。

## 后果与边界

两份 owner 半权限孤立地可以合并，不能声称 owner 本身不可复制；唯一性定理要求**共享池也在场**，此时第三份半权限不兼容。框架如何保证所有其他 API 和中断都保持该资源协议，仍须生产全局不变量与函数环境证明。

本决定没有修改 C、AST、权限框架或原有冻结证据。空闲 TCB 头仍限 NULL，此模块不是通用分配器，也不是完整 `OSTaskCreateExt` 或 `GOOD_OS`。标记地址继续服从 ADR-0004；未解决机器地址1、前端翻译、端口或硬件。

## 重新评估条件

若生产不变量无法兼容现有其他 API 的所有权转移、成功发布任务指针时无法消费／重组 owner，或其他执行者需要在 owner 存续时合法写同一槽位，应以具体反例重新评估；不得弱化 precision 或删除不利结果来通过验收。
