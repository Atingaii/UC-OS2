# ADR-0007：任务入口复用框架函数标识符

- 状态：已接受（局部源码表示）；同程序客户函数映射及端口契约仍开放。
- 日期：2026-10-31。
- 范围：固定任务创建调用中的 `void (*task)(void *)`；不修改C或通用框架，不声称硬件函数地址或ABI正确。

## 决策与依据

框架没有函数指针类型，也没有间接调用表达式；现有 `pstkinit_step` 使用 `vtoZ` 解码任务入口并查询客户程序 `pc f`。`vtoZ` 只接受 `Vint32`，不接受 `Vptr`。因此在手工前端中将任务入口表示为 `Tint32` 的函数标识符 `Vint32(Int.repr f)`，而非伪装成 `void *` 的对象指针。它不是把任意C函数指针强转为整数的实现证明。

必须显式满足 `0 <= f <= Int.max_unsigned`，证明解码恢复原f及此范围内编码单射。后续完整程序要建立源码函数与框架客户函数标识符的一致映射，并在任务初始化时兑现同一个 `pc f`、参数类型与实际任务体执行义务；不能在GOOD_OS根隐藏或凭空假设这些连接已经完成。

最小试验 `audit/logs/stage67-task-create-stack-entry/selector-spike06.v.snapshot.txt` 及对应编译日志已经证明：整数表示可恢复、范围内单射；同一 `vtoZ` 解码器换为对象指针即返回None；超范围0与2^32发生编码碰撞。原5次失败快照保留，不授信用。

## 备选与边界

- 对象指针/地址token：与现有任务初始化解码不匹配，试验拒绝；不选。
- 新增函数指针类型及语义：需同步类型、内存、表达式、调用与soundness，当前仅转交入口标识即可复用成熟框架；未实现这一备选，不宣称其性能优劣。
- 直接抹去task实参：丢失任务身份，不能区分实际新任务，拒绝。

本决定不提供缺失 `OSTaskStkInit` 的函数体，不允许用noop顶替。局部到达该函数的 `sfexec` 只表示实参已求值，不表示函数体已开始执行。若固定源码以后要求函数指针算术、对象解引用或真正间接调用，或无法建立统一的有限标识映射，应根据反例重新评估，不能缩小源码功能或改动固定C以制造通过。
