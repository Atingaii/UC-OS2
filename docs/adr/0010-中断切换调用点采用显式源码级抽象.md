# ADR-0010：中断切换调用点采用显式源码级抽象

- 状态：已接受，仅限 PROJECT_SCOPE 已接受的任务切换抽象边界。
- 日期：2026-11-02。
- 范围：OSIntExit 的 OSIntCtxSw 无实参调用点；不替代 ADR-0001/0005，不增加 C 修复。

## 背景

分析端口只声明切换函数。原始 `sfexec` 仍要求函数定义；不能从外部声明推出可执行函数体。框架 `pswitch_step` 仅写 `OSTCBCur`、保存旧任务代码并改变执行者，不写 `OSPrioCur`。因此直接把切换调用解释成裸 `switch`，不能得到新当前任务的优先级缓存一致性。

## 决策

保留原始调用模型、既有临界宏映射和缺失定义时的停顿证明。另建独立的调用点解释：在 ADR-0005 的结果上，仅将指定的无实参 `scall OSIntCtxSw nil` 映射为 `OSPrioCur := OSPrioHighRdy; switch OSTCBHighRdy`。不安装端口函数体、不增补 `sfexec` 规则、不改变框架的切换规则。

以真实空间所有权构造两个物理写入，并连接完整函数调用前缀到原 `lpstep` 切换。对照程序只删除缓存赋值，其他源码、输入堆、调用者与任务映射不变；对照也必须实际切换，而不能用语法拒绝或入口停顿代替消融。

当前/目标指针的全局类型使用同一 `Tptr V293_tcb_type`，满足原切换规则要求。独立见证为此重建全局类型环境，但保持同一物理字节；旧 `Tptr Tvoid` 见证及其证据不改写。

## 理由与备选

- 复用原 `switch` 及现有所有权/缓存定理，避免重新定义调度语义。
- 裸 `switch` 保留为反事实对照，不能作为生产缓存同步方案。
- 给原始外部调用编造函数体或添加执行公理：无法由声明支持，拒绝。
- 立即导入汇编/硬件端口：超出已接受的源码级范围，不采用。

## 后果与限制

这是显式源码级边界选择，不是原外部调用到原语的语义保持证明。原 C、配置、AST、旧证据及框架保持不变。归一化拒绝指定端口的非空实参、值返回调用和内部 runtime 语句，但这不是任意程序的完整翻译器。

实际切换后，旧任务的 excrit/return/caller/kint 和新鲜 saved 局部仍被挂起；不能宣称旧任务已退出临界区或已完成返回。证明一条不交错有限执行，不保证任意交错、生产 ISR 安装、WFFunEnv、初始化或 GOOD_OS。

## 重新评估条件

实现真实端口 refinement、改变切换原语或缓存所有权契约、安装生产 ISR/函数环境时，重新审查此边界与恢复现场的对应关系。
