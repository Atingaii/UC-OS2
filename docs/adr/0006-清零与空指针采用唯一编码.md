# ADR-0006：清零与空指针采用唯一的四零字节编码

- 状态：已接受；原有187源的隔离重建、所有权连接及框架信任根实际检查通过。
- 日期：2026-10-30。
- 范围：本工程源码级32位指针表示；不修改固定 C、配置、两项授权补丁或 ABI 边界。

原生 `OS_MemClr` 只写零字节，但旧模型把 `Vnull` 编码成四个 `MNull`；第43步的闭合反例表明二者不同。仅修改解码不能建立要求精确编码的 `Amapsto`。因此同时将 `Tnull`／`Tptr`／`Tcom_ptr` 的 `Vnull` 规范编码改为四个 `Byte.zero`，仅恰好四个全零字节解码为空指针，复用现有字节与列表相等决定。

最初考虑保留 `MNull` 的读取兼容，但隔离全量构建在既有 `V293_pointer_decode_encoding` 失败，独立 `DualEncodingCounterexample` 又证明“旧 MNull 可读为 null，但不等于新规范编码”。保留双表示会使现有的读回→规范所有权推导失效。删除这一非必要兼容层，而不是弱化旧定理：旧裸 `MNull` 仍是可存储字节构造器，但不再能解码为空指针；旧 rekey 有限实例的四个空值字节迁移为规范零字节，其执行结论与全部原有引理陈述保持不变。

改变 C 清零、直接假设指针表已初始化均绕过原目标，不采用；把所有权扩展为多种表示会改变更多框架断言与推理，当前没有必须接受这种输入的需求。整数解码、非空指针片段算法、内存块上界及分配接口不改，不加公理、不加入整数转指针或新依赖。

这是模型语义变更，不声称旧模型全部可观察行为保持：零字节的指针 load、null store 后的整数 load 和旧 MNull 的指针 load 有意改变。旧日志、反例、失败及对象归档保留；历史输入哈希不再代表当前模型，不能改写旧证据制造通过。必须在唯一新模型上重建全部原有模块，检查框架 soundness／顶层根，再证明字节所有权到 typed null 与真实清零执行的连接。

该选择不证明 ABI／机器零地址、C 前端、完整 TCB 表或初始化可达性，也不推进 GOOD_OS／K1–K4 六门覆盖。若需不同指针宽度或真实整数地址转换，据新需求重新评估。

验证记录见[第44步](../../audit/STAGE44_NULL_BYTES.md)。候选双编码的提议和失败留在审计目录，不改写历史。
