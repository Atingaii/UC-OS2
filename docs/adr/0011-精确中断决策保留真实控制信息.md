# ADR-0011：精确中断决策保留真实控制信息

- 状态：已接受下述信息边界；框架状态的最终表示及迁移尚未决定。
- 日期：2026-11-05。

在当前不变式允许的真实输入中，同一低层程序、抽象任务状态、Inv 和 LI，仅修改锁字节，就会分别触发调度和不调度。若要求固定规格精确、确定性地决定这两个分支，不能只观察旧 `osabst`；决策必须保留能区分输入的真实控制信息，或另行证明更强入口不变式确实排除了该对照。不能把每个堆各选一个规格当成统一规格，也不采用“任选调度/不调度”来放宽目标。

本步以 `(osabst * V293_irq_control)` 提供可检查的迁移组件：三个字节从实际 `BuildintPre` 的同一状态读取，唯一捕获，确定性选择；旧四键状态原样投影，不将控制位塞入时间或任务表的虚假条目。复用现有源码 guard 规则，保留 dispatch body 前提。这不是将产品状态安装进旧 `spec_step`、`WFInt` 或健全性定理。

## 备选与限制

- 精确 O-only 布尔选择器：当前允许输入的单字节对照已将其排除；不等于排除所有非确定性规格。
- 更强 current/初始化可达不变式：仍是可能路线。对照含 Waiting 当前任务，没有证明它从初始化可达；必须先证明新不变式的建立和保持，不能直接删除反例。
- 扩第五抽象键或参数化框架状态：尚未比较完整迁移成本及健全性义务，当前不改既有框架，也不将直积当成最终架构。
- 高层条件选择：旧框架的中断规格固定、不能直接读取这三个物理字节。未来扩展须证明与真实字节的耦合关系及更新保持，不能只增加一个未被执行规则读取的字段。

完整调用见证仍分别使用既有 `CCspec` 与 `QCspec`，不是同一个高层程序的双轨迹。饱和深度255的 Enter/Exit 对落到254，不能伪装为恢复原深度。quiet 当前非最高时选择 END；没有放宽最高就绪调度规则。
