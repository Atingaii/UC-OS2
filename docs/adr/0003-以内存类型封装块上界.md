# ADR-0003：以内存类型封装块上界，恢复分配与 soundness 证明

- 状态：已接受并实施；完整迁移验收通过。
- 日期：2026-10-26。
- 范围：通用内存表示、原语与既有证明客户端；不改变 C 修复、配置和源码身份。
- 替代：[ADR-0002](0002-内存新鲜块必须来自显式边界.md) 中“保持任意函数类型、逐层外传边界”的表示策略；显式 `blocks_below` 接口继续保留。

## 背景

原始全满函数与 `MemoryNotFull` 能推出 `False`，历史失败证据 `audit/memory-trust.json` 保持不变。两份 `fresh_exist` 直接使用错误公理，其下游包括内存扩展、环境分配、连续分配、任务步进以及最终 soundness。

仅删除公理而保留任意函数式 `mem`，不能证明原来无条件的新块存在性。若坚持该表示，就必须改变这些真正面向任意 `mem` 的接口，在状态、并发分片和操作语义中另行传递边界。

## 决策

1. 用 `HalfPermMap.Map` 的 record 封装原函数 `contents` 和命题字段 `bounded : raw_bounded contents`。该字段明确要求存在块标识严格上界；不是 `True`，不是新增公理。
2. 上界只约束块标识，不引入有限偏移支持、固定 RAM 容量或全局分配游标。不同内存可有不同上界，分配后上界可以增长。
3. 空内存直接给出上界；`set` 与 `merge` 用正整数最大值合成上界，`del` 与 `minus` 继承已有上界。所有构造器必须真的证明保持性。
4. 数据函数及读写权限算法不变。保留函数式读取强制转换，以及 `memMap`、分配／读写／释放与既有规则的接口；只修正因 record 投影或隐式类型推断而失效的证明脚本。
5. 使用既有标准函数外延性和由经典逻辑推出的证明无关性证明 record 外延相等；不新增独立的证明无关性公理。
6. `memory_has_fresh_block` 成为稳定接口，两处旧 `fresh_exist` 复用它。原 `MemoryNotFull` 从活动源码移除，不以另一个未经证明的公理替代。

## 依据与备选

可丢弃实验实际在 Coq 8.18.0 中编译了改造后的整个 `memory.v`，保留内存操作引理规格；模块内三个泛型函数外延辅助引理收窄为 record 外延引理，无外部调用者。原语闭包与 `memory_not_full` 均已有证明。迁移到正式依赖链后，出现的具体失败是客户端展开函数后未化简 record 投影，而非必须削弱其规则规格。

这提供了采用封装方案的可执行依据，但不是对“逐层传递边界”方案做过耗时 benchmark；后者没有被完整实现，不能声称量化性能胜出。

认真考虑过的替代方案：

- 继续接受原公理：已有矛盾，拒绝。
- 保持任意函数类型并显式外传边界：逻辑上可行，但需要改变分配进展与相关规则接口；本次采用类型内共享的不变量避免重复前提。
- 改成有限映射库：引入当前新块存在性不需要的偏移有限支持约束，迁移面更广，本次不采用。

## 后果与验收

`mem` 不再与任意地址函数等同；旧全满函数作为 raw 函数仍存在，但不能成为合法 `mem`。为防止通过缩小类型偷偷改变算法，新增 `memory_representation.v`，证明原语擦除等式、join 双向等价、分配／写入／释放结果对应、类型可满足和连续分配，并证明满映射不具备边界且不可表示。

最终验收还必须包含完整干净构建、真实调用链和 soundness 根的假设与 `coqchk`、实际坏构造器拒绝以及仅中和边界条件的单因素对照。仅编译此模块不代表整框架迁移完成；更不代表固定配置内核的 `GOOD_OS` 已完成。

实际验收已完成：109 文件干净构建、11／20／13 个根的检查、构造器和三个指定位置故障对照、依赖闭包 `coqchk` 均通过。完整记录与剩余假设见[第六阶段报告](../../audit/STAGE06_FRAMEWORK_REPAIR.md)。

这是对合法状态域的显式限制，原语对应只针对有界子域，不声称保持旧表示全部任意函数状态的行为。具体 V2.93.01 初始化与程序连接仍是后续义务。

如未来需要固定物理容量或分配失败建模，应另行修改语义与规格，而不是把当前逻辑块上界当作该性质的证明。
