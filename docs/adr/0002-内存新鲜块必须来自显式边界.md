# ADR-0002：内存新鲜块必须来自显式边界，不依赖全局不满公理

- 状态：已接受；全框架迁移尚未完成。
- 日期：2026-10-26。
- 范围：通用框架内存分配的前提与后续共享不变量；不改变固定 C 源码、CPU 边界或授权修复范围。

## 背景与证据

`mem` 是 `addr -> option (bool * memval)`，没有有限性约束。`FullMemory m` 表示每个块标识都至少有一个已占用地址；现有 `MemoryNotFull : forall m, ~ FullMemory m` 对所有任意函数生效。

本机 Coq 8.18.0 已编译具体反例 `fun _ => Some (true, Undef)`，它满足 `FullMemory`；结合原公理得到 `False`。在独占临时模块只移除该公理声明，原具体满内存见证仍编译，但同一矛盾证明在引用该公理处失败。此消融只说明这条矛盾路径依赖该公理，不证明其余框架的全局一致性。

`memory_prop.v` 与 `rulesoundlib.v` 中两份无条件 `fresh_exist` 直接使用该公理。仅对新辅助文件执行 coqchk，不能把这些调用链变成可信依据。

## 决策

1. 不使用该公理／矛盾证明为内核取得任何证明覆盖。
2. 保留当前函数式内存表示和标准正整数块标识，先显式维护“已占用块标识小于某个 upper”的谓词 `blocks_below`，从它证明 fresh。
3. 边界随分配增长，而非预设固定容量；现阶段只引入新鲜块论证所需的块标识有界性，不额外要求每个块的无限偏移域都具有有限支持。
4. 现有框架仍隔离为信任未通过：独立门禁返回失败；在状态／语义／soundness 全部传递正确边界并移除原公理前，不宣称修复完成或使用旧无条件 fresh 结论闭合 GOOD_OS。
5. 后续需在初始化中给出可满足的边界，并证明所有相关状态操作和调用边界保持它；禁止将 `init := False` 或 `forall m, bounded m` 当作替代。

## 理由

已有 `allocb`、写入、释放均能在保留原内存表示的情况下保持或增长块标识边界。新增模块实际证明了 11 个接口，含空内存可满足性、边界推出 fresh、更新／删除／分配／写入／释放保持；全部根假设检查不含 `MemoryNotFull`。实际列出的其他假设仍为经典逻辑和依赖函数外延性，未声称完全无公理。

## 认真考虑过的备选

- 原样接受全局公理：已存在具体可编译的矛盾，拒绝。
- 直接将 `mem` 全面改成带有限支持证明的 record 或有限映射：能从类型限制任意满映射，但会同时改变 map 运算、权限实例及大量依赖接口；当前新鲜块所需约束可用显式边界表达，先不全面替换。
- 仅删公理且保持旧无条件 fresh 引理：原函数空间中该命题为假，不能靠补 tactic 修复。

## 后果与重新评估

需要改造真正使用 fresh 存在性的证明链，而不仅新增这个模块。现有顶层框架证明不得因“能构建”就被视为信任通过。若在并发分片、合并或客户端步骤传递边界的成本实际超过有限映射替换方案，应依据可复现障碍重议表示方式，不偷偷恢复全局公理。
