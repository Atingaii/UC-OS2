# ADR-0008：为空语句补齐经过语义证明的推导规则

- 状态：已接受；构建及验收结果见本步报告。
- 日期：2026-10-31。
- 范围：框架 `InfRules`、`RuleSound`；不改变 C、操作语义或已有规则的前提。

## 背景

`V293_init_zero_sequence` 的空尾是 `sskip None`。完整 `OS_InitMisc` 的现有模型保留该空尾，然后执行 `sret`。框架 `InfRules` 中历史 `skip_rule` 只有注释，不能构造通常的空语句证明。因此原模型的执行轨迹已经可证明，却不能按现有赋值／顺序／返回规则完成 Hoare 组合。

## 决策

在 `InfRules` 末尾增加保持同一断言的 `skip_rule`，适用于任意 `sskip v`。先直接从现有 `MethSimMod` 证明 `skip_rule_sound`，再在 `RuleSound` 的归纳证明加入对应分支。其余规则前提、操作语义及 `RuleSem` 不变。

`RuleSem` 本来就要求实际状态满足 `CurLINV`，新规则不删除该要求。`OS_InitMisc` 的赋值仍必须证明更新后持有该不变量；新增的函数 Hoare 接口显式要求保留 frame 蕴含真正的 `CurLINV`，不声称启动前状态满足它。

## 理由与备选

独立 Spike 在修改框架前已由 Coq 8.18 检查空语句的 `RuleSem` 定理（允许的经典逻辑和函数外延性假设保留）。空语句在方法结束处直接满足相同后置断言；它既不写内存，也不伪造抽象步。

认真考虑过两个替代：

- 另建不带空尾的初始化程序，再只证明这个新程序：需要维护两份表示及额外等价连接，且仍未证明当前精确函数。
- 仅另证语义 Hoare，不加入 `InfRules`：无法直接满足现有 `WFIFun` 的推导要求。

选择补齐框架这一条规则，避免改写待证程序或复制一套顶层逻辑。不采用公理，也不降低覆盖验收标准。

## 后果

`InfRules` 的归纳结构变化，依赖它的 Coq 产物必须重新构建，不能宣称复用了全部旧产物或旧信任检查结果。历史证据仍保留原身份；旧快照哈希测试可能拒绝当前修改，必须明确报告，不覆盖历史报告使其变绿。

本次不证明完整启动、运行态共享不变量、94 函数统一规格环境或 `GOOD_OS`。若未来操作语义改变了空语句的行为，必须重新检查此规则及其健全性，而不能仅保留构造器。
