# ADR-0004：保留指针采用显式符号地址

- 状态：已接受（局部表示与guard）；上层统一符号、非冲突、初始化义务仍开放。
- 日期：2026-10-28。
- 范围：固定源码宏 OS_TCB_RESERVED 的手工源码表示，不修改固定 C、通用框架或 CPU 边界。

## 背景

宏是整数1到OS_TCB指针的转换；现有框架对直接表达式返回evaltype=None，已有闭合探针确认。冻结源码中的宏只用于特殊值存储和比较，不能把它删掉或替换NULL。需保留NULL、保留值、真实任务指针三个不同角色。

## 决策

复用现有typed pointer及address-of，通过一个静态全局符号地址表达token。取地址不读取token内存，不引入可变全局指针load。符号不是C源中新对象，也不是具体数值地址1；属于手工源码映射的显式表示约定，而非一个已验证C前端。

契约必须公开：符号的全局绑定、无局部遮蔽、真实任务指针不与token相同；证明三类相等决定、实际guard两支选择、入口查表与guard的连续执行。未来各API的存储/比较统一使用同一token，上层函数环境、共享TCB关系及初始化须建立这些义务，不能在GOOD_OS根偷偷假设已完成。

## 理由与备选

既有框架已经有pointer equality和address-of，足以表示当前非解引用标记的决定。扩展整数转指针会牵涉值、语言、大小步语义和soundness，并引入本阶段不需要的数值地址解释；未完整实施该替代方案，不声称性能优劣。可变全局指针load会为常量引入无必要的状态依赖，不选。删除guard或换NULL改变源决定，拒绝。

## 后果与重新评估

此约定不证明机器地址1、ABI、全部C cast或前端翻译正确。旧直接整数cast探针仍应返回None。若之后发现token被实际解引用、需要算术/大小关系，或上层无法建立唯一符号与非冲突关系，应据具体反例重议；不得缩小TCB域或更改固定源码来制造验收。
