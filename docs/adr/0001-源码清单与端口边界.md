# ADR-0001：源码清单由编译器产生，端口操作保留显式边界

- 状态：已接受。
- 日期：2026-10-26。
- 范围：固定配置后的可移植源码清点；不构成 C 到 CoqImp 翻译或硬件端口选择。

## 决策与理由

使用本机已有 Clang 17 预处理并生成 AST，用 GCC 12 独立预处理与语法检查作交叉核对；Universal Ctags 5.9 只作未配置源码目录索引，不能决定活动函数集合。不自行编写 C 解析器，也不采用历史文档中的函数总数。最小试验得到 92 个活动定义，Clang 与 GCC 对名称、类型、定位、调用一致；ctags 对这 92 个定义的起止行一致，另索引到 34 个未进入配置翻译单元的定义。

缺失的 CPU 头由一个**只用于源码分析**的薄适配头提供：32 位指针与整数、向下增长的栈、critical method 3。临界区和切换宏展开为外部函数调用，不展开为空操作。这里选择固定的源码表示边界，而不是实现某个硬件端口；这些调用未来必须对应框架中断／任务切换语义，CPU hooks 的契约仍开放。

这些位宽会影响后续 C 表示与 Coq 内存布局，修改前必须重新生成清单并审查所有相关映射，不能视为无影响的“编译参数调整”。

## 认真考虑过的备选

- 手写正则表达式提取 C 函数：依赖条件编译、注释与声明格式，不能可靠给出活动集合，弃用。
- 把 CPU 宏展开为空以便解析：会从后续源码对象中删除关键行为，弃用。实测两个编译器都可能接受这种错误适配，单有编译成功不够。
- 导入完整硬件端口：引入本阶段不需要的汇编／ABI／硬件选择，超出源码级边界；暂不采用。

## 后果及重新评估条件

生成器需要 `clang`、`gcc` 和带 JSON 支持的 Universal Ctags。工具版本和生成内容一并记录；更换工具造成的清单变化要审查，不能静默回退。Ctags 不是所有配置的语义解析器，未进入当前配置的记录只是有界源码目录索引。

当前清单身份明确为修复前上游，不得计入修复后函数覆盖。集成两项授权修复后，必须另行冻结修复后身份、增补函数并重建清单；若真正需要不同位宽或端口契约，应先重新评估此边界。
