# 实际调度器与共享状态：施工入口

这是第八步之后保留的施工入口。后续已完成源码绑定的读取／两次赋值检查点，见[第十步教学](10-调度器真实内存读取与两次赋值.md)；函数级 Hoare 和共享不变量仍未完成，仍不提高 `OS_SchedNew` 的六门覆盖。

## 已核对的真实对象

- 固定修复后源码身份：`74390755cddc42a391055da46b744bbf32e77ba3dc025c2ae55b9441ba6170da`。
- `OS_SchedNew`：`Source/os_core.c:1751–1776`，静态、无参数、返回 `void`，无直接或间接调用。
- 配置后函数体 SHA-256：`79b7dfc83a0691b32d2d74f1009397bee928f720f68cec034fd98d13dd350815`。
- 当前 `OS_LOWEST_PRIO = 12`，真实 `OSRdyTbl` 是 **2** 项，不是根据 64 个优先级上限猜成 8 项。
- 实际 AST 有局部 `INT8U y` 和两次赋值：

```c
y = OSUnMapTbl[OSRdyGrp];
OSPrioHighRdy = (INT8U)((y << 3u) + OSUnMapTbl[OSRdyTbl[y]]);
```

实际预处理 AST 的 `OSUnMapTbl` 定义包含 256 项初始化器。本次逐项检查：非零输入对应最低置位位号，输入零对应零。首次提取误选了无初始化器的声明，检查明确失败；随后只选择唯一实际定义，256 项检查通过。该有限枚举只是下一步证明输入，不是 Coq 定理。

## 不能丢弃的 C 细节

- 第一次赋值是数组读取，不是一个预先给定的数学函数结果。
- `y` 在移位前经 C 整数提升为 `int`；常量 `3u` 是 `unsigned int`；加法的结果为 `int`，最后显式窄化到 `INT8U`。
- 数组到指针转换、左值读取和指针索引必须由受限翻译器检查，不能把未知 AST 节点全部剥掉。
- 函数注释要求中断已关闭；前置条件必须体现读取期间位图不会被中断修改。

## 先建立最小的资源和状态关系

本函数需要的具体资源是：`OSRdyGrp`、两项 `OSRdyTbl`、只读 256 字节 `OSUnMapTbl`、`OSPrioHighRdy` 及局部 `y`。全局名字到类型／地址的映射必须来自同一目标，不能拿历史内核布局代替。

就绪位图前置至少应给出：

1. 组位 0、1 分别等价于相应行非零，其余组位为零。
2. 优先级 0–12 中至少有一个就绪位；上层可由空闲任务优先级 12 就绪推出。
3. 数组项与“任务就绪”关系一致；完整 TCB 一致性由上层共享不变量推出，不在此处复制另一套任务状态。

这里没有把“优先级 13–15 的位都为零”加入局部前置。本轮从真实查表初始化器枚举 65,528 个满足其余条件的两行状态，单独允许这些高位后，选中结果始终不变，且等于 0–12 中实际就绪优先级的独立最小值。它对该局部决定不是必需条件；完整内核的 TCB／位图一致性是否要求这些位清零，另由全局证明确定。历史调查命令为 `PYTHONDONTWRITEBYTECODE=1 python3 scripts/inspect-v293-ready-bitmap.py`，当时记录见 [ready-bitmap-investigation.json](../../audit/ready-bitmap-investigation.json)。这份有限调查不是 Coq 定理，不增加函数覆盖；它绑定的是第八阶段输入，不能当作当前修订的实时身份通过证据。后续全称 Coq 证明及读／写检查点见[第九阶段报告](../../audit/STAGE09_SCHEDULER_UPDATES.md)。

由此应推出：组查表得到 `y < 2`，两次数组读取合法，最终结果在 0–12 中且等于就绪优先级的最小值。除了 `OSPrioHighRdy` 和局部 `y`，所有共享资源不变。

这一步必须同时落到真实内存断言、准确函数体和局部 Hoare 接口；不能只增加一个独立的位运算模型算作源码覆盖。

## 预先确定的单因素对照

| 只变一个因素 | 见证／指定失败 |
| --- | --- |
| 查表项 `OSUnMapTbl[16]` 从 4 改成 3 | 仅空闲任务就绪时，结果从 12 变为 11；最高优先级结论必须失败 |
| 移位常量从 3 改成 2 | 优先级 8 与空闲任务就绪时，应选 8，却得到 4 |
| 仅取消组位与行非零的对应 | 行 0 为 2、行 1 为 16、组为 2；空闲任务仍就绪，算法选 12 而不是最小值 1 |
| 仅取消 0–12 中非空就绪要求 | 全零位图使算法返回 0，却不存在可选就绪任务 |

这些控制要进入各自的语义或不变量义务；不能全部由源码哈希变化提前拒绝后宣称所有下游机制都有效。
