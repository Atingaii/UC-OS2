# 第十八课：让中断与临界区资源穿过内部调用

## 1. 我们正在接哪一段？

仍是同一份冻结源码中的 `OS_Sched`，不是新做一个调度器：

```text
进入临界区                         ← 入口资源的产生仍待连接
检查中断嵌套与调度锁
  OS_SchedNew()                    ← 本轮补内部调用的资源交接
  OSTCBHighRdy = OSTCBPrioTbl[OSPrioHighRdy]
  如果选中优先级不同：
    切换计数器加一
    真正切换                       ← 仍有开放证明义务
退出临界区                         ← 仍待连接
```

上一课把当前任务、当前优先级和目标指针联系起来。但还有一个障碍：走到真正切换前，需要保留中断状态和临界区状态；不能让这些资源在内部调用时丢失。

## 2. 为什么不能直接套 frame？

分离逻辑通常允许把无关资源放到 frame：调用修改自己的资源，其余原样保留。但这里框架的 `GoodFrm` 对中断／临界区标志有明确限制。`Ais stack`、`Acs critical` 等断言不满足普通 frame 的要求。

不能补一个 `GoodFrm (这些标志)` 前提就当问题解决了：那可能把接口变成永远不能实际调用的条件定理。

本轮采用的办法是：**把必须保持的资源放进被调函数的正式契约，由实际函数体证明保持。** 普通 frame 仍只放允许的资源。

## 3. 新契约携带什么？

简写：

```text
K = SWINV I ** (Ais stack ** Acs critical)
```

| 部分 | 这里的意思 |
| --- | --- |
| `SWINV I` | 框架真正的切换不变量，包含中断清理、关中断状态、栈顶以及相应中断不变量资源 |
| `Ais stack` | 中断栈快照 |
| `Acs critical` | 临界区栈快照 |
| `I` | 参数化中断不变量；本轮没有声称已构造实际内核的完整不变量 |

新内部调用接口可以直观读成：

```text
{ (原内部前置 ** K) ** 合法普通 frame }
    OS_SchedNew();
{ 存在返回值，(原内部后置 ** 同一个 K) ** 同一个 frame }
```

`stack` 和 `critical` 是每次调用的逻辑参数，不是把整个程序固定成空栈。返回保持同一个快照。两次真实赋值和返回语句提供这个结论，没有新增“任意调用都会保持标志”的规则。

## 4. 如何连接上一课？

| 已有部分 | 本轮连接后的结果 |
| --- | --- |
| 内部构造器 | 用 `BuildPreI`／`BuildRetI` 包住携带 `K` 的前后置 |
| 内部函数环境 | 同一个真实函数体建立新的单函数 `WFFunEnv` |
| 内部调用 | 用真实 `call_rule`，不要求 `GoodFrm K` |
| 后续指针赋值 | 更新实际可写全局目标指针，保留 `K` |
| 两层 guard、比较、计数器 | 同一条前缀继续执行；递增后把当前任务／目标资源和 `K` 一起交给切换的后续证明 |

最后一行中的“交给后续证明”不是“切换已经证明”。`suffix` 的 Hoare 仍明确出现在接口前提中。

## 5. 有没有一个实际满足这些前置的状态？

有。本轮将上一课两种完整状态，分别加上空栈和空中断不变量的资源：

| 场景 | 当前任务 | 目标 |
| --- | --- | --- |
| 相同目标 | 优先级 12，就绪 | 当前任务自身 |
| 不同目标 | 优先级 4，时间等待 | 另一个优先级 12 的就绪任务 |

位图、指针表、当前任务、两个合法 guard 字节和任意计数器，仍共同存在于同一个状态。新增断言不是用 `False` 糊过去的。

这个见证只证明**该局部前置确实可满足**。它选择空不变量、空栈，不代表真实内核初始化，也没有证明进入临界区的源码会产生这些资源。参数化保持定理比这个见证更一般，两者不能混为一谈。

## 6. 现在仍缺什么？

1. 从完整函数入口的进入临界区语句得到这些资源，并在退出时正确归还。
2. 合并／取得当前指针的完整写权限；现有 `CurTid` 只有半权限读取。
3. 将真实 TCB 字段、全局变量和参数化关系连接成实际共享不变量。
4. 接真实 `switch_rule` 和对应抽象调度动作。
5. 对已自删除的当前任务单独走 `SWPRE_DEAD`／`switchdead_rule`，不能强迫它仍在任务表中。
6. 整个程序的函数环境、初始化、`GOOD_OS` 和同程序 K1–K4。

所以当前函数覆盖不增加，uC/OS-III 也尚未开始。下一步继续真实切换所需的当前指针权限与共享不变量，不需要先回答练习。
