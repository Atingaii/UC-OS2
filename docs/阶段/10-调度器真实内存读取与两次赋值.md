# 第十步：让调度器真正读取和写入内存

上一步确定了真实 `OS_SchedNew` 的两行 C 代码及最小前置。本步把它们连接到真实查表初始化器、CoqImp 表达式求值和两次赋值执行。验收见[第九阶段报告](../../audit/STAGE09_SCHEDULER_UPDATES.md)。

**本步还不是该函数的完整 Hoare 证明，更不是整核完成。** 先理解下面这个例子，再看证明接口，不需要回答练习题。

## 1. 先用空闲任务走一遍

当前优先级范围为 0–12，数字越小优先级越高。两个就绪字节分别覆盖 0–7、8–15；本配置只使用其中 0–12。

假设只有优先级 12 的空闲任务就绪：

| 对象 | 值 | 含义 |
| --- | --- | --- |
| `OSRdyTbl[0]` | 0 | 优先级 0–7 都未就绪 |
| `OSRdyTbl[1]` | 16，即二进制 `00010000` | 第二行的第 4 位就绪，对应优先级 12 |
| `OSRdyGrp` | 2，即二进制 `00000010` | 第二行非空 |
| `OSUnMapTbl[2]` | 1 | 组值最低置位位号为 1 |
| `OSUnMapTbl[16]` | 4 | 行值最低置位位号为 4 |

实际 C 执行：

```c
y = OSUnMapTbl[OSRdyGrp];             /* y = 1 */
OSPrioHighRdy = (INT8U)((y << 3u)
                    + OSUnMapTbl[OSRdyTbl[y]]); /* 8 + 4 = 12 */
```

`y << 3` 在这里相当于 `y * 8`。查表不是任意数学函数：`V293ReadyTable.v` 中的 256 个值来自固定 C 源码的实际初始化器，门禁分别从 GCC／Clang 预处理结果中提取并比较。

## 2. “算对了”还缺哪些内容

可以按五层理解本项目：

| 层次 | 要回答的问题 | 本轮状态 |
| --- | --- | --- |
| 数学性质 | 所选结果是否确实就绪，而且是最小优先级？ | Coq 全称定理已建立 |
| 实际读取 | 数组地址、索引、类型提升和字节读取是否得到这个结果？ | 已建立 |
| 两次赋值 | CoqImp 是否真的执行两次写入，并保留其余字节？ | 不被其它执行交错的执行已建立 |
| 函数 Hoare／内部组件 | 分离资源、局部变量生命周期、返回及中断不变量是否全部连接？ | 未完成 |
| 整核 `GOOD_OS` | 所有函数、初始化、调度、中断与同程序 K1–K4 是否共同闭合？ | 未完成 |

第三行不是第四行的替代品。当前 `cstepstar` 是语言层的语句步进，不是任务／中断系统所有可能交错的安全性定理。

## 3. 数学定理没有把答案写进前置条件

`V293_bitmap_ready lo hi p` 用 `Nat.testbit` 独立定义某个优先级是否就绪，不用查表结果来定义“正确”。

前置只要求：

1. 两行都是字节：`lo < 256`、`hi < 256`。
2. 组值与各行是否非零一致。
3. 0–12 中至少存在一个就绪优先级。

`V293_ready_selection` 推出：组查表索引小于 2；结果实际就绪；结果不大于任何就绪优先级。因此不是“假设结果最小，再证明结果最小”。

第 13–15 位在本局部定理中不必清零：如果第一行非空，第一行优先；否则非空的合法候选保证第二行最低置位不超出合法范围。以后建立 TCB 与位图的全局一致性时，仍须单独决定那些位的约束，不能把局部可删除条件泛化成全局结论。

## 4. 内存前置描述的是叶子读取，不是最终结果

`V293_sched_read_env` 把全局名字定位到有类型的块；`V293_sched_read_memory` 规定：

- 组字节读出 `g`；
- 256 项查表逐项读出源码初始化器中的值；
- 两个就绪字节分别读出 `lo`、`hi`。

输出和局部 `y` 还各自需要可写的一个字节。只读查表不要求可写；读取的字节和可写输出之间不能用一个含糊的“内存正常”代替。

`V293_OSSchedNew_precondition_witness` 构造出一份有界的实际内存：查表、组及行只读，输出及 `y` 可写。这说明前置确实可以同时满足，不是互相矛盾的空条件。它是局部见证，不是内核初始化证明。

## 5. 两次赋值保证什么

主要接口在 `V293OSSchedNewExec.v`：

- `V293_OSSchedNew_updates_execution`：从具体叶子读取和可写前置，推出两次赋值的 `cstepstar` 执行；写入 `y` 后重新证明共享读取保持，再执行第二次赋值。
- `V293_OSSchedNew_updates_frame`：除 `(y块, 0)` 和 `(输出块, 0)` 这两个精确地址外，其余字节和权限均不变，包括同一块的其它偏移。
- `V293_OSSchedNew_updates_result`：最终输出字节读到所选结果，且结果确实就绪、最小。

变量标识仍为链接参数，还没定义完整目标的全局符号表。源码的 `void` 函数隐式返回已在翻译体中表示，但本轮执行定理只覆盖两次赋值，不声称已经证明局部变量分配／释放或返回。

## 6. 怎样知道检查器不是只会报通过

五项控制一次只改变一个因素，其余输入／规格／证明保持不变：

| 变化 | 必须观察到的拒绝 |
| --- | --- |
| 查表项 16 从 4 变成 3 | Coq 的实际查表性质证明失败 |
| 移位 3 变成 2 | 基础位图证明先通过，再在真实优先级表达式定理处失败 |
| 仅取消组／行一致性 | 先确认算法实际选 12，再拒绝“应选最小值 1” |
| 仅取消合法范围内非空 | 先确认全零状态选 0，再拒绝“0 位就绪” |
| 仅取消写权限 | 先证明实际 `store` 返回 `None`，再拒绝写入成功的声明 |

这些不是全部在源码哈希处提前拒绝。哈希检查用于防证据过期，语义控制用于检查具体义务，两者用途不同。
