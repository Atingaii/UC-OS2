# 第十五课：什么时候真正进入调度主体

接着上一课的两句顺序证明，这次看它们外面的两个条件：

```c
if (OSIntNesting == 0u) {
    if (OSLockNesting == 0u) {
        OS_SchedNew();
        OSTCBHighRdy = OSTCBPrioTbl[OSPrioHighRdy];
        /* 后面还有优先级比较、计数器和切换 */
    }
}
```

## 第一步：先看路径，而不是先看定理名

| 中断嵌套 | 调度锁 | 行为 | 本轮证明 |
| --- | --- | --- | --- |
| 非零 | 无需读取 | 外层条件为假，跳过整个主体 | 不需要锁资源，也不需要主体契约 |
| 零 | 非零 | 进入外层，但内层为假 | 保持完整前置资源，不运行前两句 |
| 零 | 零 | 进入主体 | 复用前两句证明；后续语句仍有开放义务 |

这里的“跳过”只指两个条件包裹的主体，不包括 C 函数外面的进入／退出临界区。

## 第二步：从内存字节算条件

`V293_guard_cell` 包含三件事：

1. 全局变量绑定到准确的字节地址；
2. 局部环境中没有同名变量遮蔽它；
3. 拥有该地址的只读字节资源。

`V293_guard_eval` 执行真正的表达式求值：读字节、转成 32 位整数，再与零比较。没有直接把“条件为真”塞入前置。

例如字节为 3，计算得到比较结果 0；字节为 0，比较结果为 1。框架用非零整数表示真。

## 第三步：看短路路径需要什么

打开 `certiucos/v293/proofs/V293OSSchedGuards.v`，找到 `V293_OSSched_interrupt_skip`。

它只要求外层字节非零，不要求读取调度锁，也不要求证明主体正确。这是嵌套 `if` 的实际短路性质。如果外层条件已经为假，内层不能成为这条路径的必要前提。

再看 `V293_OSSched_guards_rule`：只有两个字节都为零时，才使用主体的 Hoare 证明；任一条件不满足时，后置就是原前置。

## 第四步：为什么还有 suffix

`V293_OSSched_guarded_prefix_continuation` 把两个条件接到前两句上，但保留显式 `suffix`：

```text
前置 → 两个条件 → 已证明的两句 → suffix → 最终后置
```

老师要求的是实际程序正确，不能删掉尚未证明的语句后宣布整函数完成。这里 `suffix` 代表后面仍需连接的优先级比较、计数器和切换。它的 Hoare 证明是调用这个组合接口时必须兑现的义务，不是已经完成的结果。

## 第五步：排除“前置根本不存在”

新见证对任意两个 0–255 的嵌套值都成立，把它们放在块 11、12；查表、位图、当前任务、任务表和两个可写输出仍同时存在。因此不只是 0／0 的启用路径有见证，禁用路径也有。

复用上一课见证时，仅将其内部 helper 泛化到满足七个准确查找的环境；原稳定根类型不变。新环境中的七个查找逐个计算兑现。
