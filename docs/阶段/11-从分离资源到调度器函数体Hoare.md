# 第十一步：从分离资源到调度器函数体 Hoare

## 1. 上一步与这一步的区别

上一步已经证明：若各次实际读取成立、两处字节允许写入，执行两次赋值便得到正确结果。

这一步继续追问：**调用方凭什么保证这些读取和写权限？** 答案是把真实内存片段放进前置条件，再使用框架的赋值规则，而不是让调用方直接承诺整个表达式的结果。

## 2. 看懂三个符号

| 记号 | 含义 |
| --- | --- |
| `Amapsto address Tint8 false value` | 此地址存放一个实际可读字节；这里没有写权限 |
| `PV address @ Tint8 |-> value` | 此地址拥有可写字节 |
| `p ** q` | 两份可相容地分开的资源组合；不是普通逻辑“并且” |

环境绑定没有字节占用，所以用逻辑合取组合。输入表、输出字节、局部字节和当前任务资源则用 `**` 组合。这样，错误的别名／权限不能被当成两份独立可写资源使用。

## 3. 第一条赋值怎样证明

真实 C：

```c
y = OSUnMapTbl[OSRdyGrp];
```

证明链是：只读组字节和表字节 → 实际 `load` → 上一步的数组求值定理 → `assign_rule` → `y` 的新值。其余输入、全局输出旧值及 frame 保留。

对应代码：`certiucos/v293/proofs/V293OSSchedNewHoare.v` 中的 `V293_OSSchedNew_row_hoare`。

## 4. 第二条赋值与返回

第二次读取使用刚写好的 `y`，由两个就绪行字节和查表得到该行最低位，再计算 `8*y + bit`。证明连接真实表达式的整数提升、移位和字节窄化。

`V293_OSSchedNew_body_hoare` 将两次赋值接起来，并证明隐式 void 返回：返回值是 `None`，最高就绪优先级字节是合法就绪候选中的最小者。资源中的 `CurLINV` 是调用方真实提供的局部不变量，函数体不能随意丢弃。

## 5. 为什么还要构造一份具体内存

如果前置条件本身不可能成立，错误程序也可能拥有一条空洞的条件定理。

`V293OSSchedNewWitness.v` 实际构造：

- 256 个只读表字节；
- 两个就绪行字节 `0`、`16`，组字节 `2`；
- 可写的 `y` 和输出字节；
- 只读当前任务指针及一个合法的测试局部不变量。

`V293_OSSchedNew_spatial_precondition_witness` 证明整份空间前置可满足。不只是给出几条互相可能冲突的读取等式。
