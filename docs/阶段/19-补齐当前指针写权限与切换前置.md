# 第十九课：补齐当前指针写权限与切换前置

## 1. 接着上一课看同一个函数

`OS_Sched` 的不同优先级分支已经完成内部调用、目标指针赋值和计数器递增。本课不新增 C 修改，而是证明：走到这里时，满足框架切换规则要求的 `SWPRE_NDEAD`。

注意：“具备一项切换前置”与“切换已经证明”不是同一件事。

## 2. 为什么能读取指针，还不能写它

框架把一块完整写权限拆成两半只读权限：

```text
同一单元的一半只读权限 + 另一半只读权限 → 完整写权限
```

不是把任意两个指针拼起来，也不是复制资源。两半必须指向同一个全局单元，并具有一致类型。本课先从同一个全局环境中证明类型一致，再使用框架的权限合并引理。

`CurLINV` 原本只带一半 `OSTCBCur` 权限。我们在调用方的普通 frame 中预留另一半，让它穿过内部调用、赋值、条件判断和计数器更新，最后才合并。额外一半是明确的输入要求，不会凭空得到；完整程序未来必须交代它从哪里来。

## 3. 这次补全的表格

| `SWPRE_NDEAD` 要求 | 本轮从哪里取得 | 现在是否已证明 |
| --- | --- | --- |
| 目标确为最高就绪任务 `AHprio` | 同一状态的抽象任务表，加前缀已证明的最高就绪关系 | 是 |
| 所有中断服务均已退出 `isrclr` | 上一课内部契约保留的 `SWINV` | 是 |
| 目标全局指针拥有完整写权限 | 前缀真实指针赋值的输出 | 是 |
| 当前全局指针拥有完整写权限 | `CurLINV` 中的一半，加调用方预留的一半 | 是 |
| 当前任务仍在同一任务表中 | 当前任务与优先级关系；当前任务允许已经等待 | 是，仅非自删除路径 |
| 实际共享不变量与 `GoodI` | 尚须建立并连接真实内核状态 | 否 |
| 实际切换语句及抽象调度动作 | 尚须满足切换规则其余义务 | 否 |

## 4. 为什么没有把资源用两遍

输出接口使用逻辑合取：

```text
原来的前缀后置 ∧ SWPRE_NDEAD
```

它表示**同一个状态的两种看法**。不是分离合取 `**`，不会声称同时拥有两份任务表或两份完整指针权限。

切换前置本身含 `Atrue`，允许其余资源留在该视图之外。原始完整后置仍由另一视图保留。

## 5. 两个实际见证

新增见证中的当前指针，从一开始就是一个完整可写单元，再由框架规则分成两半。因此不是让两个互相冲突的权限前提假装可以同时成立。

- 相同目标：当前优先级为 12，当前任务也就绪。
- 不同目标：当前任务优先级为 4、已经时间等待，目标任务优先级为 12、就绪。

两个场景都允许任意合法的中断嵌套字节、锁嵌套字节和任意 32 位计数器值。它们使用空不变量、空中断栈、空临界区栈，仅证明完整局部入口可满足；不是启动状态可达性或真实 `GoodI`。

## 6. 下一步为什么仍是共享不变量

真正的 `switch_rule` 不只需要 `SWPRE_NDEAD`，还要求从共享部分得到 `SWINVt`，并正确分离调用方局部不变量、保留动态栈、衔接抽象调度动作。

不能把额外独立拥有的任务表，未经证明便同时塞进 `SWINV`，也不能因为“当前指针能写”就忽略其余资源。下一步要让**真实共享不变量**包含并联系这些共享资源，然后证明切换前后的保持。

当前任务已被合法删除的路径要单独使用 `SWPRE_DEAD`；本课的成员关系不能套用过去。


下一步按这个顺序施工，不要求你先回答问题：

1. **列资源归属**：逐一标出就绪位图、优先级表、抽象任务表、当前任务标记与当前指针，哪些放在共享不变量，哪些只属于调用方局部部分。同一资源不能重复拥有。
2. **建立并重组共享不变量**：把实际内存与抽象任务关系联系起来，证明关闭中断后可以打开、完成读写后能够重新封装；不能继续把整张任务表永久放在不变量之外。
3. **分离切换两部分**：共享部分满足 `SWINVt` 和 `SWPRE_NDEAD`，局部部分满足 `LINV` 与 `GoodFrm`，同时保留动态栈和准确的抽象 `sched` 动作。
4. **再接真实切换与函数入口／出口**：核对源码宏与框架原语的抽象边界，不能用任意 `suffix` 的假设冒充实现。之后还需完整函数环境、初始化与最终顶层定理。

每一步的验收问题都是“缺少这项资源／关系时，是否在对应义务失败”，而不是“新增了几个证明文件”。
