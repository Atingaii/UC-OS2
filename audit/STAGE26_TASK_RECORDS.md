## 需要修补的真实缺口

上一轮的 `CurTid` 读取权限位于标准指针存储块80，指向抽象 ready 任务 `(60,0)`；这不意味着 block60 已有物理 TCB。旧输入的状态字段实际缺失，本轮用 `RecordProbeOldInputMissingCurrent` 证明它不满足新增关系，不能给旧例子追授物理任务合法性。

新关系必须覆盖抽象任务表的**全部成员**，并穿过同一次执行；仅再次检查目标任务不足以补上该缺口。

## 最小证明链

1. `V293_task_record`：单个任务的优先级、行／列、两种位掩码与物理编码一致。ready 要求状态0和消息；时间等待另外要求延时；IPC 等待使用已有 payload 并关联同一事件指针。IPC 等待结果字节存在但不加入抽象任务表。ready 不约束延时。
2. `V293_task_records`：对 `get tasks t = Some (...)` 的每个成员量化；不是有限例子枚举代替一般命题。
3. `V293_task_record_frame`：整块逐字节权限／值相等保持全部选定字段的 typed load。
4. `V293_task_records_update_frame`：map 单点更新分为被改任务和其他任务。前者必须具有新记录，后者必须从入口真实记录和块 frame 运输。
5. `V293_critical_event_task_records_execution`：保留旧接口全部前提和输出，增加入口全称关系与其他任务块分离条件；仅调用一次旧完整执行根，消费其同一个 `Mf/Os'/OO'`。目标使用该次实际坐标写入、payload 和事件指针；其他任务使用该次写集合／locals 释放集合以外的完整块 frame。

不删除旧条件来换取结论。新增的其他任务分离前提是整块级的，**不覆盖多个 TCB 共用一个 block 的数组布局**。选定字段关系不是物理结构的所有权或分配合法性断言，也没有建立它与 `fullreadyinv` 的等价关系。

## 新输入与同一次完整返回

`RecordProbeMemory` 为 current 的 block60 安装五个优先级坐标字节、ready 状态和完整 NULL 消息编码。probe 重新建立入口 CurTid 读取权限、共享字段、表读取、可写性、局部变量、事件及调度条件；不调用旧 `OwnershipProbeExecution` 的完成结果代替新入口。

同一返回保留：目标 `(41,8)` 优先级8→6，仍等待同一个信号量，delay1、非空消息 `(120,7)` 和等待结果0不变；current `(60,0)` 优先级4、ready、NULL；ready16/0不变；事件位图0/1→64/0，SEM类型3、计数0和NULL不变；返回0、caller恢复及locals释放。现有 CurTid／共享字段空间组合与新全称物理字段都指向同一个终态。

run／ISR／lock 为1/1/0，实际调度调用仍受ISR阻挡。不授正常无锁切换或初始化可达性信用。
