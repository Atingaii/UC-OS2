# 第二十五阶段：物理共享存储与真实递增／切换尾部

## 固定对象与决策

对象仍是固定 uC/OS-II V2.93.01，源码身份 `74390755cddc42a391055da46b744bbf32e77ba3dc025c2ae55b9441ba6170da`。`OS_Sched` 定位 `Source/os_core.c:1702–1732`，配置后函数体 SHA-256 `4bbf6819f5a458dfdadb30dbc8aeaad5156553b98f1b6466d4b89054cbd965e9`。基线提交 `a0c636f89ff7d5fa63d9171e5a7663285da256ad`；冻结 C、配置、两类补丁、框架／策略和旧正式 JSON 均不修改。

stage24 已给出规范化调度片段，但计数器、位图等真实全局资源仍按片段局部 frame 保留。其局部定理不等于实际其他线程执行后共享值不变。本轮选择最小纵向闭环：先把计数器和参数化的有类型物理单元列表纳入现有共享核心，证明实际模递增后归还资源，再真正应用普通 `switch_rule`。不重写 scheduler，不以线程私有 frame 隐藏共享存储，也暂不改动所有旧前缀。

## 资源和真实动作

`V293DispatchStorage.v` 中的 `V293_storage cells` 是固定地址／类型列表的分离合取。每个单元都要求存在一个类型正确的值和完整写权限，空列表恰为 `Aemp`；不包含任意内存 frame。证明其精确性、ISR／辅助状态变化稳定性，并构造含现有唯一抽象核心、目标单元和这些物理存储的 `V293_storage_inv`。打开／关闭、两半当前指针合并、真实 `OSTCBCur` store 与抽象 `curtid` 同步更新的保持均闭合，最终得到四项框架 `GoodI` 条件。

`V293OSSchedStorageTail.v` 保持同一实际递增 AST 和真正普通切换原语。入口具有 pending `sched;;aop`、打开的共享核心、第二半当前指针、动态栈、完整计数器 `c` 和额外存储；环境绑定与真正私有 `px` 单独作为 frame。

- `V293_storage_tail_increment`：实际递增后的中间断言精确为 `Int.add c Int.one`，不添加“不溢出”前提。
- `V293_storage_tail_return`：把计数器／额外物理存储及其他共享资源封回 `SWINVt`，不丢弃资源，不把同一完整单元同时保留在 frame。
- `V293_storage_increment_switch`：由同一实际资源推出 `SWPRE_NDEAD`，真正应用 `switch_rule`，消费调度动作；恢复后只保留 `aop`、`SWINVt`、原线程动态栈、环境绑定和合法私有 frame。

恢复后不固定共享计数器值。该改变不是弱化既有承诺来制造通过，而是为真实共享归属另立准确接口；旧片段定理及其原证据保持原样，新链不声称继承它们的跨线程值稳定性。

## 同状态完整尾部入口

`V293_storage_increment_entry_witness` 构造一个实际状态，包含完整 pending 动作、两半当前指针、唯一四抽象槽位、完整目标单元和任意 32 位计数器，以及对应环境绑定、空栈和空私有 frame。覆盖当前 ready／同目标和当前时间等待／不同目标，事件表、时间及后续动作任意。

该 fixture 明确实例化 `rest=nil`，**不是所有全局布局、完整前缀入口、初始化或可达性证明**。一般定理允许额外单元列表，但本轮没有给出所有真实全局变量的布局实例，也没有证明物理位图／优先级表／TCB／ECB 与抽象任务表的关联。

## 独立接口与单因素控制

新检查器 `scripts/v293-scheduler-storage.py` 用独立字面定义固定 typed storage、四抽象槽位、共享标志、目标单元、尾部入口和恢复后置；不由候选类型打印生成预期。六个公开根的类型、实际假设和 `coqchk` 都单独检查。静态记录校验还将假设元数据与实际根输出重新比对，不能通过删掉假设列表伪装更强信任基础。

本机 `audit/logs/stage25/PROTOCOL.txt` 在负控运行前登记因素及澄清；其他资源、AST 和旧证明保持不变。

| 控制 | 唯一契约因素 | 指定观察 |
| --- | --- | --- |
| `storage_omitted_only` | 仅把返回共享不变量的物理存储从 `cells` 改成 `nil`，入口不变 | `V293_storage_return` 拒绝；不计下游信用 |
| `increment_omitted_only` | 仅将精确中间递增根的 AST 改为类型正确的 `sskip None` | `V293_storage_tail_increment` 拒绝；不计最终切换信用 |
| `frozen_counter_post_only` | 仅在最终恢复后置额外索要旧 `c+1` 的完整计数器单元 | `V293_storage_increment_switch` 拒绝；不计未执行义务信用 |
| `extra_false_only` | 仅给最终根增加 `False` 前提及引入 | 三个新模块先编译成功，再由固定最终接口拒绝 |

第三项同时暴露额外私有所有权问题：共享不变量已经拥有完整计数器，再索要一份完整单元不是单纯的数值观察。因此它是**非法恢复后置的契约敏感性检查**，不能单独证明“只固定数值、不重复所有权”的另一规格不可证。第二项观察精确中间后置，不把最终存在值后置当作递增发生的唯一判据。

指定拒绝须同时满足退出 1、Coq `Error`、准确文件及声明到 `Qed` 的行范围；成功、超时、警告或较早位置失败均不计。控制用于检查固定证明／接口的敏感性，不声称每个被改规格绝对不可证明。

## 对抗性复核

- **是否仍把共享存储藏进私有 frame？** 最终 frame 只有环境绑定和参数 `px`；实际计数器／额外列表显式关闭到新 Inv。固定接口独立展开完整资源。
- **是否在归还前丢掉精确递增证据？** 精确中间根仍对任意 32 位值证明实际模加一；归还才将值存在化。无递增控制针对该中间根。
- **`GoodI` 是否就是完整物理内核不变量？** 不是。它满足框架的结构与普通切换保持条件，但不含全部真实数据关联。
- **入口是否为空前置？** 同一具体状态同时满足整个新尾部入口；额外列表为空这个范围限制显式保留。它不建立实际初始化可达性。
- **是否已经接回上轮前缀？** 没有。stage24 的完整前缀使用旧 `V293_dispatch_inv`，本轮尾部使用新 `V293_storage_inv`；尚未在同一新核心下重组并连接。
- **是否解决了 port 的 `OSPrioCur` 同步？** 没有。框架切换写 `OSTCBCur`，不能据此凭空声称真实 port 同步了当前优先级。本轮仍接受源码级抽象切换边界，不扩展为硬件验证。
