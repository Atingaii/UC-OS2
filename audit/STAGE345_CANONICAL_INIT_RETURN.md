# 第345步：完整优先级表接入连续TCB初始化／返回

## 本步解决什么

第344步能清空完整表，也能执行两个hook之间的写表语句，但有限写表例子没有分配表中指针所指的TCB记录。本步沿已有真实TCB初始化前缀至返回的连续模型执行，把完整13槽表和更新后的物理任务记录放到**同一个返回堆**上。不重复一份表资源，也不把纯映射更新当作抽象执行。

生产稳定接口为 `V293_OS_TCBInit_canonical_return_under_hooks`，位于 `certiucos/v293/proofs/V293CanonicalInitReturn.v`。复用已有纵向执行定理，而非另造初始化内核。

## 怎样连接

1. 从完整表中暂取即将写入的第p槽，保留其余12槽的所有权及原字节偏移；`V293_priority_hole`只描述这个缺口，没有另外复制资源。
2. 将其余槽作为frame传过原TCB字段初始化、两个CPU hook、优先级表及链表发布、返回和局部对象释放。
3. 在同一返回堆上重排资源，把更新后的p槽和原其余12槽重新组装成完整表所有权。
4. 同时取得双向初始化表关系、更新后的canonical任务记录及其他发布资源。完整表和任务记录通过分离合取共同持有，不是分别存在于两个不同返回堆。

## 有限物理入口与读回

独立探针 `audit/probes/V293CanonicalInitReturnProbe.v` 分配旧任务的7个canonical字段、新任务待初始化字段、13个表槽、真实参数及发布链槽。新旧TCB位于同一block的不同字节区间；哨兵为77。

- `CIRLiteralEntry`：正负两种物理入口都真实满足原始单元所有权，无hook假设。
- `CIRSpatialEntry`、`CIRPrefix`：正例物理入口非空，并无条件执行至第一个hook调用入口；不是无条件执行完两个hook。
- `CIRGoodCall`：在**两个原hook契约**下，从同一物理入口连续返回、释放局部对象，并取得表／记录联合资源。
- `CIRJointReads`、`CIRJointCanary`：联合资源导出全部13槽的load、任务记录一致性以及哨兵load=77。

`CIRGoodCall`没有证明hook契约可由当前固定CPU端口实现兑现。因此没有声称无条件完整返回实例非空。7个canonical字段也不是完整TCB所有字段的强内核不变量。
