# 第324步：真实分配的延时调用接通调度和末端切换

## 解决的缺口

第323步的真实调用止于 `OS_Sched` 前，且原实例缺少调度器所需的物理资源。第320/321步虽有调度和切换证明，但入口环境、堆和调用帧不同，不能直接拼接其执行轨迹。

本步建立一个同时绑定 `OSTimeDly`、`OS_Sched` 和 `OS_SchedNew` 的程序，以及含双任务记录、查找表、物理优先级表、目标指针、缓存、计数器和canary的同一初始堆。参数、y和CPU局部块初始均不存在，由真实调用分配，而非在输入中预放已初始化的局部变量。

现在的闭环是：

`scall → 参数/局部分配 → CPU初始化 → 入口判断 → 进入临界区 → y首次赋值 → 清就绪位/写delay → excrit → 调度器调用/分配 → guard → helper调用/分配/释放 → 发布目标 → 比较 → 计数器自增 → switch指令前`

该前缀是原 `loststep` 局部闭包；随后在其真实末端堆上构造原框架 `lpstep` 切换，并单独证明同一阻塞后抽象任务表的原 `hswi_step` 选择相同任务。**局部前缀加末端全局一步，不等于整条调用的全局可达性。** 客户端堆与OS堆在全局分配规则中的边界仍开放。

不是完整 API，不是全局记录不变量，不是全局 ProgSim，更不是最终 `GOOD_OS`。

## 源码和范围

固定 uC/OS-II V2.93.01、上游提交 `0c4a48e6fbc6e915714e816196619a5481accf0c`、原配置和两类授权修复。独立重放脚本重新物化源码、应用修复并预处理三个函数，身份必须与第323步一致。六份函数快照及身份在 `audit/logs/stage324-time-delay-allocated-sched/`。本步不修改C、源码锁、覆盖清单、旧证明或旧冻结审计材料。

## 稳定生产接口

`certiucos/v293/proofs/V293TimeDlyAllocated.v` 导出 `V293_dly_allocated_to_sched_refines`：

- 输入：准确的延时函数绑定、三个新鲜局部块、明确的callee环境、调用前物理所有权和抽象任务/位图关系；不输入执行结果或最终store。
- 构造：实际参数与局部分配/初始化，消费未初始化y的首次赋值，再从该末端继续阻塞更新和临界退出。guard、encrit和y赋值均不重复执行。
- 输出：真实 `scall` 到调度调用前的轨迹、原抽象阻塞一步，同一末端堆的全部任务记录、逻辑优先级表、就绪位图及局部/guard/frame所有权。

通用所有权采用入口辅助状态快照；不把任意aux敏感frame搬入临界区。该接口的输入资源在明确callee环境中检查，不冒充已注册的caller环境Hoare契约。实际执行中的IE和临界栈变化独立由语义轨迹给出。

## 非空实例的观察值

`audit/probes/V293TimeDlyAllocatedProbe.v` 仅复用其他probe的资源工具、函数定义和抽象选择证明，不消费其他堆上的旧执行结论。

| 检查项 | 调用前 | 到switch前/原switch后 |
| --- | --- | --- |
| 当前旧任务 | 优先级4，ready | time-wait，delay=3 |
| 另一任务 | 优先级6，已ready | 仍ready；正例实际切换到它 |
| 参数/y/CPU块 | 三者均不存在 | 实际分配；参数3、y=0、CPU=0及4字节写权限 |
| 就绪行/组 | 80,0 / 1 | 64,0 / 1 |
| 发布优先级/目标 | 0 / null | 6 / ready任务的TCB指针 |
| 切换计数器 | 任意32位c | `Int.add c Int.one`，包含最大值回绕0 |
| 优先级缓存 | 4 | 仍4，不谎称已经同步 |
| canary | 99 | 99 |
| helper局部 | 尚未分配 | 真实分配后释放 |
| 旧任务continuation | 实际delay调用帧 | 保存实际调度/延时调用帧，尚未恢复/return |
| IE | 任意true/false | 调度临界区中false；栈保存原值 |

`DAallocated_run` 对两种物理表实例、任意计数器和IE构造真实局部执行，终点记录、位图、延时、局部槽及canary共享一个 `Mf`。`DAallocated_switch` 从正例同一堆构造原switch，保留全部记录和观察值。`DAhigh_switch` 使用相同阻塞后抽象表和精确continuation执行原高层切换。`DAboth_IE` / `DAwrap_run` 提供显式回归。

原switch只写current TCB指针，**不更新优先级缓存**。另一任务的环境/代码是明确给定的有限实例，不声称它们满足整核全局任务不变量或从boot可达。

## 预先登记的单因素消融

`protocol.json` 在新证明之前冻结。唯一变化：物理优先级表第6项从已就绪任务指针改成已阻塞旧任务指针。`DAonly_slot` 精确给出相同前9项、单个改变的cell和相同后缀；输入堆的其余部分及整个程序不变。

`DAwrong_target` 证明变异输入仍真正执行分配、首赋值、阻塞、调度/helper、比较和自增，直至原switch指令前；高优先级值6、记录/位图、计数器、参数/y/CPU、canary和helper释放均通过，只有发布目标不是要求的ready任务，被目标身份门**晚拒绝**。

负例仅局部前缀，不执行错误目标的全局切换，不声称变异物理表满足抽象优先级表关系或实现了成功调度精化。`DSmutant_outside_table` 明确证明该表不一致。局部阻塞一步可独立成立，不意味着之后的错误调度正确；正例的原低/高切换另有证明，不能以负例早期通过代替它们。
