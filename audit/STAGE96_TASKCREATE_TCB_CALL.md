# 第96步：任务创建实际调用、七实参读取与 err 接收

## 本步连接了什么

上一步证明的是 `OS_TCBInit` 的带入口快照函数体契约。本步沿着锁定版本的 `OSTaskCreateExt` 中这条真实 C 调用向上连接：

```c
err = OS_TCBInit(prio, psp, pbos, id, stk_size, pext, opt);
```

新的生产接口是 `V293_TaskCreateExt_TCB_snapshot_call`，直接使用既有模型 `V293_TaskCreateExt_TCB_call`，证明中实际应用 `calle_rule_lvar`。它不是无返回值 `call_rule`，也不接受“该调用已经成立”的 Hoare 前提。

调用者的七个局部变量由 `LV` 断言持有，每个值从全调用者内存的局部单元读出，依次为101／108／205／206／207／208／204。其中108是 `psp : Tptr Tint32`，不能误用被调用者中编号同为108的 TCB 指针。209是 `err : Tint8`；旧值允许 `Vundef`，调用后由返回值替换。七个实参单元及任意满足 `GoodFrm` 的额外调用者资源 `F` 保留。

### 两种参数顺序

`Rvl` 与函数规格签名采用 C 的实参顺序。旧 `V293_TCBInit_argument_types` 是执行／builder 边界所用的逆序列表，因此本步在调用处使用它的 `rev`。同类型的栈指针对即使交换顺序，仍可能通过类型检查，必须另外检查实际读取值。

## 快照、返回码与实际内存

函数规格直接使用第95步的快照规格，内部仍是精确的既有空／成功前后置。逻辑参数只携带入口 head，不增加 C 参数。生产证明从这两种精确后置导出 `retpost`，从真实外部资源中的 `R` 导出 `CurLINV`，并将入口与返回码的相关性带到调用者：

- 空入口对应 `err = 66`；
- 合法非空入口对应 `err = 0`；
- 外部资源按各自精确后置交还，参数及调用者 frame 保留。

探针在同一有限 `CallSpec` 中加入900号 TCB 初始化规格，同时保留501／502两项真实 CPU Hook 规格。被调用函数的真实 builder／函数体契约和调用现场 Hoare 都在这个相同规格表下检查；没有借用仅含 Hook 的另一个规格表来冒充连接完成。两个 Hook 仍是外部规格，不是已经验证的实现。

新的字节夹具为调用者构造独立的八个局部单元（701–708）和额外哨兵709，旧被调用者局部环境不被挪用。全局环境、池字段字节、当前任务资源和内核局部不变量显式复用第93步；这不是新的 C 翻译或跨阶段独立 oracle。空／非空入口的所有权和资源不同，不能宣称只改 head 即可互换。

## 单因素控制与反例

预先冻结的控制仅交换表达式108／205，内存、类型列表、预期值和证明体保持相同。使用两个不同的栈指针801／802使这一错误可观察，另有正式定理证明交换后读取的就是交换后的值，并拒绝把它解释成原顺序。这个辅助表达式夹具与有限 Hook 实例中使用的 NULL／NULL 栈参数不同；它隔离的是参数读取顺序，不证明完整调用的执行或所有下游机制。

后置的物理 `err` 和哨兵读回用于检查资源确实位于真实地址，不只检查断言文本；空支返回内存可满足性不等于存在调用分配／回收执行轨迹。
