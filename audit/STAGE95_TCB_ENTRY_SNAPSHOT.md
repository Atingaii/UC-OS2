# 第95步：把真实入口链表头保存到标准函数规格

## 为什么继续改规格

第94步的统一后置允许“失败66／原资源”或“成功0／发布后资源”，但忘记了入口属于哪一支。它不能单独支持调用者作出“入口空则返回66”的判断。本步没有修改该旧契约或旧证据，而是增加带入口值快照的精确接口 `V293_OS_TCBInit_snapshot_internal_contract`。

快照放在框架已有的逻辑参数中，形如 `[logic_val saved]`，不是新加的 C 参数或 Boolean 分支选择器。空值快照采用既有空支的前后置；指针快照采用既有成功支的前后置，并在两端保留 `saved = Vptr(bt,Int.repr base)`。其他类型、缺失或多余逻辑参数产生 `Afalse` 入口，而不是让 `BuildPreI` 返回 `None`。类型正确的实参依然由真实 builder 检查。

## 快照必须与内存一致

入口的真实 free-head 字节仍由原有空间断言持有。生产引理分别从空支的只读指针 cell 与成功支的原始 cell 列表导出 `load`，组合后证明保存的值就是入口物理 head，而不是调用者可以随意指定的标签。实际 builder 实例的全部参数／局部 cell 和精确声明域保留在外侧，load 的分离扩展由已有框架引理完成。

函数体证明没有新增 body Hoare、执行轨迹或读值 oracle 前提。空／非空两支直接使用既有精确契约；指针 guard 的真值从入口断言取出，作为逻辑事实保留到返回。七个参数、两个局部的返回资源仍完整交给 `BuildRetI`。

返回断言现在保留：

- saved 为 NULL 时，只能返回66；
- saved 为合法入口指针时，只能返回0；
- NULL／0、指针／66，以及无返回值都不满足相应后置。

这些是已证明 Hoare 契约及后置断言的性质，不是独立的终止性结论，也不由后置可满足性推导执行存在性。

## 验证与消融边界

探针明确复用第93／94步冻结的字面字节夹具；没有声称是新翻译或跨阶段独立 oracle。两个入口仍有不同的局部布局和实参，不能当作只修改 head 的执行实验。空支返回夹具继续只证明后置可满足，允许 builder 存在性隐藏局部值，不冒充精确的执行后内存轨迹。

本步另外检查：两类真实 builder、两种入口与返回可满足、公共契约的两种有限规格表实例、初始物理 head 读回、错误快照和不合格式逻辑参数的拒绝。旧统一后置可满足而新 NULL 后置拒绝同一成功返回内存的定理，直接展示没有保存快照时丢失的相关性。

预先冻结的单因素控制只把指针相等 guard 改为 `True`，其余字面成功入口、局部／参数布局、物理 head、错误快照和拒绝证明体保持。另有正式 Coq 定理证明中和 guard 后，原字面内存确实接受伪造快照。该实验只归因于指针 guard，不验证调用分配／释放、真实执行、所有下游机制或全局 invariant。
