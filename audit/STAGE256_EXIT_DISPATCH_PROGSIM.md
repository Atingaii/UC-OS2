# 第256步：接通 OSIntExit 的实际比较、计数和切换片段

## 本步改变了什么决定

上一检查点从当前优先级复制开始；本步把起点向前推进到真实的优先级比较：

```text
high != current
  → UINT32 切换计数加一
  → 原 skip
  → 当前优先级复制
  → 原 switch
  → 已独立证明的有限 client
```

生产稳定接口为 `V293_exit_dispatch_progsim`。它使用原 `ProgSim`，不是另造一个模拟关系。纯微步复用前步的进展、全部后继、无输出及无异常桥；计数存储另外使用存储后继唯一性。**没有从“一条 cstepstar 成功”推断“全部执行均正确”。** 相等分支另有 `V293_exit_same_progsim`，由原表达式求值和条件跳转接通。

## 真实起点与独立见证

`EPscheduled` 从原 typed `CGmemory OwnershipWaiting true 0 0` 实际执行 `OS_SchedNew` 和目标更新，得到 high=4、current=6、目标 Ready、计数仍为 `Int.mone` 的堆。不能使用已经加过一次计数的旧 `CGlocal_ready` 再加一次。

`EPactual_dispatch_simulation` 在这个堆上构造实际增量、复制和物理切换，证明 UINT32 从最大值回绕到 0；不附加“没有溢出”的前提。同一个 `HPpending = CGpending ## CGouter` 贯穿比较至切换，目标 client 仍有两条 skip，而不是把终止状态冒充可恢复任务。高层调度和该有限 client 的全局后续模拟分别复用独立的 `HPschedule`、`HPpost`。

旧 guard 的问题没有被抹掉：复制后的同一个堆上，`GHinv` 仍在任意分离 frame 下拒绝关闭；原存储不变量仍成立，允许原物理 switch。新桥组合整个片段，不改旧 `switch_rule`，也不强迫瞬态满足不成立的不变量。

## 预先声明的单因素对照

| 对照 | 固定项 | 仅改变项 | Coq 检查的结果 |
| --- | --- | --- | --- |
| 省略计数写入 | 同一增量前堆、相同地址／类型 | 不执行这次增量 | 旧值 mone 不满足新值 0 的精确存储后置条件 |
| 比较变为相等 | 原调度结果、代码、frame、高层状态、其他字节和计数 | current 的一个字节从 6 改为 4 | guard=0，走 SKIP；计数仍为 mone |

第二个对照还逐字节证明该地址之外的堆没有变化。两个对照不是同一项测试，更不能用条件分支的早期拒绝代替下游切换的检查。计数对照只说明存储后置条件，**不声称所有 client 的可观察 trace 都能区分这次写入**。

## 严格边界

- 原生产接口仍显式要求高层匹配和后续模拟；独立闭合的见证只针对该有限 client，不是任意 client。
- 区间保持 IE=false；不是任意中断交错的证明。
- 调度调用前缀已有实际执行见证，但尚未把其分配／局部环境改变纳入这条全局模拟。**存在执行不等于全局模拟。**
- 尚未证明切换后重新开启中断、释放局部变量、返回原调用者的完整路径。
- 沿用 ADR-0010 的显式源码级端口解释；没有补造汇编端口，也不是原始外部函数体的实现精化。
- 不是 `WFInt`，不是 `GOOD_OS`；K1–K4 未闭合，uCOS3 未开始。
- 固定 C/config/AST/framework、旧 Inv/LI/BDspec、旧证明、测试和冻结失败不改。未提交／推送。

真实编译、逐根依赖、递归 coqchk、构建和回归结果保存在 `audit/logs/stage256-exit-dispatch-progsim/`；最终数字见 `verification.json`。所有失败尝试按独立编号保留，不以最后通过覆盖失败历史。

下一条真正缺口是：将实际调度调用、局部环境的进入／退出与本片段接入同一条原 `ProgSim`，随后处理切换后完整中断返回。不能以继续增加独立示例替代这条纵向连接。

这个缺口不能直接套用本步的唯一后继助手：`salloclv_step` 使用的 `alloc` 量化新鲜块，允许不同的新鲜块，且会改变当前局部环境。下一步须对所有合法分配后继量化后续模拟，并通过更新 `les` 的原投影连接；不能只挑一个 block 的成功执行，也不能假设分配后继唯一。
