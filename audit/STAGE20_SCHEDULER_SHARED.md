# 第二十阶段：唯一共享任务表连接真实调度前缀

## 对象与边界

继续 V2.93.01 的同一调度链：`OS_Sched` 位于 `Source/os_core.c:1702–1732`，配置后函数体 SHA-256 为 `4bbf6819f5a458dfdadb30dbc8aeaad5156553b98f1b6466d4b89054cbd965e9`，冻结源码身份为 `74390755cddc42a391055da46b744bbf32e77ba3dc025c2ae55b9441ba6170da`。不改 C、固定配置、两项授权补丁、通用框架或允许假设列表；不使用旧内核专用证明树。

本轮把 **同一份共享任务表** 接回真实的内部调用和目标指针赋值。它不是新的独立调度小模型，也不是完整 `OS_Sched`、真实切换或 `GOOD_OS`。C 与 CoqImp 对应仍依赖既有受限受信任 AST 检查器，不是经过验证的 C 编译器。

## 为什么需要资源归属重组

stage19 的 `V293_shared_core` 已拥有 `abstcblsid` 任务表槽位；旧前缀在 `SWINV I` 外另要求同一槽位。若直接把旧接口的 `I` 换成这个非空不变量，会要求同一个独占槽位属于两块不相交资源，入口无法满足。不能通过新增表副本、把资源藏在不可满足前置中，或退回空不变量来绕过。

新模块 `V293OSSchedShared.v` 采取最小借还过程：

1. `V293_shared_snapshot` 用同状态合取 `//\\` 观察 `SWINV V293_shared_inv` 内的当前任务、任务表、事件表和时间。观察本身没有分配第二份资源。
2. `V293_shared_snapshot_open` 通过四个抽象槽位的取值唯一性确定隐藏值，交付中断协议、当前指针半权限和四槽位；`close` 把同一组值重新封装。
3. 只把唯一任务表借给已有 `V293_prefix_frame`。当前指针、抽象 `curtid`、事件表和时间作为可接受的 `GoodFrm` 余项保持；ISR／中断使能／动态栈继续放在内部契约中，不冒充普通 frame。
4. `V293_OSSched_shared_prefix` 经真实 `call_rule` 调用 `OS_SchedNew`，再经原目标赋值证明写入最高就绪任务指针；后置归还同一个 snapshot，原当前任务、任务表、事件表、时间和动态栈不变。没有 suffix Hoare 前提或整段前缀 oracle。

`V293OSSchedCritical.v` 的四个必要接口内部区分资源参数 `I` 与 ambient 规则参数 `RI`：实际 callee 契约打包 `V293_opened_inv` 的中断协议，但 `InfRules`／`WFFunEnv` 始终允许选择真正的非空 `V293_shared_inv`。`V293_opened_inv` 每槽为 `Aemp`，不占第二份共享核心。原五个稳定公共根的类型保持不变，仍作为 `RI = I` 的特例使用；未保留本轮不需要的额外 guarded 泛化。

## 同状态可满足入口

新见证模块从已有真实位图、优先级数组和完整可写当前指针的状态出发。把一个当前指针单元分成两半，分别交付 `CurLINV` 与共享核心；原来唯一的抽象任务表与新增的 `curtid`／事件／时间槽位经不相交 map join 组合，没有复制任务表。

`V293_OSSched_shared_precondition_witness` 构造整个新前置，并在同一个状态同时证明：位图与任务表一致、优先级表与任务表一致、当前任务成员／优先级关系，以及是否需要切换的两种模式。当前任务可以就是被选中的 ready 任务，也可以已经时间等待而选择另一个 ready 任务；事件表和时间值任意。

见证只证明可满足，不证明初始化或可达性。其动态栈为空，且当前任务仍在表中；stage19 的已删除场景没有因此自动连接到这个新前缀。

## 审稿式边界检查

- 新根只执行 `OS_SchedNew(); OSTCBHighRdy = OSTCBPrioTbl[OSPrioHighRdy];`。旧路径已证明的两层 guard、比较、计数器和 `SWPRE_NDEAD`，尚未按新共享资源归属重新组合，不能直接合并宣传为完整调用方。
- 物理位图和优先级数组确实在新前置中，与同一任务表有数学关系；但完整物理 TCB／ECB 链表、字段和资源池不变量仍缺。本轮只是借还核心，没有证明这些结构已被所有 API 保持。
- snapshot 返回原值不代表发生任务切换。实际共享／局部资源分离、抽象 `sched`、`switch_rule` 与 `switchdead_rule` 仍需连接；合法自删除不在新见证的成员前提内。
- `GoodI` 的 stage19 实例仍限于空 `LocalInv`，不因新根对 `GoodLInvAsrt li` 参数化就升级为一般私有资源回收证明。
- `OSCtxSw`／`OSPrioCur` 同步边界、临界区入口／出口、完整函数环境、初始化、最终源码级 `GOOD_OS` 与同程序 K1–K4 仍开放；uC/OS-III 未启动。
- 新增辅助检查根不增加函数覆盖；`OSVersion` 仍是唯一具有后续六门证据的函数，六门为 `94 / 1 / 1 / 1 / 1 / 0`。
