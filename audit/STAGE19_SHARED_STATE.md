# 第十九阶段：非空共享状态核心与 `GoodI`

## 对象与严格边界

继续固定 V2.93.01 的同一调度链。`OS_Sched` 仍位于 `Source/os_core.c:1702–1732`，配置后函数体 SHA-256 仍为 `4bbf6819f5a458dfdadb30dbc8aeaad5156553b98f1b6466d4b89054cbd965e9`；冻结源码身份仍为 `74390755cddc42a391055da46b744bbf32e77ba3dc025c2ae55b9441ba6170da`。不改 C、配置、两项授权补丁、通用框架或 stage18 既有稳定接口。

本轮是**非空共享指针／抽象状态核心检查点**，不是完整物理内核不变量，更不是完整 `OS_Sched` 或 `GOOD_OS`。源码对应仍采用现有受限受信任 Clang AST 工具，不是已验证编译器。

## 实现及必要性

新增 `V293SharedState.v` 与 `V293SharedStateWitness.v`：

1. `V293_shared_core` 拥有四个抽象槽位和 `OSTCBCur` 的一半权限，抽象 `curtid` 与该半指针关联。证明公共超状态下的精确性、`GoodInvAsrt` 和 ISR 状态稳定性，构造非空 `Inv`，而不是用空不变量替代真实资源归属问题。
2. `V293_shared_switch_open`／`close` 打开和关闭同一份共享资源；`SWINVt` 的额外半权限与核心内半权限一致，复用 stage18 `V293_current_halves_write` 合成可写指针，没有重复实现合并工具。
3. `V293_shared_store` 对真实 `store` 与 `set curtid` 证明保持；底层 `store_mapstoval_frame1` 保留其余物理资源，抽象槽位更新使用实际 map join/set。该证明不依赖 `GoodI`，避免循环 oracle。
4. `V293_shared_good` 证明框架的四项 `GoodI` 条件，允许当前任务仍在表中或已不在表中。删除分支仅针对显式选定的空 `LocalInv`，不声称可吸收任意任务私有资源。
5. `V293_shared_store_witness` 对任意当前／目标指针、任务表、事件表、时间值构造实际可写状态和实际 store 结果。`V293_shared_switch_cases_witness` 再给出当前任务时间等待和当前任务已删除两个具体场景；二者都有同一状态的最高就绪目标 `AHprio`，不以“空任务表中无最高就绪任务”制造第三项条件的空证明。

核心中任务表属于共享资源，不能再以旧前缀的外部任务表所有权重复持有。后续必须打开核心让前缀使用、再重封装；本轮没有声称已经完成这种前缀实例化。

## 预定消融与独立检查

| 单因素控制 | 指定检查位置 | 不变条件及解释 |
| --- | --- | --- |
| 仅移除抽象 time 槽位 | `V293_shared_fields_get` | 其余三槽位、指针、后续证明不变；早期拒绝只计该槽位敏感性 |
| 仅省略 store 后置中的抽象当前任务更新 | `V293_shared_store` | 物理写入、其余资源和目标值不变；在保持义务拒绝 |
| 仅把见证指针字节改成只读 | 核心先通过，`V293_shared_fixture_pointer` 拒绝 | 不用上游核心失败冒充见证检查 |
| 仅给 `GoodI` 根增加额外 `False` 前提 | 变异核心与见证先通过，固定 `checked_shared_good` 拒绝 | 保持原证明，新增参数未使用；独立类型探针不接受更弱接口 |

探针独立写出四槽位、核心、Inv 各槽位形状、空 LocalInv、双向打开／关闭、实际 store 后置和两个具体场景，不从候选根的类型生成预期接口。记录复核还验证拒绝发生的文件／行范围与 Coq 错误形态，不只检查退出码。

两次完整预检曾在移除 time 后因 `now` 类型无法推断而提前失败。该结果未计为消融通过；将正常定义的参数类型显式写出后，编译型预检命中全部指定义务。失败日志保留，不回写旧证据，也未放宽指定拒绝位置。正式验收与预检分离。

## 尚未闭合：审稿式反例检查

- 本核心没有真实就绪位图、优先级数组、TCB／ECB 链表和字段，也没有把这些内存与抽象任务表联系起来。`GoodI` 成立不等于实际内核不变量完成。
- 具体见证具有可满足状态与实际写入，但不证明真实启动可达性、非空中断／临界区栈可达性或全部 API 的保持。
- 合法自删除的状态见证不等于 `switchdead_rule` 已经接入源码；实际两种切换规则、抽象 `sched` 动作及共享／局部资源分离仍开放。
- 当前使用空 `LocalInv`；若未来任务拥有非空私有资源，删除路径需重新证明资源回收／合回，不能复用空资源结论冒充一般情况。
- `OSCtxSw` 是分析端口的声明边界，当前抽象切换只更新 `OSTCBCur`。真实 `OSPrioCur` 与 TCB 优先级关系纳入后，必须明确该边界如何同步它，不能只改变当前指针就假装该关系保持。本轮不修改分析端口或通用切换语义。
- 六门函数覆盖保持不变。六个新根是辅助检查根，不是六个已验证函数。完整函数环境、初始化、最终源码级 `GOOD_OS` 与同程序 K1–K4 仍开放；uC/OS-III 未启动。
