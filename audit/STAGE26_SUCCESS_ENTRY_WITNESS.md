# 成功返回根的同时入口见证

## 证明对象与本轮改动

继续固定 uC/OS-II V2.93.01 的源码级主线，不启动 uC/OS-III。活动源仍为 166 个（103 个框架／策略源、63 个目标源）。本轮仅在 `certiucos/v293/proofs/V293CriticalReturn.v` 追加 479 行：原 4107 行／264,621 字节逐字节保持，当前 4586 行／302,952 字节，SHA256 为 `fb8047b322b3b9207c3badfcd5570374ffe76c65615e85dfa01a1cdc056eea31`。

其他 165 个活动源和 12 项受保护输入不变，HEAD 不变，无提交或推送。冻结 C、配置、分析端口、框架、正式函数证据和覆盖清单未改。身份逐项核对见 `logs/stage26-success-entry-witness/identity-review.json`。

## 从条件定理到不空洞的实例

旧完整返回根要求原始内存同时满足参数、任务表、TCB、位图、局部写权限和分离条件。分别有局部夹具不意味着这些条件能在同一内存中同时成立。本轮增加：

- `V293_critical_null_success_return_witness`；
- `V293_critical_event_success_return_witness`。

两根只量化 `ir`、原 IE 和相关栈，随后存在一个最终 `Mf`；没有资源成立或执行完成前提。各自从其唯一原始具体内存应用对应完整返回根。两分支的原内存不同，不要求事件指针同时 NULL 和非 NULL。

SELF=255 实际解析旧优先级 8，新优先级为 6。入口 `ptcb=NULL`，四个坐标目标字节故意为 255。任务表槽 8 的原 TCB 迁到槽 6；TCB 字段实际更新为 6／0／6／1／64。ready 两行入口 **16／1**、组为 3，最终 80／0、组为 1；非空事件两行入口 **0／1**、组为 2，最终 64／0、组为 1。门禁 scope 简写中的 `ready and event rows=0/1` 指行索引 0、1，不能理解为两张表入口内容都为 0／1；以固定 probe 和定理中的数值为准。

全部 11 个局部块互异：9 个字节局部、2 个四字节指针，共 17 字节；原始内存提供完整写权限，包括旧返回尾额外需要的块 52。终态同一个 `Mf` 同时观察任务表、TCB、ready／事件、17 个已删除局部字节及三个 guard 全块保持。调用者环境具体取空、continuation 取 `kstop`。

`OSRunning=1`、中断嵌套=1、调度锁=0，因而真实调用 `OS_Sched`，但在 ISR guard 受阻。实际执行 return0、释放和 caller 恢复，不执行正常无锁选择／切换。

## 为什么不用整个内存的求值代替证明

三个 guard 字节落在独立块 100／101／102。新增 get／load frame 引理证明其他块不变，再运输原入口的具体资源和权限；只对有关地址做有界推理。追加的生产证明没有 `vm_compute`、未完成证明占位符或新公理。

旧轮超过 4.6GB RSS 的统一入口求值已中止。本轮开发第 02 次的求值再次超过 1.2GB RSS 后主动取消，退出 130，不授成功信用。随后改用 frame／权限引理，而不是放宽入口条件。

## 验证设计与证据归属

规范新门禁：`scripts/check-v293-success-entry-witness.py`，结果目录 `logs/stage26-success-entry-witness/gate02/`。工具结果以最终 `result.json` 为准，不能把 `result.partial.json` 当成已完成。

- 固定手写 `V293SuccessEntryWitnessProbe.v`，独立字面环境、数值、程序和后置；通过新根完成契约检查，但不是第二份独立证明。
- 临时冻结旧 4107 行前缀，另编完整、NULL、event 三种正控；不导入候选生产模块来代替其证明。
- 生产／旧 probe／新 probe 的实际重编，生产／新 probe 和完整正控的 `coqchk`。
- 两个 probe 根及三个正控分别打印实际假设，只允许既有 `classic` 与 `functional_extensionality_dep`。
- 前瞻冻结三个输出契约单因素负控：返回改为 1、要求保留局部字节、将最终事件首行中和为 0。各保留目标完整 Proof 后缀，要求在目标 Proof 内首次拒绝。

这些负控只检查固定证明对后置的敏感性，不是 C 修改、命题不可证性或所有下游机制有效性的证据。每项 `downstream_credit=false`，实际首次拒绝另行审阅。

旧完整返回门禁脚本不改，在本轮 `complete-return-replay/gate02/` 重放其 17 项检查和六个原有负控。旧 12 项测试的 31 个 assertion AST 不改，仅将当前全文件身份检查绑定到这次实际重放，冻结历史前缀检查仍读旧快照。原历史门禁和正式证据不覆盖，前瞻理由见 `evidence-binding-protocol.json`。

## 保留的失败与无效成功

`gate01` 在 probe 直接依赖导入问题被发现后主动中止，最终报告不通过；修正后新开 `gate02`，没有覆写失败结果。开发 01、03 的 Abort 诊断、04–08／11–12 的证明错误均不算已完成证明；开发 04 的临时占位符只在隔离开发文本中，未进入活动源码。开发 10 的生成器先以 ValueError 失败，后续 shell 却编译了上次遗留文件，其退出 0 不授新双分支成功信用。开发 13 才实际通过两个强化见证。所有快照、失败、取消和预检错误日志保留。

新增 **14 项测试通过，相关局部测试共 77 项通过**。完整 **827 项仍有 263 失败、1 错误**；264 个 FAIL／ERROR 标签与前轮 813 项按重数完全相同，无新增或删除。原失败没有删除或改成通过。详见 `new-tests-final.log`、`related-local-tests.log`、`full-tests.log` 和 `full-test-comparison.json`。

范围审计、冻结只读核对、增量 make 与文本 diff 检查通过。增量无需重建，生产源另有实际重编／coqchk；本轮不授 source-only 全量干净构建或旧函数完整门禁重放信用。默认正式审计仍退出 2，失败日志保留。

## 严格限制与下一步

具体物理入口存在不等于它由初始化可达或满足整核共享不变量。尤其，本例同时观察 ready 和非空事件位图，并未声称这已是一个合法整核等待／就绪关系。不能凭这个实例直接推出所有 API 的 Hoare 规格。

下一步将当前物理 ready／TCB／事件资源与调度入口的同一抽象任务表及共享不变量连接，再处理准确当前优先级缓存、源码切换对应和无锁调度。入口分配、完整函数环境、ISR／其他 API 保持性和初始化仍开放。显式临界宏抽象不是 raw port 或机器码验证。

正式六阶段覆盖仍为 **94／1／1／1／1／0**，默认 `make audit` 仍因旧正式证据身份过期退出 2。源码级 `GOOD_OS` 与同程序 K1–K4 未闭合，第一阶段未完成，uC/OS-III 未启动。中文入门见 [把全部入口条件放到同一内存](../docs/开发中/把成功入口的全部条件放到同一内存.md)。
