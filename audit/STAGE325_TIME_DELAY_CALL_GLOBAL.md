# 第325步：真实客户端延时调用到原全局切换

## 解决什么缺口

第324步已有真实局部分配、初始化、阻塞和调度前缀，以及末端原全局切换一步，但没有证明整个前缀从客户端调用开始就在原框架全局语义中可达。本步补齐这个边界，不用局部轨迹直接冒充全局执行。

固定目标仍是 uC/OS-II V2.93.01，上游提交 `0c4a48e6fbc6e915714e816196619a5481accf0c` 及原先仅有的两类授权修复。`source.py` 重放锁定源码预处理；`OSTimeDly`、`OS_Sched`、`OS_SchedNew` 三个函数的身份及六份片段快照与324一致。没有新增 C 修复，没有复用旧内核专用证明树。

## 从第一步看执行链

1. 开始只有 `scall 1200 [3]`，continuation 是 `kstop`，没有伪造外层内核调用帧。
2. 真实客户端语义完成三步：展开调用、求常量值、完成参数列表，抵达 `sfexec`。逐步从代码和 continuation 推出不是 OS 上下文，客户端环境更新等于原环境。
3. 根据 OS 函数表中的真实绑定进入内核。只有此时才产生真实 `kcall`，保存 OS caller 环境，开始使用 OS 堆。
4. 在 OS 堆真实分配参数、未初始化的字节局部 y、CPU 局部；写参数和 CPU 初值。三块在初始 OS 堆均不存在。
5. 从该真实末端执行 body：判断、进入临界区、首次写 y、清就绪位、写延时、退出临界区，抵达调度调用。没有重跑分配或初始化。
6. 在同一程序和演化堆中调用调度器及 helper，实际比较优先级、自增计数器，抵达 switch。
7. 从同一末端堆的写权限构造原 `lpstep` 切换，把它接到前面原全局闭包；另证同一抽象阻塞后任务表的原 `hswi_step` 选择。

`V293_dly_global_call_to_sched_refines` 是生产证明稳定接口：输入只有函数绑定、环境、初始资源、freshness、任务表/位图等条件；执行轨迹和末端堆都是输出，不是输入 oracle。它同时输出原抽象阻塞一步及同堆任务记录/位图/所有权。通用 frame 保留入口辅助状态快照；没有声称任意依赖动态 aux 的断言在临界区中保持。

## 客户端堆与 OS 堆不是一回事

新实例故意让客户端拥有块12的整数99，而 OS 初始块12完全 fresh，真实调用随后在 OS 块12写入参数3。客户端全局环境为空，OS 全局环境非空；客户端局部环境含标识符777，OS 初始 caller 局部环境为空。这里是语义中的两份独立堆，不需要假设它们 join 或地址不相交。

`DXdistinct_heaps` 在整条全局执行末端同时给出 OS 参数3、客户端整数99和不变的客户端环境。整个闭包使用固定 `DXclient`，而不是只比较首尾中的一个整数。

## 新证明与验证根

生产文件 `certiucos/v293/proofs/V293TimeDlyCallGlobal.v` 新增6个根，实例 `audit/probes/V293TimeDlyCallGlobalProbe.v` 新增12个根。全部18根由 `Print Assumptions` 和递归 `coqchk` 复核；允许的既有逻辑假设仅经典逻辑与依赖函数外延性，实际结果见 `trust.json`。

- `DXglobal_run`：无轨迹输入，从原始客户端调用到实际 switch 前。
- `DXglobal_switch`：整个原全局闭包加同堆最后原切换一步，保存旧 continuation、另一任务环境和 aux；保留全部记录、位图、延时、参数、CPU写权限、canary、helper已释放信息。
- `DXboth_IE`：两种初始 IE。
- `DXglobal_wrap`：32位计数器回绕到0。
- `DXdistinct_heaps`：两份堆中同编号地址的不同值均得到验证。
- `DXhigh_switch`：同一抽象阻塞后状态的原高层选择。单独的高层一步不是全局模拟定理。

Python新增8项检查负责身份、接口形状、实例连线、单因素边界、信任结果与历史不变性；它们不替代 Coq 语义证明。稳定生产/实例各重复编译两次。构建、原审计、全量回归及失败 ID 顺序比较均保存原始结果，独立 `verify.py` 全部通过后才产生本步 `verification.json`。

## 事前冻结的单因素对照

协议 `protocol.json` 在实现前冻结，SHA256 为 `d08aade9c987638cb04b48f0b112f19d7356a7681e63cc59452f759f0b0eeb58`。

只删除 OS 函数表中1200的延时函数绑定，其他函数、程序体、客户端程序、代码、堆、环境、资源均保持不变。

- `DXonly_binding` 证明只改变这一项。
- `DXsame_client_prefix` 证明正例和负例都能在原全局语义中经过同样三步，到同一个 `sfexec` 状态。
- `DXentry_gate` 证明正例存在真实内核入口 `loststep`，缺绑定时不存在该 OS 局部入口步；不预设负例 `InOS`。

**仅检验早期调用链接**，不把早拒绝当作下游分配、阻塞、调度和切换均已被消融检验。不声称负例原全局状态无任何后继；没有证明中断或客户端分支的全局停滞。这是明确有界的负例，不是整个调度器或安全性反例。

## 仍未完成的目标

本步是常量参数的有限、无交错正向可达性，**不是完整 API，不是全局记录不变量，不是全局 ProgSim**。还没有推广任意参数表达式或证明跨客户端/OS的 return 边界。

原 switch 只写 current TCB 指针，优先级缓存仍保存旧值4；没有把实际未发生的缓存同步记成成功。旧任务恢复、return、统一 WFInt、初始化、全交错保持、源码级 `GOOD_OS` 及同程序 K1–K4 仍开放。三函数六阶段覆盖仍只有 located=true；本步局部证据不自动提升完整函数覆盖。uCOS3 未开始，必须在第一阶段全部完成后依次推进，总目标保持 active。

历史基线有438个失败、1个错误，另有 `make audit` 的旧输入身份失配以及 `git diff --check` 六处旧空白问题。本步不修改旧测试、旧证据或验收门来制造全绿；实际计数及 ID 是否保持以 `verification.json` 为准，不以本段文字代替验证。
