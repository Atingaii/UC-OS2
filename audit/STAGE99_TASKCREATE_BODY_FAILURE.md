# 第99步：从任务创建原始入口接通空闲 TCB 不足的失败路径

## 这一步解决什么

第98步已经连接栈 Hook 调用、TCB 初始化调用以及失败清槽／返回66，但起点仍在任务创建入口前缀之后。本步使用同一个 `V293_CreateExt_body`，把真实入口前缀接到这条调用链：

1. 实际局部变量 `cpu_sr`（标识109）初始化为0。
2. 从优先级参数字节读取 `p`，检查 `p <= 12`。
3. 进入临界区，从实际全局字节读取 `OSIntNesting=0`，排除中断上下文。
4. 读取并确认 `OSTCBPrioTbl[p]=NULL`，写入真实静态预留符号地址，然后退出临界区。
5. 从调用者局部内存读取栈函数四实参，把返回值交给 `psp`。
6. 执行七实参 TCB 调用，空闲链表头为NULL时得到错误66。
7. 执行原始失败后缀：进入临界区、清空实际持有的优先级槽、恢复临界区栈、返回66。

核心接口位于 `certiucos/v293/proofs/V293TaskCreateBodyFailure.v`：

- `V293_OSTaskCreateExt_empty_body_hoare`：完整原始函数体上的受限失败路径。
- `V293_OSTaskCreateExt_prefix_hoare`：内部组合辅助定理；后缀证明由第98步已有接口实际提供，不是新增执行 oracle。

## 前提与保留资源

入口要求优先级合法、实际嵌套字节为0、可写优先级槽为NULL、可读空闲TCB链表头为NULL，以及所有实际参数／局部对象的分离所有权。中断在入口已经关闭。

CPU局部、嵌套字节、全局符号绑定和额外调用者 frame 在返回后保留。优先级与槽内存各持有一次，不重复字节所有权。`Rbefore` 与栈 Hook 返回资源 `R` 可以不同；入口临界区规则额外需要明确的 `GoodFrm Rbefore`，不能把 `GoodFunAsrt` 当作等价前提。

TCB调用仍使用原有同时包含空／非空两支的完整 snapshot 规格，而不是为失败路径另造更弱的被调用者规格。

## 组合时发现并修正的问题

原始前缀的预留成功分支后面仍有“优先级已占用”的错误语句。因此，任意会正常落出的后缀不能直接接到这里，否则还会执行该错误语句。内部组合接口要求后缀正常后置为 `Afalse`：本次后缀通过实际返回语句终止，不能落出。所有其他源码分支保留在原语法树中，只用实际 guard 及入口前提排除，不删除分支制造证明通过。

## 非空洞检查和单因素控制

探针 `audit/probes/V293TaskCreateBodyFailureProbe.v` 复用冻结的第93／96／97／98步内存夹具，明确扩展同一个 GE／LE，加入真实 CPU 局部与嵌套全局字节；既有名字的绑定不变。入口、返回资源以及同一有限规格表下的调用契约分别检查。

预先登记的控制只把预留符号标识97替换为98：两个符号类型均为 `Tint8`，但静态地址分别为901与902。两边使用相同完整入口内存、GE／LE、优先级、旧CPU值和后缀。比较点是实际前缀执行到后缀边界时的槽读回：正确地址应为901，错误实现写入902。

必须在清槽前比较。后续失败回滚会把两种预留值都清成NULL，若只测最终返回值就看不到差异。这项控制只验证真实前缀执行与符号身份，不证明外部栈算法，也不伪造整条外部调用链的执行轨迹。
