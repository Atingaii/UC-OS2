# 第103步：把完整任务创建函数体接到受限成功路径

## 本轮结果与边界

新增稳定接口 `V293_OSTaskCreateExt_success_body_hoare`：直接针对原来的完整 `V293_CreateExt_body`，连接入口检查／预留、四实参栈调用、完整 snapshot 七实参 TCB 调用，以及原始成功返回后缀。没有改写函数体或增加执行／后半段正确性前提。

这是**完整原函数体的一条受限成功路径**，不是所有路径或整函数环境验证：入口中断已关闭，合法优先级／任务上下文／空优先级槽，空闲 TCB 链表非空，`OSRunning=0`。栈初始化和两个 CPU Hook 仍是外部规格；成功侧标准 builder、活动调度、`WFIFun`、完整全局不变量与初始化仍开放。六门保持 `94 / 1 / 1 / 1 / 1 / 0`；`GOOD_OS`、同程序 K1–K4 未完成，uCOS3 未开始，总目标仍活动。

## 为什么要分开这一块内存

分离逻辑中的 `P ** Q` 要求两边的内存权限相容。不能既让入口前缀拥有优先级槽，又让 TCB 完整前置重复拥有同一个可写槽。

本轮只做必要的交接：

1. 入口前缀独占槽，初值 `NULL`；TCB 其余资源放在 `tl cells` 中。
2. 按实际语义执行检查，将槽写成预留对象的地址。
3. `V293_create_success_body_to_calls` 将**同一槽**与其余 cell 合并回完整 `pre_owned`，旧槽值精确为预留指针，不是任意旧值。
4. 栈 Hook 返回的同一资源增加真实参数／head 的纯事实，交给原完整 snapshot TCB 契约；完整 callee 后置、调用者参数、入口 CPU／nesting 字节、环境绑定和 frame 全部保留。

`globals` 含环境绑定和残余 `R`；`R` 可以拥有内存，不能误称整个 `globals` 都是空内存。取预留对象地址也不需要凭空分配或拥有该对象的数据字节。

## 从字面内存验证，而非只看定理名字

探针 `audit/probes/V293TaskCreateBodySuccessProbe.v` 复用此前冻结的 TCB 字节，不冒称重新翻译 C 源码。新增有限 GE／LE 与调用者字节，槽 `211+44` 从 `NULL` 真实写为 `721+0`。

- `SBLiteralEntry`：同一状态满足完整入口，量化任意 CPU 旧值／临界栈，以及旧任务链表为空／非空两种情况。
- `SBHoareChecked`：实例化本轮完整原函数体稳定接口。
- `SBSameSpecCallee`：同一有限 `SBSpec` 下检查 TCB 函数体；CPU501 的槽值也用预留指针，不能误用旧的 `Vundef` 规格。
- `SBPrefixExecution`：实际 small-step 前缀执行，并读回预留指针、保留完整前缀后置资源。
- `SBPrefixHandoff`：从实际执行后的同一状态取得栈调用所需资源。
- `SBHookResourcePostPreserved`：Hook 前后物理资源相同，只增加确实成立的纯事实。

具体栈返回 `NULL` 仅用于类型与调用连接见证，**不是有效初始化栈或端口算法证明**。本轮没有整个 Hook／TCB／后缀的 small-step 轨迹；完整成功路径的连接结果是 Hoare 推导。

## 前瞻单因素对照

`protocol.json` 在实现前固定因素：只改最终**期望槽值**，正确预留指针对照错误 `NULL`；源码、符号、入口内存、实际执行和 continuation 全部相同。

两项正式控制均先完成同一前缀执行定理和指针类型检查，错误组仅在最终槽 load 等式拒绝；`SBReservedSlotNotNull` 另行证明该实际读回不等于 `NULL`。它只检验前缀执行／交接观察，不能给未执行的 Hook、TCB 和返回后缀信用。

首次两项控制因缺少直接导入，在类型定理前失败，完全不计作指定负控。只向两组同时补充相同导入，旧快照／失败日志保留。检查器另修正 Coq `-time` 的括号格式匹配，没有改控制源码或接受条件。
