# 第109步（进行中）：NULL 槽预留、资源归还与栈 Hook 片段

## 前因与本轮决策

第108步覆盖入口 `IE=true` 时的两类提前拒绝，但共享资源池只允许非 NULL 优先级槽。因此不能用它证明真正创建任务的分支。本步保留计数字节的存在量化，将槽扩展为 `option addrval`：`None` 表示 NULL，`Some` 表示真实指针。写入前后的槽都能归还**同一个**物理资源池，调用者在临界区外不私有占有这些共享字节。

原 C、完整 AST、固定配置、既有证明和覆盖门均不修改。源码身份沿用 `audit/logs/stage109-taskcreate-enabled-slot-pool/source-identity.json`，`OSTaskCreateExt` 位于修复后逻辑源码的347–407行；逻辑源码由锁定上游与授权补丁重放得到，不伪称该 checkout 物理存在。

后两个定理是**NULL 分支内的连续源码片段**，不是完整函数契约。它们不接管从函数入口到 NULL 分支的全部并发控制流。Hook 仍是外部规格，不是已验证端口函数体。

## 为什么没有把截短程序当成完整证明

原函数的 NULL 分支后仍接着“退出临界区并返回40”的占用分支；真实 NULL 分支通过后续返回语句避免落入它。如果只把后缀替换为一次可正常结束的栈调用，再声称整个前缀正常结束，就会错误地继续执行占用分支。

本步没有删除这条分支、插入合成 return 或修改原 AST 来制造通过。探针中的原前缀执行只停在实际调用设置处，保留真实 continuation；它是无交错的局部轨迹，不是并发整函数证明，也不包含 Hook 的实际执行。片段 Hoare 定理与这条局部轨迹分别检查，不宣称二者已构成一个入口到返回的整函数契约。
