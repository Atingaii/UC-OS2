# 第二十四阶段：enabled 调度路径的抽象收尾

## 固定对象与最小增量

仍验证固定 uC/OS-II V2.93.01，源码身份 `74390755cddc42a391055da46b744bbf32e77ba3dc025c2ae55b9441ba6170da`。`OS_Sched` 为 `Source/os_core.c:1702–1732`，配置后函数体 SHA-256 `4bbf6819f5a458dfdadb30dbc8aeaad5156553b98f1b6466d4b89054cbd965e9`。不修改冻结 C、配置、两类补丁、框架／策略或任何旧正式 JSON。

stage23 的实际规范化链已连接比较、模递增和普通切换，但相等优先级分支仍有 pending `sched`。本轮不增加新调度模型，不重写实际 AST；只补相等分支的抽象自调度，再接回同一调用／赋值、比较／递增／切换和两层 guard。

## 证明与同一份资源

`V293OSSchedDispatchFinish.v` 在原 tail 上复用位图／任务表关系、唯一优先级表与当前任务关系。由实际选中的最高就绪者和优先级相等，推导目标指针就是当前线程，再从同一共享 snapshot 观察 `curtid` 和唯一任务表，证明 `sched_self`。没有额外“当前任务已最高”oracle。

为应用 `absinfer_sched'`，仅打开原 snapshot，将动作与全部资源分开。资源包括完整共享标志、第一半当前指针、四个抽象槽位、完整目标单元、另一半当前指针、动态栈和原 locals；`Atrue` 残余不丢弃。证明资源不依赖抽象动作后，消耗 `sched`，去掉 `END None`，再封回同一 `SWINVt`。不执行额外 C 指令或物理切换。

`V293_dispatch_change_finish` 通过 `abscsq_rule_full` 将相等分支收尾接回 stage23 真正比较／递增／切换定理；不同分支原样复用。`V293_dispatch_prefix_finish` 接回实际内部调用和目标赋值，`V293_OSSched_guarded_dispatch_finish` 接回两层真实字节条件。

| 分支 | 抽象后置动作 | 计数器 | 资源后置 |
| --- | --- | --- | --- |
| 任一 guard 非零 | 仍为 `sched;;aop` | `c` | 完整原入口 |
| 两 guard 为零、相同优先级 | `aop` | `c` | `SWINVt`、原动态栈、完整 locals |
| 两 guard 为零、不同优先级 | 原线程恢复时为 `aop` | `Int.add c Int.one` | 相同形状，不冻结共享任务表／事件／时间／目标 |

**跨其他线程执行后的全局计数器保证仍不成立。** 当前位图、数组、当前优先级、计数器及 guard 字节仍在片段独占的局部 frame 中；完整内核需要将实际共享全局资源纳入物理不变量，并调整恢复后置。相等分支没有发生线程切换，但不能借此跳过不同分支的资源重组。

## 完整入口与禁止调度的边界反例

入口类型与 stage23 完整见证一致，独立探针重新检查同一字面前置：两种任务模式、任意合法 guard 字节、任意计数器、事件表、时间和后续动作。复用现有证据而不是增加等价 fixture。

新增 `V293_locked_dispatch_deferred_witness` 在同一个完整入口状态中固定中断嵌套 `0`、调度锁 `1`、当前任务优先级 `4` 且时间等待，另一个优先级 `12` 的任务 ready；计数器、事件、时间和后续动作任意。证明该状态 `~sched_self`。它说明当前片段前置不足以无条件采用自调度规则，不能把所有“不切换”都等同于“已经选回自己”。

这只是完整片段入口可满足性和规格边界反例，**不是实际初始化／可达性，也不是已证明内核锁定路径发生错误**。最终可达不变量或更高层 API 规格仍可能排除该 fixture；本轮不臆造这些尚未证明的事实。也不将抽象 scheduler 改成允许任意 current，以制造统一后置。

## 前瞻单因素控制

本机 `audit/logs/stage24/PROTOCOL.txt` 在控制运行前记录精确因素、指定拒绝和不变部分。

| 控制 | 唯一逻辑变化 | 指定观察 |
| --- | --- | --- |
| `equal_pending_post_only` | 仅将 equal 根后置动作改回 `sched;;aop` | equal 根拒绝，不记下游信用 |
| `counter_condition_inverted_only` | 仅将完成后计数器选择条件取反 | change 根拒绝，不记下游信用 |
| `guard_false_premise_only` | 仅最终 guarded 根增加未用 `False` 前提及引入 | 核心和反例先成功，固定 guarded 接口拒绝 |
| `guard_entry_action_only` | 仅最终 guarded 根完整入口动作改为 `aop` | 最终 guarded 根拒绝，不记其他下游信用 |

控制检查现有证明是否兑现固定契约，并不声称所有被改规格在逻辑上都不可证明。例如保留 pending 的弱化式描述可能有另一种证明，但不是本轮承诺的调度收尾。固定接口探针仍要求真正消耗动作。

探针复用 stage23 **未改动的字面独立资源定义与完整入口见证类型**，追加本轮字面六根类型；不从候选定义／打印类型生成预期。正式记录哈希同时绑定两个检查器。每次控制只改变新文件的一个因素，保持实际 AST、旧证明和其他资源不变。指定拒绝必须是退出 1、Coq `Error`、准确文件及指定声明到 `Qed` 的行范围；超时、前置失败或其他位置拒绝不计成功。

## 对抗性复核与结论限界

- **相等分支是否偷加了最高就绪假设？** 公开接口仅接收原位图／任务表、唯一优先级表、当前任务关系和实际比较结果；最高就绪结论在证明内推导。独立探针固定这一类型。
- **资源或动作是否被悄悄丢弃？** 后置重封原共享核心，保留两半当前指针、完整 locals 和 `Atrue` 残余；固定接口要求 `aop`，不是只陈述“存在某个后置”。实际证明及依赖交由 Coq 和 `coqchk` 检查。
- **控制拒绝能否证明所有被改规格都不可证？** 不能。尤其 equal 控制在定向预检和正式重放中的实测都是后置空间蕴含未闭合，下一 proof bullet 触发 `[Focus] Wrong bullet`，并非不可满足性的证明。这些控制只说明固定证明／固定接口对指定因素敏感，不给未执行的下游义务信用，也不声称每个内部步骤都有独立消融证据。
- **锁定反例是否证明实际内核有错？** 不能。它只否定当前片段入口足以推出 `sched_self`；尚未给出该状态的初始化可达性。禁止调度的上层规格和可达不变量仍是开放义务。
- **统一后置能否直接用于整核？** 不能。全局资源目前仍按片段局部 frame 保留，必须重组共享归属并调整恢复后置；`OSCtxSw`／`OSPrioCur` 的源码对应也没有被本轮规则替代。
