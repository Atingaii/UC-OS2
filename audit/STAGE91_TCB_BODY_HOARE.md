# 第91步：把 OS_TCBInit 的两条路径接成一个函数体接口

## 先用直白的话说明

`OS_TCBInit` 创建任务控制块时，先读取空闲 TCB 链表：

| 实际入口 | 执行结果 | 本步统一返回断言保留的内容 |
| --- | --- | --- |
| 空闲链表头为 NULL | 返回 66，不执行两个 CPU Hook | 局部 ptcb 为 NULL、cpu_sr 为 0；原控制状态和失败分支 frame |
| 链表头为非空指针 | 初始化字段、两个真实 Hook 调用、写优先级表、发布任务，返回 0 | 既有成功返回断言的全部资源，包括链接、ready 位、计数以及剩余25个 cell 的 frame |

过去两条路径分别有完整函数体 Hoare。现在上层可以使用**同一个函数体、一个析取入口、一个精确区分返回码的出口**，不用自己重复拼接两份证明。它不是对两段不同程序的选择，也没有额外的 Boolean 参数充当分支选择器。

## 交付接口

文件：`certiucos/v293/proofs/V293TCBBodyHoare.v`。

- `V293_OS_TCBInit_body_hoare`：用框架 `disj_rule` 合并两个入口，用 `r_conseq_rule` 接到统一出口。
- `V293_OS_TCBInit_body_semantics`：由 `RuleSound` 得到相同完整函数体的 `RuleSem`。
- `V293_tcb_body_post_empty`：返回66时，统一出口与完整失败资源断言等价。
- `V293_tcb_body_post_ready`：返回0时，统一出口与完整成功资源断言等价。
- `V293_tcb_body_post_codes/no_other/no_void`：只允许66或0，排除其他码与无值返回。

成功资源直接复用旧 `V293_link_return_post` 在 `Some 0` 处的断言，其中自反的返回值等式是恒真，不丢失任何空间资源。该复用不新增程序效果或实现假设。

入口中两支分别拥有真实 NULL／非NULL 的 free-head。**两支资源集合和权限不同**：失败分支只需只读 head 和两个局部等资源；成功分支还需要字段、参数、优先级槽及发布资源。因此不能宣称本步证明了“只改变一个 head 字节即可把两类完整状态互换”，也不能把析取解释为所有可能机器状态的穷尽。

## Hook 与函数调用边界没有消失

统一定理为了覆盖成功路径，仍需两个调用现场特化的外部 `Spec` 查找，以及成功分支的 `GoodFunAsrt R` 条件。失败分支另外使用 `GoodFrm E` 和 `E ==> CurLINV`；不能随意把只对成功 frame 成立的条件套给失败 frame。

独立失败定理仍可用于全空 Hook 规格表。统一定理要求两个查找，不意味着失败分支实际执行了 Hook。CPU Hook 实现、统一全局 port 规格、调用分配／释放、整函数 `WFIFun` 及全局不变量仍未闭合。

## 验证及消融

独立探针不导入旧探针模块。字面资源实例包含：

- 同一 GE/LE、局部与全局地址、当前任务及哨兵下的可满足空／非空入口；非空入口覆盖旧 ready 链表 NULL 和非NULL两种情形。
- 任意入口临界区栈；初始化前相关字段和局部可为 `Vundef`。
- 两个有限外部规格查找与统一完整函数体实例。有限规格表不是 Hook 实现。
- 精确返回资源投影、排除 `None` 和65；失败路径无 Hook 规格实例保留。

前瞻单因素控制只修改**返回66对应的资源投影 empty→ready**；导入、前置断言、返回码、量化参数和证明体不变。先运行正控，通过后运行负控；信用仅限返回断言投影，不外推到 Hook 实现、终止性或整核正确性。

全部编译尝试、假设检查、活动模块内核复核、全量回归与清理记录保存在 `audit/logs/stage91-tcb-body-hoare/`。最终数值以该目录 `final-report.json` 为准；旧失败不删除、不改门槛。

## 剩余工作和目标

本步没有修改原 C、模型函数体、固定配置、两类授权修复、框架或旧冻结证据。已有两个 CPU Hook 仍为真实 `scall`，不是 `skip`。

下一个有实质意义的接点是：整理调用分配／局部回收与这个双分支 body 接口的资源对应，再推进可用于全局程序连接的函数规格。Hook 的全局统一与实现边界也必须保持显式，不能由两个单态查找伪造 `WFIFun`。
