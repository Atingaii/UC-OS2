# 第39步：OSTimeSet 接入真正的 API 前置／返回构造器

## 要解决的缺口

第38步证明的是已经分配好局部存储的函数体。本步不重写这个函数体，而是证明框架实际生成的调用前置条件足以进入它，函数体的返回资源也能回到框架实际生成的返回条件。

新增生产文件 `certiucos/v293/proofs/V293TimeSetAPI.v`，稳定接口为 `V293_TimeSet_api_contract` 和 `V293_TimeSet_api_rule`。函数包装声明一个 `Tint32` 参数和一个 `Tint32` 局部变量，函数体仍是既有 `V293_TimeSet_body`；抽象 action 使用真实参数，不是独立给定的期望结果。

## 连接链与本轮边界

| 接口／义务 | 本轮做了什么 | 不代表什么 |
| --- | --- | --- |
| 函数与规格定义域 | `EqDomAPI` 检查同一个函数编号、返回类型和参数类型 | 不是全内核函数环境已经齐备 |
| 真实参数列表 | 对所有 `vl` 分析真实 `dl_vl_match`，成功时必为一个 `Vint32`；非合法列表不进入契约 | 不是只证明参数42这一例 |
| 调用前置条件 | `Some pre = BuildPreA' ...` 本身作为输入，不用别名偷偷加强前置条件 | 不要求调用者提供时钟字节或成功 store 证据 |
| 全局名称可见性 | 从 `p_local` 所含的局部不变式取得全局名称事实，再由真实局部域推出没有名称遮蔽 | 名称绑定不是字节所有权 |
| 函数体 | 复用第38步真正 encrit／赋值／合法抽象 primitive／同 Inv 关闭／excrit／return | 不修改原 AST、C、配置和端口 |
| 返回条件 | 返回两局部对象对应的真实 `LV` 资源，符合 `BuildRetA'`；只移除零字节名称事实 | 不是本轮另证了一条独立具体分配／free／continuation 执行轨迹 |
| API 规则 | 构造真正的 `APIRule`，使用框架既有调用／返回健全性边界 | 不是全内核的完整源码级 component 链接或 GOOD_OS |

## 独立非空检查

`audit/probes/V293TimeSetAPIProbe.v` 不导入其他 probe。它使用字面内存布局：共享时钟块80、参数块81、保存值块82、当前任务指针块90、任务标识91，参数42。`TimeAPIActualBuilders` 直接证明写出的前置／返回条件就是实际构造器的结果；空参数、null、额外参数和重名局部声明被真正构造器拒绝。

局部不变式不是隐藏假设：明确选择只包含时钟全局名称的 `TimeAPILi`，证明 `GoodLInvAsrt`、`NoAbs` 及名称复制事实，然后实例化整个 `APIRule` 和实际 builder 对应的函数体契约。

`TimeAPICallerEntry` 证明具体调用者内存满足真正 API 前置条件；`TimeAPICallerLacksClock` 检查同一个调用者内存没有块80的任何字节。`TimeAPIJointEntry` 对任意旧时间证明同一份完整内存能同时满足共享核心和真实 API 前置条件；当前指针的两半读取权限由一份真实写权限经 `GV_separate_rw` 拆出，不是假设两个不相容内存都存在。

## 前瞻负控

实现前冻结 `audit/logs/stage39-time-set-api/protocol.json`：

1. 仅把 API action 的实参 `n` 换为 `Int.zero`。
2. 仅把函数包装里的 saved 局部类型从 `Tint32` 换为 `Tint8`。

两个控制保持全部 Proof、原函数体、共享 Inv、C 和其他源不变，分别检查真实 builder 与原函数体契约之间的连接是否拒绝。只授这一个连接的拒绝信用，不把共同的早期拒绝算作下游所有机制均已验证。

## 必须保留的开放项

- 当前 API 使用的非空名称局部不变式，不是第37步 GoodI 定理所用的空局部 fixture；本步**没有证明新局部不变式对应的 GoodI**，不能把两者拼成完整系统健全性。
- 入口限制仍为 IE=true、ISR 标志全部清零；没有所有 ISR 交错、完整任务资源生命周期或初始化可达性。
- 全局时间退出后可能再被其他任务／中断更新，不声称永久等于参数。
- 手工归一化映射不是已验证 C frontend；不新增端口、ABI、机器码正确性声称。
- 默认 audit 的 stale 身份失败、历史测试失败及六阶段94／1／1／1／1／0保持，不晋级覆盖。
- GOOD_OS、同一最终程序 K1–K4 和后续 uCOS3 仍开放，总目标继续 active。

下一步应先让共享时间 GoodI 与真实 API 使用同一个局部不变式，并连接当前程序的全局名称／初始化资源；不能直接用空 fixture 的 GoodI 冒充这一连接已完成。
