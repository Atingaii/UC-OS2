# 第339步：真实全局任务切换后调用源码时间接口

## 新增连接，而不是重复证明函数体

生产文件 `certiucos/v293/proofs/V293TimeReadyGlobalCall.v` 把已有两个已生成的完整时间函数调用证明接到框架真实 `lpstep` 任务切换。稳定接口为 `V293_time_switch_source_get`、`V293_time_switch_source_set`。

从旧任务持有的**原强时钟／就绪切换不变量**出发，构造物理当前指针写入与全局切换；被选中任务在任务代码表、环境表和辅助状态表中有明确绑定。随后从切换实际产生的同一个 `Ms` 开始调用生成函数，最终返回同一个被选中任务的环境，保留强 core 与当前任务资源，并释放两个局部对象。不把两个互不相关的满足堆拼成“连续执行”。

前提包括生成函数绑定、显式目标指针读取、当前指针及时间名字绑定、全块新鲜的局部块等，**不要求成功 store、成功执行或释放结果**。只为构造可写 store 临时忘记时钟；保持结果使用原始强不变量和同一个 store 恢复，不能用弱就绪资源冒充时钟保持。接口仍是条件于目标读取及任务表绑定，不证明调度器自己计算出该目标。

## 非空实例与边界

`audit/probes/V293TimeReadyGlobalCallProbe.v` 构造非空任务表：优先级4就绪任务与优先级6等待任务，各自的 canonical TCB 记录和原 bitmap16 保持。真实切换从不同的等待任务到就绪任务；所选任务环境、初始 IE、时钟和设定值均可量化。两个函数在同一生成的 `SRprogram` 中；返回恢复所选 IE，两个局部对象共八字节均释放。

为给原语的 offset0 目标读提供所有权，实例在**原关系没有约束的优先级表槽0**中额外放置就绪任务别名；槽4仍保持原正确指针。原 ready 关系只要求任务对应其优先级槽，并不反向约束未分配槽。本步没有削弱该不变量，但此别名实例**不是规范初始化表，也不证明从 OSInit 可达**。该选择事先记于 `fixture-plan.json`，不把满足性试验包装成调度器选择或系统启动证明；需要规范初始化／更强反向表关系时必须另外连接。

旧任务切换时持有的 flags 要求关中断；被选中任务的辅助状态可开也可关。传给时间调用的是与 IE 无关的 core，而不是虚假断言 IE=true 时仍满足关中断切换不变量。

## 事前单因素对照

冻结的 `protocol.json` 规定只改变抽象当前任务槽。`Gswitch_stale_current_control` 保持原程序、输入、真实切换、实际 `Ms`、所选环境、IRQ／IE／操作和物理时钟，仅把解释中的抽象当前任务保留为旧任务：

- 实际当前指针读取仍为新任务；
- 同一 `Ms` 用新抽象当前任务解释的强 core 通过；
- 同一 `Ms` 用旧抽象当前任务解释的强 core 被晚端拒绝；
- 当前指针之外的字节保持不变。

拒绝由独立物理读取和 core 抽象槽一致性矛盾推出，不是语法或链接早拒绝。它**不是运行时突变程序**，不能证明删除调度／写指针后的程序执行性质。未改变源码生成器，本步复用第337／338步冻结的源码对应，不把历史重放冒充本轮新鲜重放。

## 仍开放的整体义务

这里只有**一次全局切换 + 有限局部调用**，尚不是连续全局调用轨迹，也不是任意交错的 ProgSim、合法 ISR、启动可达性或完整全核程序。源模型不是经验证C前端，ADR0005 临界归一化与原框架任务切换边界不变。两个CPU hook仍缺实现，不通过增加编译器／硬件范围绕开源码目标。

最终 GOOD_OS、同程序 K1–K4 和 uCOS3 均未完成，总目标保持active。旧覆盖清单不改写，旧失败与冻结证据保留，不提交／推送。后续真正缺的是把所选任务的局部调用提升为同一全局程序轨迹，再连接全核接口、中断及非空初始化，而不是把此局部组合重命名为 GOOD_OS。
