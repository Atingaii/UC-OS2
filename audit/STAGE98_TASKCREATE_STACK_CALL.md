# 第98步：将实际栈初始化调用接到任务创建失败链

## 先用普通代码理解这一步

任务创建不是单独写一个 `ready=true`。它先检查优先级、预留对应槽位，再准备任务栈和任务控制块（TCB）。本步连接的是中间到失败返回的连续片段：

```c
psp = OSTaskStkInit(task, p_arg, ptos, opt);
err = OS_TCBInit(prio, psp, pbos, id, stk_size, pext, opt);
/* 实际原始 if 的成功侧也保留在语法中；本步入口选择失败侧。 */
if (err != OS_ERR_NONE) {
    OS_ENTER_CRITICAL();
    OSTCBPrioTbl[prio] = (OS_TCB *)0;
    OS_EXIT_CRITICAL();
}
return err;
```

上面的短代码只用于讲解失败路径，不是新增翻译；实际证明使用既有的完整 `V293_TaskCreateExt_calls` 和完整后缀，未把成功分支从程序中删除。

- `ptos` 是传给栈初始化的输入地址；`psp` 是它返回的地址，二者不能直接当成同一个值。
- `err=66` 在本入口来自 TCB 空闲链表为 NULL；不是由我们任意假设一个错误码来跳过 TCB 调用。
- 失败时必须释放自己拥有的优先级预留槽；否则后续创建同一优先级可能被错误拒绝。
- 本局部接口从中断已关闭的状态出发，临界区栈 `cs` 精确保留。不能由此推断任意开启中断入口已经安全。

## 新的稳定接口

生产文件：`certiucos/v293/proofs/V293TaskCreateStackCall.v`。

`V293_OSTaskCreateExt_stack_empty_failure_hoare` 在既有框架中依次连接：

1. 从调用者真实 `LV 201/202/203/204` 读取四个实参，检查 C 顺序及类型列表逆序边界。
2. 使用实际 `calle_rule_lvar`，把外部 `OSTaskStkInit` 的返回值写进 `LV 108`，不是把 `ptos` 直接作为 `psp`。
3. 从更新后的 `psp` 等七个局部读取 TCB 调用参数，使用第97步的同一完整 snapshot 规格。
4. 沿 TCB NULL 入口得到错误66，执行原始失败后缀的清槽、临界区退出和返回。

本接口不再要求上层提供这两个调用或失败后缀的 `InfRules` 作为前提；仍要求真实的规格表查找。失败侧预留值 `reserved` 与 TCB 成功规格旧槽值 `slot` 独立量化，不能暗中混同。七个 TCB 参数、三个仅供栈调用使用的局部、额外 frame、只读 NULL head 及返回后的 `R` 保留。

### 外部栈函数的边界

栈函数规格明确保存实际四实参，并限定返回结果；`Rbefore` 和 `Rafter` 可以不同。这样没有默默要求真实栈初始化完全不改内存：栈缓冲区可位于外部资源中，由将来的 port 契约描述。

本步没有虚构 CPU port 的实现，也没有证明栈初始化算法。主接口要求返回的栈值符合后续 TCB 参数类型；不证明该指针所指的完整栈布局或 ABI。任务入口沿用 ADR0007 的框架整数 selector，本步仅传递该值，不新增函数指针硬件语义。

## 检查夹具与单因素控制

新探针：`audit/probes/V293TaskCreateStackCallProbe.v`。

复用第93、96、97步的冻结字节夹具，明确扩展调用者环境，新增三个互不重叠的局部字节区。不是独立 C 翻译。TCB 被调用者函数体与新连接链在**同一个有限 `StackSpec`** 下检查；没有把 TCB 规格替换成只覆盖 NULL 的弱版本。

联合内存入口包含原八个局部、三个新增局部、预留优先级槽、只读 NULL free-head、全局当前任务与哨兵资源。探针把外部栈返回值实例化为 NULL，仅检验类型兼容的调用／赋值连接；**这不表示真实初始化后的栈可以为空，也不是 port 正确性证据**。生产定理对返回值一般化。

单因素控制在外部函数**已经返回**的调用者 continuation 上开始：

| 保持不变 | 仅改变的因素 | 实际结果 |
| --- | --- | --- |
| 相同字节内存、GE/LE、返回 NULL、旧 `psp=Vundef`、非空且不同的 `ptos`、类型、最终 `psp=NULL` 检查 | 接收变量 `108` 改为同类型的 `203` | 两者都走真实返回赋值／地址求值／store；正确接收者改写 `psp`，错误接收者只改写 `ptos`，`psp` 仍为 Vundef |

不能把这个控制宣传成缺失的 port 实现、调用分配／释放或整条任务创建路径的实际执行。完整失败调用链由 Hoare 组合单独检查；返回后真实赋值执行则单独提供正反字节读回证据。负控制必须到最终读回才拒绝，不用早期类型报错冒充下游赋值验证。
