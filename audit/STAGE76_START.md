# 第76步：OSStart 从启动前内存执行到 CPU 启动端口

## 要补的真实缺口

上一步 `OS_InitMisc` 的 Hoare 接口要求 frame 蕴含 `CurLINV`，但启动前不能无依据地假设已经存在当前任务。本步选择固定 V2.93.01 的 `OSStart`，证明实际调用 `OS_SchedNew`、设置当前优先级与任务指针，停在 CPU 启动端口入口；不通过预置当前任务来套用运行态调用规则。

这是一段必要连接，不是整核运行态不变量或 `GOOD_OS` 的替代品。完整初始化、真实 Hook、统一函数环境与同程序 K1–K4 仍开放，uCOS3 尚未开始。

## 源码和模型

重新物化固定修复后 C，由 Clang 提取配置后函数体，全部94函数身份与冻结清单一致。`OSStart` 位于 `os_core.c` 的869–878行，预处理函数体 SHA256：

`ace6a295a4176b3abbcb8cced0c44fa9af1a11d28b4b963dff565385f4d15f7c`

本步不修改 C、固定配置、分析 CPU 端口、原框架语义或旧证据。模型 [V293OSStart.v](../certiucos/v293/code/V293OSStart.v) 保留 `OSRunning == 0`、两个真实调用和中间三个赋值；隐式 void 结束显式表示为 `sret`。这是手工受审查的前端映射，不声称已验证 C 前端。

## 已证明的连接

### 1. 调度器真实调用，不要求已有当前任务

[V293OSSchedNewStartup.v](../certiucos/v293/proofs/V293OSSchedNewStartup.v)：

- `V293_OSSchedNew_startup_call`：从真实 `scall` 执行调用、分配局部 `y`、两次源码赋值、void return 和释放，恢复调用者，保留幸存单元。
- `V293_OSSchedNew_startup_fresh_call`：从实际有界内存和有限幸存集合构造新块，不把 fresh／互异块选择作为上层输入。

入口仍要求精确查表读取、合法非空就绪位图和可写最高优先级单元。这些是资源与输入关系，不是“已经执行成功”的前提；没有要求 `CurTid`、`CurLINV` 或 CPU Hook 路径。

### 2. 在同一实际内存写入三个字段

[V293Start.v](../certiucos/v293/proofs/V293Start.v)：

- `V293_OSStart_body_to_port`：真实 guard、调度器调用、`OSPrioCur = OSPrioHighRdy`、优先级表指针读取、`OSTCBHighRdy` 与 `OSTCBCur` 写入。
- 稳定接口 `V293_OSStart_call_to_port`：加上外层实际调用，保留尚待返回的调用者 continuation，抵达 `sfexec OSStartHighRdy`。
- `V293_OSStart_already_running_call`：当运行字节为1，完整调用直接返回，实际内存与调用者局部环境不变。不推广为已证明任意非零运行值。
- `V293_OSStart_highest_ready_call_to_port`：从位图／任务映射及优先级表关系推出实际读取的指针对应最高优先级就绪任务；不是先假定选出的目标满足调度结论。

端口前 `OSRunning` 仍为0。没有执行端口、修改抽象当前任务、构造真实全局 `Inv` 或调用框架顶层定理。

## 非真空实例与单因素控制

独立 [V293StartProbe.v](probes/V293StartProbe.v) 从字面内存构造入口：仅任务12就绪，两个当前任务指针初始均为 NULL，旧优先级分别为7和8；另有哨兵123。调用前不含调度器局部对象。

冷启动实例使用同一 `Mf` 得到高／当前优先级12、最高／当前任务指针、仍为0的运行字节、未变的表槽和哨兵，共7项类型化读取；也实际实例化最高就绪任务包装定理。fixture 的抽象任务映射只有任务12，未实例化真实任务记录／全局 `Inv`，更不是完整 `OSInit` 可达状态。

测试程序只有 `OSStart` 和 `OS_SchedNew`，`OSStartHighRdy` 查询结果明确为 `None`；因此结果必须停在入口，不伪造端口实现或完成返回。

控制在编译前冻结：

1. 保持入口、路径和证明体完全不变，仅将最终当前任务指针改为 NULL；正控通过，错误后置在预定类型核对处被拒绝。这只证明后置条件敏感性，不独立证明路径 safety。
2. 同一字面构造只改变 `OSRunning` 的0／1输入，分别实际执行冷启动到端口与热启动原样返回。它授 guard 分支及对应路径信用，不授端口、所有执行或中断交错信用。
