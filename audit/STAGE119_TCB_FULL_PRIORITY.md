# 第119步：完整 OS_TCBInit 函数体接优先级槽写入

## 本步解决什么

第118步已经证明首个 Hook 及其后的真实优先级槽写入，但使用的是只含 `prio`、`ptcb` 的小资源视图。本步把它接回第116步的完整函数体接口：入口仍有七个参数、两个局部变量及原调用者资源，不修改原 AST，也不把参数字节丢弃后再凭空补回。

生产文件为 `certiucos/v293/proofs/V293TCBFullPriority.v`，上层接口为 `V293_OS_TCBInit_free_body_after_owned_priority`。它证明的是**带显式前提的原完整函数体 Hoare 组合定理**，不是无条件成功或标准整函数契约：

```text
原入口 → 同 Inv 借空闲链 → 空头返回66／非空弹出
       → 归还尾链 → 原18字段写入 → 首个真实Hook调用
       → 同 Inv 借预留槽 → 真实优先级槽写入 → 归还新槽
剩余 Hoare 前提：第二个Hook → 原任务链及ready发布 → 返回0
```

空头返回66的后置蕴含、共享不变量开合、首 Hook 类型化契约和分配节点不等于 RESERVED 的实际状态条件仍是显式前提。不能仅因 Hoare continuation 减少，就把这些前提当成已经由生产系统提供。

## 如何保留七参数和两局部

`V293_tcb_full_priority_view` 与 `V293_tcb_full_priority_restore` 是同一状态上双向成立的资源蕴含，不执行指令、不改变内存：

| 资源 | 小视图期间的位置 |
| --- | --- |
| `prio` 参数字节、`ptcb` 局部字节 | 第118步优先级资源，恰好各一份 |
| 其余六个参数字节、CPU局部字节 | `V293_tcb_priority_caller_frame` |
| 七参数及两个局部的全部原环境绑定 | 调用者 frame；额外复制的仅是空堆的两个环境事实 |
| 已初始化节点及调用者 `R` | 原样保留，供第二个Hook与发布段使用 |
| 预留槽 owner 半权限 | 首Hook后临界区内与池的另一半合并，写入后交还原 Inv；不在后置中残留 |

`GoodFunAsrt` 只用于跨 Hook 的资源；包含 `Alvarenv`／`A_notin_lenv` 的绑定放在 `GoodFrm` 调用者 frame。这样没有把依赖调用者局部环境的断言误当成函数环境无关资源。

freshness 的形式是：**若某个实际完整分配后状态满足前置，则该状态选出的节点不等于 RESERVED**。它不是错误的“所有指针都不等于 RESERVED”，也不是要求非空堆满足独占空堆的纯断言。生产分配器如何保证此条件仍待证明。

## 非空实例与消融检查

`audit/probes/V293TCBFullPriorityProbe.v` 使用真实非空字节堆，包含七参数、两个局部、完整初始化节点、调用者保留值、真实全局优先级表绑定；另一个实例加入 RESERVED owner 半权限。两个实例都通过完整视图→小视图→完整视图检查；实际优先级读取和 `ptcb` 实参读取也有独立证明。

单因素对照在生成控制源之前冻结计划：固定物理内存、全局绑定、`prio`／`ptcb` 绑定、期望地址及最终脚本，只增加一个 `Tint8` 的局部变量92来遮蔽全局数组92。正常组得到表403的偏移20；遮蔽组得到 `None`，先通过共同输入检查，再在错误的地址期望处失败。正向定理 `TFShadowDiffers` 同时证明观察不同。

该对照仅判别**类型化数组地址解析**。共同完整入口检查针对未遮蔽的固定状态，不声称遮蔽后的状态仍满足完整绑定断言。它不是 Hook 执行、完整函数执行或生产不变量的可达性检查。非空实例也没有实例化整个条件函数体定理的全部前提。
