## 为什么不能照搬旧 Hook 快照

旧接口固定在关闭中断、私有持有共享数据的快照上，不能直接套用当前路径。本步只分离必要资源：

| 所有者 | 资源 |
| --- | --- |
| Hook 契约 | 已初始化的完整私有节点、Next及未写字段、OS状态、调用者提供的环境无关资源R |
| caller frame | ptcb/CPU局部单元、七个参数单元、局部及全局变量绑定 |
| 原共享Inv | 共享head字节和剩余空闲链表；不进入Hook契约 |

callee 满足 `GoodFunAsrt`，caller frame 满足 `GoodFrm`；双向分离视图保留所有资源。真实参数通过 `evar 108` 的局部绑定及物理指针单元读取，不把预期指针作为求值前提。

契约只使用一个有限 `Spec` 条目。动态节点指针与 Next 通过两个 `logic_val` 实例化；没有为每个节点要求不同的 `Spec` 条目。

## 非空实例与单因素对照

`audit/probes/V293TCBEnabledHookProbe.v` 使用原 `FPInv`，构造真实已初始化节点、局部变量、七参数和保留值的字节内存；它与共享head及尾链实际分离并满足同一中断不变量。另有原字段段的真实初始输入和闭合调用片段。

`EHAdmitsExact` 在同一个可满足的物理输入上证明返回契约恰好要求：指针为 `FPHead`、任务为 `FPTid`、结果为 `None`。正常对照编译成功；仅替换指针、仅替换任务、仅替换结果的三个对照，都先通过共同输入和实际实参检查，再在各自最后一个错误期望处失败。三项正向拒绝定理另行编译成功。

这些只说明契约身份判别，不说明 Hook 的实现已执行、更不说明整个 API 的变异测试通过。实验计划在控制源生成前写入。首次运行因文件系统时间粒度令 plan/source 的 mtime 相同，被过严的时钟比较阻止；没有开始 Coq 控制实验。保留初版脚本和诊断，续跑复用原计划、原源和相同预期，没有重写冻结证据。
