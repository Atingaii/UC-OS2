# 第十三阶段：内部调用与任务指针赋值的顺序 Hoare

## 固定对象与结论边界

对象仍为冻结的 uC/OS-II V2.93.01，身份为 `74390755cddc42a391055da46b744bbf32e77ba3dc025c2ae55b9441ba6170da`。C 源码、固定配置、两项授权补丁、框架和历史 JSON 不变。

本阶段只证明 `OS_Sched` 未锁定分支的前两句：

```c
OS_SchedNew();
OSTCBHighRdy = OSTCBPrioTbl[OSPrioHighRdy];
```

这是**源码绑定的两句顺序 Hoare**，不是整个 `OS_Sched`，更不是 `GOOD_OS`。沿用上一阶段对整个配置后调用方 AST 的核对及两句精确发射，不将 AST 核对冒充整函数证明。

调用位置仍为 `Source/os_core.c:1702–1732`；源文件 SHA-256 为 `96eef5dc1a519887499cffd8f9a6c8873b96978ed9646c42e52eb6992422fea5`，配置后函数体 SHA-256 为 `4bbf6819f5a458dfdadb30dbc8aeaad5156553b98f1b6466d4b89054cbd965e9`。

## 三个稳定根

| 根定理 | 已建立的接口 |
| --- | --- |
| `V293_OSSched_target_assign` | 用真实 `assign_rule` 写入最高就绪表项的指针；保留内部后置、同一抽象任务表、只读输入及任意调用方 frame |
| `V293_OSSched_unlocked_prefix_hoare` | 用真实 `seq_rule` 接合已有内部 `call_rule` 与上述赋值；后置得到某个最高就绪任务及指向它的可写输出单元 |
| `V293_OSSched_prefix_precondition_witness` | 构造同一状态中的整个两句前置；就绪位图、抽象任务、13 项指针表、全局绑定、当前任务指针、可写优先级与可写输出指针共同可满足 |

`V293_prefix_selected_load` 从内部调用资源直接推出优先级字节的真实 `load`。读取表达式复用上一阶段 `V293_OSSched_target_task`，不把表达式的计算结果直接当作前提。

组合根不假设“选中结果最高”；它从全称位图／任务、任务／指针表关系推导该结论。赋值辅助根接收选中表项相等关系，组合根使用 `V293_ready_selection_task` 在内部兑现它。

前置中的任务关系以及准确内部规格查找，仍是未来完整共享不变量和内部环境必须建立的条件；本阶段没有消除这些义务。后置保留同一 `Aabsdata abstcblsid (abstcblist tasks)` 和任务最高就绪性质，不声称真实 TCB 字段已连接。

## 整个前置的具体见证

见证包含单个优先级 12 的空闲任务；位图两行为 `[0,16]`，组为 2；第 12 项存该任务指针。优先级输出初值为 0，任务指针输出初值为空。callee 的局部字节不放进调用方 frame，由既有内部调用构造器负责。

| 块 | 内容／权限 |
| --- | --- |
| 1 | 256 字节查表，只读 |
| 2 | 就绪组字节，只读 |
| 3 | 两行就绪位图，只读 |
| 4 | `OSPrioHighRdy` 字节，可写 |
| 6 | 当前任务指针，只读 |
| 8 | 13 项任务指针数组，只读 |
| 10 | `OSTCBHighRdy` 指针，可写 |

所有内存都由有界内存构造器和显式分离连接构成。它证明完整两句前置不是资源冲突造成的空洞断言，但不是完整 OS 初始化，也不证明全部调度状态可达。根定理仍参数化任意合格局部不变量；具体可满足见证仅用空局部不变量实例。

## 前瞻固定的四项单因素控制

其他源码、证明和独立接口保持不变，分别要求命中指定位置：

| 单独改变 | 指定观察 |
| --- | --- |
| 将桥接引理的读取结论改成所选字节加 1，前置不变 | `V293_prefix_selected_load` 拒绝 |
| 仅将指针输出资源的可写位改为只读 | `V293_OSSched_target_assign` 拒绝 |
| 仅将组合根要求证明的两句顺序反转，已生成源码和赋值根不变 | `V293_OSSched_unlocked_prefix_hoare` 拒绝 |
| 仅给组合根新增 `False` 前提 | 组合模块及完整前置见证先编译成功，再由固定的 `checked_prefix` 接口拒绝 |

顺序控制检查新组合证明是否对顺序敏感，不声称遍历所有可能的交换证明。源码 AST／精确发射的顺序核对另由已有调用方门禁检查。前述控制不依赖 C 源码身份的早期拒绝。

独立探针另写全局绑定、任务表资源、输出写权限及两个完整 Hoare 类型；不在运行时从被检验定理生成期望类型。旧阶段的 23 项指定控制保留。
