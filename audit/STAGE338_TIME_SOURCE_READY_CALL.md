# 第338步：源码时间接口从调用者到返回的资源闭合

## 本步补的缺口

第337步已将固定配置后的 `OSTimeGet`、`OSTimeSet` 对应到生成的完整函数，并连接原有时间接口证明。更早的强就绪资源证明、分配证明和函数体精化也已存在，不能把它们重新包装后宣称新证明了整核。

本步的新增点是一个**不依赖 audit 实例的通用生产接口**：从任意调用者环境持有的强就绪／时钟 core 和当前任务半份资源出发，构造调用、局部对象分配、实际函数体执行、临界区内抽象提交、退出、释放和恢复调用者；不再要求上层事先提供分配后的 callee 所有权或成功执行结果。

- 生产文件：`certiucos/v293/proofs/V293TimeSourceReadyCall.v`。
- 稳定接口：`V293_source_time_get_ready_call`、`V293_source_time_set_ready_call`。
- 同一生成程序的非空实例：`audit/probes/V293TimeSourceReadyCallProbe.v`。
- `V293_source_time_ready_coherent` 将同一源码程序的两个真实 API builder 接到原有强就绪不变量；这是复用已有强函数体契约，不是再次发明函数体证明。

## 精确前提与结论

前提是正确的生成函数绑定、三个名字互异、全局时钟绑定、两个不同且在原堆全块新鲜的局部块、抽象时钟槽，以及调用者持有的 `V293_time_ready_core ** CurTid t`。没有成功 store、成功执行、释放结果或 callee 所有权 oracle。

结论给出：

1. 原调用到原调用者返回的实际 `V293_local_steps`，局部变量真实分配、初始化与释放。
2. 到同一 `Mc` 的实际临界区前缀，以及从该 `Mc` 到同一 `Mf` 的退出／返回后缀；没有把互不相干的执行堆拼在一起。
3. 合法抽象一步和退出前重装的强 core。
4. 返回后同一 `Mf` 上的完整就绪资源、物理与抽象时钟一致、当前任务半份资源；`freels` 关联前述 `Mc` 与 `Mf`。
5. 非空实例量化任意调用者、时钟、设定值和初始 IE，覆盖 IE=true 与 IE=false；返回恢复原 IE，两个局部对象共八个类型长度字节均不再分配。

所有字段／位图／优先级表资源沿原有 core 保持，不复制资源，不把名字局部不变量误称为任务局部堆不变量。临界状态的 core 是已绑定到实际前缀的资源断言，不是任意挑选的满足堆。

## 事前单因素消融

`protocol.json` 在实现前冻结。`SRset_stale_abstract_control` 固定同一个生成程序、输入、实际执行、返回堆、IRQ、调用者、返回动作和资源定义，**只让抽象时钟槽保留旧值**。设定值不同于旧值时：

- 完整真实调用仍成功，物理时钟读取为新值；
- 以新抽象时钟解释的强 core 通过；
- 同一实际返回堆以旧抽象时钟解释的强 core 被拒绝；
- 两个局部对象仍释放。

拒绝由独立的原始字节读取与 core 对应关系冲突导出，不是语法、求参、链接或动作 guard 的早拒绝。此控制只测晚端资源对应关系，**不是运行时突变程序的执行反例**。源码复制源突变的前端／等式控制另由原检查器新鲜重放，两类控制不互相冒充。

## 仍然没有完成的目标

这是有限、无中断交错的局部路径，不是任意调度下的全局 `ProgSim`，不是合法 ISR 可达性、初始化可达性或整核程序。源模型不是经验证C前端，仍接受 ADR0005 临界归一化；不补做物理 port／编译器／硬件验证来阻塞源码目标。

两个CPU hook仍缺实现。统一全核 `WFAPI`／`WFInt`／`WFIFun`、合法初始状态、最终 `GOOD_OS` 和同程序 K1–K4 仍开放；uCOS3 未开始。总目标保持active。旧覆盖清单不改写，旧失败和冻结材料保留，不提交／推送。
