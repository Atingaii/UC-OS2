## 新增证明

- `V293OSSchedNewHoare.v`：将实际 256 个表字节、两个就绪行字节及组字节表达为只读 `Amapsto`／`**` 资源；从中推出上一阶段需要的实际 `load`。
- 绑定断言只表达真实全局／局部变量环境及无局部遮蔽；不把最终 `evalval`、选择就绪或最小性放入前置。
- 两个可写 `PV` 分别代表局部 `y` 与全局最高就绪优先级。通过框架 `assign_rule` 逐条连接，保留实际输入、任意分离 frame 和调用方给定的 `CurLINV`。
- `V293_OSSchedNew_body_hoare` 用 `seq_rule` 与 `ret_rule` 连接两次赋值及隐式 void 返回。返回结果为 `None`，输出字节为最低合法就绪优先级；`y` 为选中的行。
- `V293OSSchedNewWitness.v` 实际构造有界的分离内存、环境、只读当前任务指针及两处可写字节，证明整个空间前置可满足。只读输入位于块 1／2／3，输出与局部在 4／5，当前任务指针在 6；就绪行是 `0/16`，组为 `2`，候选为优先级 `12`。

见证中的空局部不变量仅用于构造一个合法测试实例；主 Hoare 定理对任意调用方 `li` 全称量化并要求／保留真正的 `CurLINV li tid`，没有将未来内核共享不变量替换成 `True`。

## 验收协议（执行前确定）

正向：全部活动源文件在空目录重新构建，独立探针另写期望程序／空间前后置类型；打印调度器所有根的实际假设，再检查依赖闭包。独立探针不从导出的定理声明自动抄出类型。

本阶段预定四项单因素控制；实际表、C 翻译、其它断言和证明步骤保持不变：

| 单独改变 | 指定观察点 |
| --- | --- |
| 删除组字节资源 | 必须在 `V293_sched_inputs_load` 的真实读取义务失败 |

## 保留的失败与限制

首次本地独立探针的 Python 字符串将 Coq 合取符号的反斜杠转义错，定位为探针夹具后改用 raw string；不修改 Coq 断言或门槛。首次定向运行还错误地将空表传给上阶段表变异夹具，正向 `coqchk` 通过后在 Python 下标处退出；这是运行夹具错误，不计语义控制成功。随后删除组资源的变异在未使用参数的隐式类型推断处提前失败，门禁正确拒绝计为指定读取失败；为资源定义明确标注块／自然数参数类型后重跑，未放宽指定失败位置。失败日志保留，正式报告只由从空目录运行的门禁生成，历史 JSON 不回写。

尚缺局部变量入口分配、返回释放及 `BuildPreI`／`BuildRetI`／`WFFunEnv` 内部组件义务；还缺真实共享不变量、关闭中断上下文、准确全局符号布局与初始化。因此不能宣称所有中断交错下的调度安全，不能将当前参数化标识当完整链接，也不能提前启动 uC/OS-III。
