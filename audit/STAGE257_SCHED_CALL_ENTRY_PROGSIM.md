# 第257步：实际 OS_SchedNew 调用入口的全部分配后继模拟

## 为什么需要这一步

第256步把 Exit 的实际比较、计数、复制和切换接入原 `ProgSim`，但尚未跨越调度调用的局部环境变化。本步只补这个真实缺口，不新增模拟关系、不修改原函数体，也不把一条成功执行当作全部执行正确。

稳定生产接口是 `V293_sched_call_entry_progsim`，连接以下四个原语义微步：

```text
scall f nil
  → sfexec f nil nil
  → 保存调用者环境到 kcall，当前局部环境清空
  → 为局部 Tint8 变量 y 分配一个合法新鲜块，字节为 Undef
  → 进入实际 V293_OSSchedNew_body，保留 kcall 和调用者续体
```

图中“保存／清空”对应函数执行进入步骤，“分配”对应下一步骤；总共四步，最后进入 body 的步骤不再修改堆。没有额外插入初始化存储。局部变量分配会同时改变物理堆与当前任务的 `les` 投影，其他任务的局部环境、辅助状态、client 状态和当前线程保持不变。

## 不能假设分配后继唯一

原 `alloc` 允许选择不同的新鲜块。因此原先用于纯微步的唯一后继助手不能直接套到这里。本步最小新增机制是：从同一任务投影出发，把**每一个**原 cstep 后继还原为原全局 lpstep 后继，并分别排除输出和异常；再用框架原 `simulation.prog_sim` 组合。

| 独立义务 | 证明接口 | 不依赖什么 |
| --- | --- | --- |
| 存在实际进展 | `V293_os_family_progress` | 不假设后续 ProgSim |
| 任意全局后继都被覆盖 | `V293_os_family_all_successors` | 不要求后继唯一 |
| 没有输出事件 | `V293_os_family_no_output` | 不以进展代替输出检查 |
| 没有异常分支 | `V293_os_family_no_abort` | 使用实际 cstep 进展排除 stuck，不从后续模拟倒推 |
| 接入原模拟关系 | `V293_os_family_progsim` | 不另造 coinductive 关系 |

生产主定理要求**所有合法新鲜块**上的函数体后续模拟：`forall b, fresh M b -> ProgSim ...`。这项后续模拟**尚未独立建立**；它是公开的条件，不是已完成的完整函数证明。新增接口还显式要求函数绑定、调用者局部环境、合法 OS 调用上下文和高层 current 匹配。仅有函数地址绑定不能冒充合法调用上下文。

## 实际实例与预先声明的消融

独立实例使用原 `CGmemory OwnershipWaiting true 0 0` 非空 typed 堆、真实调度函数绑定，以及 `HPpending = CGpending ## CGouter`。`CEtyped_heap` 检查 ready/TCB/所有权和 frame，不预先把局部字节放入堆。

`CEactual_prefix_all_fresh` 不要求任何 ProgSim 后置条件，对每个合法新鲜块实际执行上述四步；证明 y 绑定到该块，旧调用者的局部变量 120 不留在新局部环境，分配字节仍为 Undef。`CEall_global_successors` 另行分类全部全局分配后继，不能由这条执行见证代替。

按事先固定的 protocol，消融只改变选择的新鲜块：同一原堆、函数体、调用者、代码、续体、辅助状态和高层程序不变。`CEtwo_fresh_successors` 证明两个合法实际全局后继都存在，且局部环境、物理堆分别不同；堆差异在 `(b1,0)` 直接见证。`CEunique_allocation_rejected` 进一步否定同一原 cstep 的唯一后继前提。反驳的是助手的适用条件，**不是**内核分配漏洞，也不表示一条后继被拒绝。

## 严格边界与下一步

- IE=false，四步期间不允许任意中断交错；高层是零步停顿，显式保持 current 匹配。
- 后续模拟按所有合法新鲜块量化，并保留真实 kcall 与 caller。还没有独立关闭函数体在这些入口状态上的模拟。
- 尚未组合函数体、局部变量释放、调用返回及完整中断返回；不是完整调度调用的无条件模拟，不是任意 client。
- 原比较、计数、复制至 switch 的旧证明仍保留；尚未把两个端点之间的局部读写和后续释放完整接通。
- 沿用 ADR-0010 的显式源码级端口解释，不宣称原始外部端口实现精化。
- 不是 `WFInt`，不是 `GOOD_OS`；K1–K4 未闭合，uCOS3 未开始。
- 固定 C/config/AST/framework、旧 Inv/LI/BDspec、旧证明测试及冻结失败不改。未提交／推送。

下一步应独立证明**任意新鲜局部块**上的实际调度函数体模拟，并与当前入口接口组合，然后处理释放和返回；不能用再增加一个固定 block 的轨迹替代这项通用义务。
