# 第124步：有限链约束接开启中断的发布后缀（进行中）

## 本步解决什么

第123步只证明关闭中断后的发布体。本步把同一份实际链的地址索引、表成员关系和不重复性保留在共享断言中，连接原有 `encrit1 → 发布体 → excrit1 → return 0`。不会先忘却索引，再凭空恢复。

生产源：`certiucos/v293/proofs/V293TCBFiniteEnabled.v`。

- `V293_tcb_finite_shared` 持有当前链的实际字节和有限成员约束；它可以忘却为原共享池，没有第二份内存权限。
- `V293_tcb_finite_enter` 从同一个 `Inv` 借出上述当前链，存在量词由共享状态选择，不是调用者保存的旧计数。
- `V293_tcb_finite_exit` 从插入后的索引链直接重建同一个共享断言，再归还同一个 `Inv`；新节点留在共享链中，调用者仅取回局部资源。
- `V293_OS_TCBInit_publish_finite_enabled` 连接完整原发布后缀，不再接收独立 `Capacity` 或物理地址 freshness 前提。新节点属于固定TCB表的成员条件仍显式保留。
- `V293_OS_TCBInit_free_body_finite_published` 将该后缀接回原完整 `OS_TCBInit` 函数体，没有下游Hoare continuation；分配后节点的表成员性、token freshness、Hook契约和共享借还仍是条件。

这里TCB表块 `tcbtable` 与优先级表块 `table` 不同，不能混用。

## 非空性与整段检查

探针：`audit/probes/V293TCBFiniteEnabledProbe.v`。

已独立检查同一个物理 `FEInv` 的精确性、ISR稳定性和借还等价；并分别检查四个开启中断的字面入口（空旧链／两个旧节点 × ready表两行）及完整原发布后缀的通用Hoare结论。实际节点共用一个块，偏移为0、56、112。它们不是整个函数初始化可达性的证据。

本步没有新增独立物理机制；对照是忘却有限索引后的原共享池，它仍允许计数255，不能作为通用容量来源。第123步的单因素包含关系消融仅证明纯基数反例，不是255节点物理执行，也不授予发布体之后的机制任何检查信用。

## 尚未完成的部分

这**不是生产全局Inv**：`FEInv` 只检查物理发布资源，未连接完整任务映射、ready语义、所有中断或删除保持性。尚需由真实初始化及空闲／活动／私有节点分区建立表成员性，并证明分配、归还和删除保持约束。完整函数的所有借还条件能否由同一个生产Inv同时满足，也尚未证明。

旧第122步定理没有改写，仍带 `Capacity`。本步新接口的容量来自当前有限共享链，但不能因此宣称生产容量义务全部关闭。Hook函数体、`WFIFun`、分配器token freshness、初始化可达性、标准整函数契约、最终 `GOOD_OS` 与同程序K1–K4均未完成，uCOS3未开始。六门仍为94/1/1/1/1/0。
