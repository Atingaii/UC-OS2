# Stage26：同一次完整返回的ECB细粒度frame

## 本轮决策与冻结边界

为避免复制六套完整执行证明，本轮原地增强构造性执行核心，并将原公开定理保留为投影包装；六个旧命题（包括全部入口、出口）逐字一致。不是追加-only：旧6129行前缀不再保持。明确接受并保留由旧源码冻结身份及Proof布局断言产生的失败，不更改旧测试、旧gate或旧报告，不把旧完整函数门禁的历史成功重新绑定到本身份。

基线、前瞻协议、原始源码、开发变换及失败日志见 `audit/logs/stage26-event-return-frame/`。仅一个活动Coq源改变，另外165个活动源、12项受保护输入与已有测试/报告逐字保留。固定C、配置、端口、框架、正式覆盖不改。

## 实际证明链

旧的纯事件frame与类型定义前移到首次消费者之前，没有重复实现。增强核心串接真实S1/S2任务表store、TCB旧值读取、ready条件写、事件指针store、事件位图更新、TCB更新、坐标计算、入口SELF解析、受阻调度、return/free。事件相对偏移10～12之外的字节保持到同一个Mf。

完整队列核心只调用一次增强payload根；同一Mf/Os'/OO'保留旧返回、释放、抽象步骤、TCB、ready、任务表、事件位图、等待字段、实际events查询和列表关系。类型结论绑定该查询的同一data，形式为入口匹配蕴含出口匹配；不是已建立全局入口一致性。

固定probe在同一个原始内存添加SEM类型3并重建全部一般前提，实际调用新核心；实际ECB查询仍为SEM数据及原等待列表。另有邮箱不匹配和同一完整返回Mf的事件高行字节1→0语义控制。

门禁编译生产、8个probe、目标前候选前缀和完整目标后缀，并检查生产/probe/隔离正控的coqchk。隔离正控仅导入不含目标根的FrozenPrefix及版本相关依赖，不导入候选生产模块。

两个前瞻单因素负控：WrittenByteFramed扩大最终frame到所有字节；MailboxSubstituted仅把最终种类改为邮箱。完整目标Proof后缀保持，不授downstream信用；独立语义反例单独检验实际完整返回，而非以早拒绝替代下游验证。

完整测试新增8项。原887项在本轮重构后实际301失败、1错误；前轮276条诊断按重数全部保留，新增26条逐项提取trace复核：23条旧prefix/身份门槛，3条旧Proof-body布局断言（实现已进入增强核心，旧名是投影）。旧记录原样保留。该结果不是全量测试通过，不能将局部门禁通过扩大成整仓验收通过。
