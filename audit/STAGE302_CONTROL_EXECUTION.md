# 第302步：把真实中断控制片段接入固定控制前端

## 这一步解决什么

第301步已有明确的 Enter/Exit 控制状态机，也有字节资源更新，但它们不等于真实 C 语句已经执行。本步把两者连接起来：从具体内存读出控制字节和写权限，构造真实 `cstepstar`，再从**同一条轨迹的后继内存**读回控制状态。没有把目标内存、成功 store 或执行轨迹放进公开前提。

来源仍是固定的 uC/OS-II V2.93.01 与配置；`OSIntEnter` / `OSIntExit` 的源码身份及依赖见 `audit/logs/stage302-control-execution/source-identity.json`。C、配置、AST、框架和全部旧证明未改。

## 可以复用的接口

新增生产文件：`certiucos/v293/proofs/V293InterruptControlExecution.v`。

| 接口 | 已证明的内容 | 切点限制 |
| --- | --- | --- |
| `V293_control_enter_execution_bridge` | 任意有效 running/nesting/lock 字节；实际执行 Enter updates；后继 reader 等于固定 Enter 一步；嵌套字节以外的内存不变 | 不含函数调用包装、返回及中断交错 |
| `V293_control_exit_execution_bridge` | running=1 内部切点；构造实际递减，再读取实际 nesting/lock guard；同一后继 reader 等于固定 Exit 一步；保留外部内存 | enabled 只到任意 dispatch 入口，不执行 dispatch |
| `V293_control_exit_residual_exact` | 实际残余语句与固定前端对**原始深度**作出的决定精确一致 | 不把递减后的深度再次递减来作选择 |

Enter 的深度255饱和，不启动时不写。Exit 的深度0保持0，正深度递减；只有递减后深度0且锁0才到 dispatch。生产接口通过真实 load、表达式求值、赋值规则和 store 构造这些结果，而不只是比较数学函数。

## 非空内存检查与消融

`audit/probes/V293InterruptControlExecutionProbe.v` 自建三个可写控制字节与独立哨兵字节77。泛化的 Enter/Exit 结论覆盖合法字节范围。`CElock_pair` 对相同程序、相同 dispatch 和深度0/1，只改锁字节，分别构造到 dispatch 和 skip 的真实执行；两个结果都读回深度0，并保留各自锁值。它没有证明这些输入从完整内核初始化可达。

`CEboundaries` 列出未启动、非1 running、深度0/1/2/255、锁255的观察边界；这些是观察结论，真实执行由上述泛化接口提供，并非每项边界另有一条独立全函数轨迹。

前瞻协议固定三组独立单因素：忽略锁、移除255饱和检查、丢弃实际递减。每组保持原 AST、内存 fixture、判别式与编译器，只改一个定义。最终 `ablation3` 三组原版均编译成功，三个错误变体均被相同判别拒绝。**范围只是隔离定义的内存观察/残余分支判别，不是完整执行模拟消融，也不说明全部下游机制均已验证。**

第一次消融因文件名含连字符被 Coq 拒绝，不能记作语义判别成功；第二次饱和基线的 `vm_compute` 展开过慢，由代理终止，不能记作通过。之后先记录补充协议，仅将证明策略改为定向读回，保持被测对象、变体和判别式不变，再得到最终结果。相关源快照、日志及终止记录全部保留。

## 明确尚未完成的部分

1. 这只是无交错的源语句片段，不是完整 `OSIntEnter` / `OSIntExit` 调用的统一模拟。
2. Exit 从 running=1 内部切点开始，未包入保存槽分配、临界区、调度器、退出与返回。
3. 抽象任务状态 `O` 在这里是自由参数；没有重建全局 RDYINV、迁移旧 `osintspec` / `WFInt`，也没有证明初始化可达。
4. 不能由该片段推出完整函数健全性、`GOOD_OS` 或同程序 K1–K4 回归闭合。
5. 下一步应将该同轨迹接口接入完整中断上下文与统一生产规格，而不是继续增加不相连的小模型。

最终顺序仍是：完成 uCOS-II 源码级整核 `GOOD_OS` 与同程序 K1–K4，再依老师附件开展 uCOS3。本步不提前启动 uCOS3，不提交或推送 Git，目标仍为 active。
