# 第47步：真实清零返回接入TCB空闲链和链头

## 这一轮新增了什么

固定目标仍为uC/OS-II V2.93.01、提交`0c4a48e6fbc6e915714e816196619a5481accf0c`、原配置和两类授权修复；没有改C、配置、191个既有活动源或旧测试／证据。

稳定接口：`certiucos/v293/proofs/V293InitTCBList.v`中的`V293_OS_InitTCBList_body_execution`。它将上轮两次实际`OS_MemClr`的返回`M1`传给本轮循环，得到同一最终`Mf`，而不是另外假设一张已初始化的表。

| 顺序 | 实际执行与结果 |
| --- | --- |
| 两次清零 | 真实实参求值、临时参数分配／写入／执行／释放，TCB728字节和优先级表52字节变零 |
| 表示连接 | 每条TCB的4个零字节转为`Tcom_ptr 410`的可写NULL槽；复用唯一零字节NULL编码 |
| 原生循环 | `ix=0…11`，12条`TCB[i].OSTCBNext=&TCB[i+1]` |
| 尾项 | `TCB[12].OSTCBNext=NULL` |
| 两链头 | `OSTCBList=NULL`、`OSTCBFreeList=&OSTCBTbl[0]` |
| 保留资源 | 四个局部变量、两链头、13个Next槽可写；其余676个TCB字节仍零且可写，13个优先级NULL槽和任意分离raw frame可写 |

676来自`13*(20+32)`：每个56字节TCB的Next在偏移20，占4字节；前20及后32字节不丢失，包括结构体填充。本轮不把“字段之外的字节”默默丢弃。

## 源码身份和执行边界

`source/result.json`记录锁定配置后的94个实际函数身份、Clang AST、`os_core.c:1591–1617`及布局`56/728/52/20`；`source-loop.json`检查真正的for初始化、guard、后置递增、循环体四赋值和末尾四赋值。源码身份为`74390755cddc42a391055da46b744bbf32e77ba3dc025c2ae55b9441ba6170da`。

生产AST仍是原生`swhile`，没有用有限赋值序列替换循环。证明针对固定配置分别构造12次while-true和1次while-false；每步实际求值字节计数器的cast、地址、guard及store。这不是任意TCB数量的通用循环定理，也不是已验证C前端。

**函数体已连接，不等于外围函数生命周期完成。** 四个局部对象`ix/ix_next/ptcb1/ptcb2`以已分配、可写为入口；本轮没有该函数自身的调用分配／void返回／释放。也没有OSInit／OSStart可达性、所有并发执行safety、完整task／ISR、整核GOOD_OS或同程序K1–K4。uCOS3尚未启动。

## 独立复核，不使用生产定理自己的入口假设作oracle

`audit/probes/V293InitTCBListProbe.v`独立构造有限内存：TCB全部Undef、优先级字节255、局部变量含Undef、两个旧链头非空，并放置17／29及123保护对象。`LinkLiteralEntry`证明入口可满足；`LinkProgram`是仅在指定标识查到实际MemClr函数的总函数；`LinkLiteralAST`用独立字面表达式检查AST连接。

`LinkConcreteExecution`在同一Mf同时读回：12个Next链接、尾项NULL、两个链头、13个优先级NULL、TCB首字节0、两个保护字节及123，共32项。并返回所有权，不只是散立load结论。`LinkMiddleAndEnds`额外选定中间第6条链接和末尾／链头／保护对象供负控消费。
