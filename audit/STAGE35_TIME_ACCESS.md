# 第35步：时间读取／设置的真实归一化函数体 Hoare 规则

## 本步解决什么

最终目标仍是固定 V2.93.01 的源码级 `GOOD_OS` 与同程序 K1–K4，再按老师指示推进 uCOS3。第34步的时钟中断前缀和后缀之间仍缺 CPU hook 的可执行连接；本步不编造 hook，推进整核所需的两个现有时间接口。

固定输入来自 `audit/physical-access-inventory.json`：`OSTimeGet` 位于 `os_time.c:237–250`，`OSTimeSet` 位于 `267–278`。本步重新物化授权两项修复后的固定配置 C，实际运行 Clang 预处理和 AST，核对完整函数身份、正文、参数及两次临界宏的同一 `&cpu_sr` 地址。两个函数所在 `os_time.c` 与锁定上游完全相同。详见 `audit/logs/stage35-time-access/protocol.json` 及正式 gate 的 `source/result.json`。

## 已完成的证明接口

新模块：`certiucos/v293/proofs/V293TimeAccess.v`。

- `V293_OSTimeGet_body_hoare`：`cpu_sr=0` → 进入临界区 → 从拥有的全局 `OSTime` 字节读取并写入局部 `ticks` → 退出临界区 → 实际 `srete ticks`。返回值与读取时的快照相等，时钟保持，保存单元为0，局部与 frame 所有权保留至返回边界。
- `V293_OSTimeSet_body_hoare`：`cpu_sr=0` → 进入临界区 → 从拥有的参数 `ticks` 字节读取并写入 `OSTime` → 退出临界区 → 实际 `sret`。返回 `None`，最终时钟等于参数而非旧值。
- 两个入口均涵盖原先 IE=true／false，并恢复原 ISR 标志、IE、中断栈与临界区栈。
- 赋值从变量绑定与字节所有权推导地址、类型和值；前提不是“执行已经成功”或“store 必定成功”。getter 的未初始化临时量和两者的未初始化保存单元可为 `Vundef`。
- 共用的临界区规则真实使用 `encrit1/2_rule`、`excrit1/2_rule`。开中断分支取得的 `invlth_isr I` 作为任意额外资源穿过赋值后归还；没有用 `True` 替换整个 I。

独立 probe：`audit/probes/V293TimeAccessProbe.v`。字面环境把时钟、ticks、保存单元置于不同块80／81／82，另有块90的真实当前任务指针；分别编码字节并证明分离，构造满足 `CurLINV` 的入口，并读取字面入口值。对任意32位时间／参数和两种 IE 成立，控制栈含 `[true;false]`。这是入口非空与接口实例化，不是由初始化到达该入口的证明，也没有在本步另证一条完整运行轨迹。

## 前瞻单因素负控

编码前协议已固定两个修改；保持全部 `Proof...Qed` 正文和两份 AST 不变，只改返回规格：

| 对照 | 唯一修改 | 必须拒绝的位置 | 下游信用 |
| --- | --- | --- | --- |
| wrong-get-return | 返回快照改成固定1 | getter 返回值与快照的连接 | 不授予 |
| wrong-set-memory | 最终时钟改成旧值 | setter 最终内存所有权的连接 | 不授予 |

正式命令、错误行、假设及独立 Coq 内核检查记录在 `audit/logs/stage35-time-access/gate01/`。开发过程中失败的每次 Coq 快照和日志均保留，不覆盖失败结果。首次源码物化因在 Git 仓库内部运行 `git apply --numstat` 而得到路径前缀，身份检查在应用补丁前拒绝；改为任务专用仓库外临时目录后重跑，旧失败记录保留。

## 不能据此宣称什么

1. 源码对应仍是严格的手工映射回归，不是经过验证的 C 前端；语句分组采用等序的结合分组。
2. 宏归一化沿用 ADR-0005；没有原 CPU_SR 字节协议到中断保存栈的仿真。
3. 函数体入口已经拥有局部存储，本步未接调用分配、局部释放、API 规格表或完整函数连接。
4. **时钟单元仍在调用者拥有的 payload 中，不在 IRQ 的共享时间不变式内。** 通用规则保留 I 并不等于已经构造整核 GoodI，更不等于可安全忽略其他时钟访问者。
5. `OSTimeTickHook` 仍开放；所有中断交错／共享 Inv／初始化／GOOD_OS 与同程序 K1–K4 未闭合，uCOS3 未启动。
6. 正式六门覆盖不晋级；复用既有依赖，不是全仓 source-only 干净构建。旧审计与旧测试失败如实保留。

## 下一步

优先把时间单元纳入可满足的共享不变式，连接真实调用资源生命周期，并给 CPU hook 找到固定目标下可验证的实现／契约；在这些连接完成前，不把本步的局部规则计作完整内核成果。

实际测试诊断、旧源／产物保护、清理和最终冻结结果以同目录 `final-report.json` 为准。
