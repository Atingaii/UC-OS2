# 第108步：在临界区内打开同一个存在资源池并选择拒绝路径

## 这一步解决什么

第107步的接口在调用前固定拒绝类别和嵌套计数，不适合直接充当真实内核共享不变量。本步不增加新的执行假设，而是在真实 `encrit1_rule` 之后才打开存在量词，读取实际 `OSIntNesting` 字节，选择返回60或40；两条路径都用原有 `excrit1` 证明归还同一个资源池并恢复入口IE=true与原临界栈。

稳定入口为 `V293_OSTaskCreateExt_dynamic_rejection_contract`，位于：

- `certiucos/v293/proofs/V293TaskCreateDynamicReject.v`
- 独立实例：`audit/probes/V293TaskCreateDynamicRejectProbe.v`
- 验收：`audit/logs/stage108-taskcreate-dynamic-reject/`

## 从入口到返回

| 步骤 | 实际完成的连接 |
| --- | --- |
| 标准入口 | 原 `BuildPreI`，九参数／三局部、准确声明域；调用者不拥有共享字节 |
| CPU局部初始化 | 原赋值规则将实际局部写为0 |
| 优先级检查 | 从拥有的局部字节证明合法优先级分支；本契约要求 `p<13` |
| 进入临界区 | 原 `encrit1_rule` 打开ISR不变量；此时才取得存在的计数和非空槽指针 |
| 实际计数非零 | 原计数guard为真，归还整个资源池，返回60 |
| 实际计数为零 | 原计数guard为假，原表槽guard判定非空，归还整个资源池，返回40 |
| 标准返回 | 原 `BuildRetI`，全部声明资源和准确域交回；IE=true和原临界栈恢复 |

公开契约没有入口 `k`、`n`、`slot`，也没有 `evalval`、`load`、执行轨迹或另一个Hoare判断充当假设。资源转换的双向逻辑等价仍是接口的明确条件，不等同于已经构造生产全局不变量。完整原函数AST不改写；分配、Hook与调度分支没有从语法中删除。

## 非空性与单因素对照

探针只定义一个 `DRInv`，在同一个调用者、优先级11和同一个非空指针槽下，可容纳所有小于256的计数字节。证明了资源池精确性、ISR结构条件、字面物理内存、内存不交叠、标准builder、完整函数条件契约与实际类型化计数guard。

前瞻协议先于代码快照冻结。对照仅改变物理计数字节0／1，保持调用者、`DRInv`、非空指针和最终期望guard=false不变。两组先完成相同的资源池、字面入口、非空槽读回及类型化guard检查；计数1的错误期望只能在最后guard观察等式失败。对照不代表完整函数执行轨迹；最终结果以 `controls.json` 为准。

初次对照因缺少类型定义的直接导入提前停止；第二版因自动 `split` 已解掉类型等式而出现多余证明分支。两组同样修正导入及证明步骤，命题不变；失败日志、快照和原协议保留，不把它们算作有效测量。第三版先冻结相同命题与单字节因素，再实编译：计数0通过，计数1只在最后错误期望的等式处失败。
