# 第107步：开启中断时，提前返回也要归还共享资源

## 本步解决什么

第106步的统一契约要求入口 `IE=false`。它没有证明普通开启中断调用时，共享字节从哪里来、返回前如何交还。本步只推进 `OSTaskCreateExt` 的三类提前返回：非法优先级42、中断嵌套非零60、优先级槽占用40。不修改原C、原AST、分支顺序、配置或既有证明。

新接口：`V293_OSTaskCreateExt_enabled_rejection_contract`，位于 `certiucos/v293/proofs/V293TaskCreateEnabledReject.v`。它通过真实 `BuildPreI / BuildRetI` 连接原完整函数体，交接九个参数、三个局部变量和精确声明域；入口／返回均为 `IE=true`，保存栈保持原样。

## 可以怎样理解

把共享数据看成临界区管理的工具箱：

1. 优先级参数是调用者自己的局部字节，先按真实字节检查。非法时立即返回42，不借工具箱。
2. 合法时用框架 `encrit1_rule`：把原中断状态true压入保存栈，关闭中断，取得对应的共享不变量资源。
3. 从取得的资源读取 `OSIntNesting`；若非零，交还资源、用 `excrit1_rule` 恢复true，再返回60。
4. 否则读取真实优先级槽；若非NULL，同样交还资源、恢复true，再返回40。

调用者前置条件不持有这些共享字节。原来关闭中断的证明中已有的 guard 求值引理被复用，但不借用任何假定执行结果的前提。未走到的分配／Hook后缀仍保留在原函数体中，以不可达分支规则处理，不能把它们算作本步验证成功的路径。

## 关键开放义务

接口要求：被打开的 `invlth_isr I 0 (gettopis is)` 在当前ISR状态下，能够双向转换成所需真实字节、全局绑定和其余资源 `K`。这个前提是资源形状的逻辑义务，不是执行oracle；但它仍需要最终程序的全局不变量来实例化，不能用“编译通过”替代。

当前接口在调用前固定拒绝类别及相关字节值；三组分类探针不能简单合并就变成真实内核的统一不变量。真实共享状态需要在进入临界区后打开存在量词、读取并分类，再连接各分支；这一统一接口仍须补齐。

探针 `audit/probes/V293TaskCreateEnabledRejectProbe.v` 构造了局部物理不变量：检查其精确性、允许的ISR状态变换及真实字节所有权；逐类构造标准builder入口和独立共享资源，并证明二者可分离。优先级占用例的共享嵌套字节与非NULL指针均实际可读，而调用者自己的内存不包含共享嵌套字节。

**边界明确如下：**

- 探针的不变量按拒绝类别实例化，不是一个覆盖整核所有状态的统一不变量。
- ISR拒绝例把C的嵌套计数设为1，但抽象ISR标志均为false；这里只证明局部资源／契约可实例化，未证明该组合全局一致或可达。优先级占用例的计数为0。
- 探针使用测试用空LINV；这不免除生产程序的局部不变量义务。
- 仍在既有源码级 `encrit / excrit` 抽象边界内，不证明真实CPU端口或硬件。`cpu_sr`的C局部字节不等同于框架保存栈；参见ADR-0005。
- 这不是整段函数的独立操作语义执行轨迹，也不是已完成 `WFIFun`。Hook／分配／运行中的调度器以及全局 `GoodI`、初始化仍开放。

## 单因素对照

冻结协议见 `audit/logs/stage107-taskcreate-enabled-reject/protocol.json`。正反组共用相同的字面优先级占用状态、资源打开、真实类型化guard和临界区退出规则；只改变待恢复保存位true／false。两组必须先完成各自真实退出，才比较最后的IE观察，避免把类型检查失败当作恢复机制的证据。

该对照的结论仅限框架临界区退出原语：退出恢复保存位，而非无条件开启中断。不声称已执行整段C函数。
